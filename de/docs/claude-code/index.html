Integrationen

Claude-Code-Plugin

Installieren Sie das mergecat-Plugin für Claude Code, um Tags aufzulisten und Changelogs aus den Changesets eines Branches zu schreiben, mit einem KI-Nutzungsnachweis für jede Sitzung.

Auf GitHub bearbeiten

Mithilfe von KI aus dem Englischen übersetzt. Im Zweifel gilt die englische Fassung.

Mit dem mergecat-Plugin liest Claude Code den Verlauf eines Repositorys gruppiert nach Integration und macht daraus Tag-Listen und Changelogs. Es enthält den mergecat-MCP-Server und zwei Skills, /mergecat:tags und /mergecat:changelog. Changelogs sind Dokumente der Unterhaltung und keine Dateien Ihres Projekts, es sei denn, Sie bitten darum, CHANGELOG.md zu aktualisieren.

EU-KI-Verordnung (EU AI Act) und NIS-2: einmal pro Sitzung gefragt, jedes Mal protokolliert

Das Plugin sendet Daten Ihres Repositorys an Claude: Commit-Nachrichten, Namen und E-Mail-Adressen der Autoren, Datumsangaben, Branch- und Tag-Namen und, mit einem GitHub-Token, Pull-Request-Daten. Vor den ersten Repository-Daten jeder Claude-Code-Sitzung fragt Claude, ob Sie ein Claude-Konto vom Typ Team oder Enterprise nutzen. Falls nicht, fragt es, ob Ihnen die EU-KI-Verordnung und die NIS-2-Richtlinie (NIS2) bekannt sind und Sie trotzdem fortfahren möchten; „nein“ stoppt mergecat, bevor Repository-Daten gesendet werden.

Der MCP-Server setzt das durch: Seine Repository-Tools bleiben gesperrt, bis die Antwort sie freigibt. Jede Antwort wird als Audit-Nachweis auf Ihrem Computer gespeichert und Ihnen als Dokument der Unterhaltung übergeben. Siehe KI-Nutzungsnachweise.

Was Sie erhalten

TeilFunktion
/mergecat:tagsDie Tags mit Datum, Commit und Nachricht, ob sie auf dem Main-Branch liegen und wie viele Änderungen jedes Release enthält. Details
/mergecat:changelogEin Changelog nach Keep a Changelog für die noch nicht veröffentlichten Änderungen, eine Version, alle Releases oder einen Bereich, dessen Enden Tags, Datumsangaben oder Commits sind. Standardmäßig auf Englisch und in Markdown; andere Sprachen und PDF auf Wunsch. Details
MCP-ServerNur lesende Tools für die Changesets, Tags, Releases und Changelog-Entwürfe sowie die Compliance-Tools. Claude kann sie auch verwenden, wenn Sie in eigenen Worten fragen, zum Beispiel „Welcher Pull Request hat Commit abc1234 nach main gebracht?“. Tool-Referenz

Voraussetzungen

  • Claude Code mit Plugin-Unterstützung.
  • Node.js 20 oder neuer, als node im PATH verfügbar: Das Plugin startet den MCP-Server mit node.
  • Git, im PATH oder über MERGECAT_GIT_PATH festgelegt.
  • Optional: ein Token für den Hosting-Dienst des Repositorys (GITHUB_TOKEN, GITLAB_TOKEN oder AZURE_DEVOPS_EXT_PAT) für Titel, Labels und verknüpfte Issues von Pull Requests. Siehe Pull-Request-Daten.

Installieren

Das mergecat-Repository ist zugleich ein Marketplace für Claude-Code-Plugins namens mergecat.

Fügen Sie den Marketplace von GitHub hinzu:

claude plugin marketplace add CERTIFIE/mergecat

Installieren Sie das Plugin:

claude plugin install mergecat@mergecat

Laden Sie mergecat-claude-plugin.zip aus dem Download-Bereich herunter und entpacken Sie die Datei in einen Ordner, den Sie dauerhaft behalten (der Marketplace wird über seinen Pfad registriert). Sie enthält den Ordner mergecat-claude-plugin/ mit .claude-plugin/marketplace.json und plugins/mergecat/.

unzip mergecat-claude-plugin.zip

Unter Windows, in PowerShell: Expand-Archive mergecat-claude-plugin.zip -DestinationPath .

Fügen Sie den Marketplace aus dem entpackten Ordner hinzu und installieren Sie das Plugin:

claude plugin marketplace add ./mergecat-claude-plugin
claude plugin install mergecat@mergecat

Bauen Sie im Stammverzeichnis eines Klons des mergecat-Repositorys (Node.js 20 oder neuer) den MCP-Server:

npm install
npm run mcp:build

Fügen Sie den Klon als Marketplace hinzu und installieren Sie das Plugin:

claude plugin marketplace add /path/to/mergecat
claude plugin install mergecat@mergecat

Starten Sie Claude Code in einem beliebigen Git-Repository und führen Sie /mergecat:tags aus, oder bitten Sie in eigenen Worten um ein Changelog. In Claude Code zeigt /mcp den mergecat-Server und seinen Status an.

Erste Verwendung in einer Sitzung

Eine Anfrage stellen

Führen Sie /mergecat:tags oder /mergecat:changelog aus, oder bitten Sie zum Beispiel um „Changelog von v1.2.0 bis heute“.

Die Compliance-Frage beantworten

Claude fragt, ob Sie ein Claude-Team- oder -Enterprise-Konto nutzen, und, falls nicht, ob Ihnen die EU-KI-Verordnung und NIS-2 bekannt sind und Sie trotzdem fortfahren möchten. Antworten Sie mit Ja oder Nein; die Skills weisen Claude an, auf Ihre Antwort zu warten und nie an Ihrer Stelle zu antworten.

Den Nachweis aufbewahren

Claude übergibt Ihnen den Compliance-Nachweis als Dokument der Unterhaltung und sagt, wo er auf Ihrem Computer gespeichert ist.

Das Ergebnis erhalten

Lautet das Ergebnis „proceed“, liest Claude den Verlauf und liefert die Tag-Liste oder das Changelog. Bei weiteren Anfragen in derselben Sitzung wird nicht erneut gefragt.

Dokumente der Unterhaltung

Changelogs und Compliance-Nachweise gehören zur Unterhaltung: Claude veröffentlicht sie als Markdown-Artefakt, sendet sie als Datei, die Sie öffnen und herunterladen können, oder zeigt sie als Markdown-Block in der Antwort. Sie werden außerhalb Ihres Repositorys geschrieben (im Scratchpad von Claude oder im temporären Ordner des Systems). Nur /mergecat:changelog … update file oder die ausdrückliche Bitte, CHANGELOG.md zu aktualisieren, ändert eine Datei Ihres Projekts.

Pull-Request-Daten

Ohne Token verwenden die Tools nur lokale Git-Daten: Changesets, Namen gemergter Branches aus Merge-Nachrichten, Tags. Setzen Sie das Token für den Hosting-Dienst des Repositorys in der Umgebung, aus der Sie Claude Code starten, um Titel, Labels und verknüpfte Issues von Pull Requests (Merge Requests) hinzuzufügen; damit werden Abschnitte und Zeilen des Changelogs besser: GITHUB_TOKEN (oder GH_TOKEN) für GitHub, GITLAB_TOKEN (oder GL_TOKEN) für GitLab, AZURE_DEVOPS_EXT_PAT oder AZURE_DEVOPS_TOKEN für Azure DevOps (siehe MCP-Server und Tools).

export GITHUB_TOKEN=...   # a token that can read the repository's pull requests
claude

Erkannt werden nur Repositorys auf github.com, gitlab.com und Azure DevOps. Für selbstverwaltete GitHub- und GitLab-Hosts verwenden Sie die Desktop-App oder VS Code.

Aktualisieren

Nach einem neuen Release (laden Sie das neue Zip herunter und entpacken Sie es in denselben Ordner) oder nach einem erneuten Build:

claude plugin marketplace update mergecat
claude plugin update mergecat@mergecat

Führen Sie dann /reload-plugins in Claude Code aus oder starten Sie eine neue Sitzung.

Deinstallieren

claude plugin uninstall mergecat@mergecat
claude plugin marketplace remove mergecat

Die Compliance-Nachweise bleiben auf Ihrem Computer; siehe wo sie gespeichert werden.

Changelogs → Bereiche, Sprachen, PDF und das Aktualisieren von CHANGELOG.md. Tags → Listen Sie Tags auf und wählen Sie die Enden eines Changelog-Bereichs.
