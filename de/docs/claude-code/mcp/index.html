MCP-Server und Tools

Referenz des mergecat-MCP-Servers: jedes Tool mit seinen Parametern, die Compliance-Sperre, die Umgebungsvariablen und die Verwendung des Servers ohne das Plugin.

Auf GitHub bearbeiten

Mithilfe von KI aus dem Englischen übersetzt. Im Zweifel gilt die englische Fassung.

Der mergecat-MCP-Server stellt einem KI-Assistenten die Changesets eines Branches, seine Tags und Releases sowie Changelog-Entwürfe nach Keep a Changelog bereit. Er läuft lokal über stdio, liest das Repository mit Ihrem Git und ändert es nie. Das Claude-Code-Plugin installiert ihn zusammen mit den Skills; Sie können ihn auch einzeln hinzufügen und mit GitHub Copilot, OpenAI Codex und GitLab Duo verwenden.

Tool-Namen

Installiert alsTool-Namen in Claude Code
Pluginmcp__plugin_mergecat_mergecat__<tool>
Eigenständiger Server namens mergecatmcp__mergecat__<tool>

Compliance-Sperre

Die Repository-Tools (repository_info, tags, changelog, changesets, where_entered) sind gesperrt, bis die Compliance-Frage der Sitzung mit dem Ergebnis proceed beantwortet wurde. Solange sie gesperrt sind, geben sie einen Fehler mit den zu stellenden Fragen und der Anweisung zurück, record_compliance_answer aufzurufen; sie lesen nichts.

compliance_status, record_compliance_answer und render_pdf sind nicht gesperrt: Sie lesen den Verlauf des Repositorys nicht.

Eine Antwort pro Sitzung

Die Antwort wird im Speicher des Serverprozesses gehalten. Claude Code startet wie die anderen Clients einen Prozess pro Sitzung, daher wird in jeder neuen Sitzung erneut gefragt, und jede Antwort wird als Audit-Nachweis geschrieben. Die Frage nennt den KI-Dienst des Clients: ein Claude-Team- oder -Enterprise-Konto in Claude Code, eine Lizenz für GitHub Copilot Business oder Enterprise in Copilot und so weiter (siehe die Frage des jeweiligen Assistenten). Siehe KI-Nutzungsnachweise.

Welches Repository

Jedes Repository-Tool hat einen optionalen Parameter repository: den Pfad eines Git-Repositorys (einen beliebigen Ordner darin). Ohne ihn verwendet der Server in dieser Reihenfolge:

  1. MERGECAT_REPOSITORY;
  2. CLAUDE_PROJECT_DIR (das Claude-Code-Projekt);
  3. die im Client geöffneten Ordner, sofern der Client sie den MCP-Servern mitteilt (VS Code tut das): den ersten davon, der ein Git-Repository ist;
  4. das aktuelle Verzeichnis des Servers.

Tools

compliance_status

Ob die Compliance-Frage in dieser Sitzung beantwortet wurde, und die genauen Fragen, die zu stellen sind. Keine Parameter. Liest das Repository nicht.

Gibt aiService (den KI-Dienst, um den es in den Fragen geht), confirmed, askedThisSession, lastOutcome, lastRecordedAt, lastRecordFile, questions.account, questions.proceedIfNotTeamOrEnterprise und recordsFolder zurück. Beschreibung der Felder: KI-Nutzungsnachweise.

record_compliance_answer

Speichert die Antworten, die der Benutzer in der Unterhaltung gegeben hat, als Audit-Nachweis auf diesem Computer (Markdown-Dokument und JSON-Lines-Protokoll) und entsperrt die Repository-Tools für die Sitzung, wenn das Ergebnis proceed ist.

ParameterTypErforderlichBeschreibung
team_or_enterprise_accountbooleanjatrue, wenn der Benutzer den in der ersten Frage genannten Business- oder Enterprise-Tarif nutzt (in Claude Code: ein Claude-Team- oder -Enterprise-Konto)
aware_and_proceedbooleanwenn die erste Antwort false isttrue, wenn dem Benutzer die EU-KI-Verordnung (EU AI Act) und die NIS-2-Richtlinie (NIS2) bekannt sind und er trotzdem fortfahren möchte
requested_actionstringjaWas der Benutzer angefordert hat, z. B. changelog v1.2.0..v1.3.0 oder tags
answers_verbatimstringneinDie Antworten des Benutzers im Wortlaut oder die gewählten Optionen
languagestringneinSprache, in der die Fragen gestellt wurden (ISO 639-1)
ai_modelstringneinDie Modell-ID des Assistenten
repositorystringneinPfad des Repositorys

Gibt das Ergebnis, die ID des Nachweises, die Pfade des Nachweises und des Protokolls sowie den Nachweis als Markdown zurück. Ist das Ergebnis stopped, lässt dieses Markdown die Angaben zu Benutzer, Computer und Repository weg.

render_pdf

Konvertiert ein Markdown-Dokument (ein Changelog, Release Notes, einen Compliance-Nachweis) in eine PDF-Datei. Liest das Repository nicht.

ParameterTypErforderlichBeschreibung
markdownstringjaDas Markdown-Dokument (bis zu 2.000.000 Zeichen)
file_namestringneinDateiname, z. B. changelog-web-v1.3.0.pdf. Standard: aus dem Titel abgeleitet
folderstringneinAbsoluter Ordner für die Datei. Standard: mergecat im temporären Ordner des Systems
titlestringneinDokumenttitel für die PDF-Metadaten und die Fußzeile der Seiten. Standard: die erste Überschrift #
allow_in_projectbooleanneinSchreiben innerhalb des Projektordners erlauben; nur wenn der Benutzer darum gebeten hat, das PDF dort zu speichern

Der Server weigert sich, innerhalb des Projekts (des Ordners aus Welches Repository) zu schreiben, sofern allow_in_project nicht gesetzt ist. Im Dateinamen bleiben Buchstaben, Ziffern, ., _ und - erhalten. Gibt file, pages und bytes zurück. Zu den Grenzen der Schriften siehe Changelogs.

repository_info

Der Standard-Branch, der aktuelle Branch, der Hosting-Dienst und die Versions-Tags auf dem Standard-Branch mit ihren Daten (die neuesten zuerst, bis zu 30). Gibt außerdem an, ob Pull-Request-Daten verfügbar sind (GitHub (GITHUB_TOKEN set) oder none (local Git data only)), wann zuletzt abgerufen wurde und ob der Klon ein Shallow Clone ist.

ParameterTypErforderlichBeschreibung
repositorystringneinPfad des Repositorys

tags

Jedes Tag, die neuesten zuerst: Datum, Commit, annotiert oder leichtgewichtig, Nachricht, Ersteller, ob es wie eine Version aussieht und ob es auf dem Branch liegt. Bei Versions-Tags auf dem Branch: das vorherige Versions-Tag und die Anzahl der Changesets seitdem. Außerdem die Anzahl der noch nicht veröffentlichten Changesets und das neueste Versions-Tag.

ParameterTypErforderlichBeschreibung
repositorystringneinPfad des Repositorys
branchstringneinBranch, von dem die Releases erstellt werden. Standard: der Standard-Branch
patternstringneinIm Namen enthaltener Text oder ein Glob-Muster mit * und ? (z. B. v2.*); ohne Beachtung der Groß-/Kleinschreibung
versions_onlybooleanneinNur Tags, die wie Versionen aussehen (v1.2.3, 1.2)
limitintegerneinMaximale Anzahl der Tags, 1 bis 500. Standard 50

changelog

Ein Entwurf nach Keep a Changelog für das, was in den Branch kam, eine Zeile pro Changeset, gruppiert nach Release (Versions-Tags) und nach Abschnitt (Added, Changed, Deprecated, Removed, Fixed, Security). Gibt den Markdown-Entwurf und strukturierte Daten zurück: pro Changeset den Abschnitt und den Grund, Nummer und Link des Pull Requests, den Branch, die Commits sowie die Kennzeichen „Breaking“ und „intern“; bei einem Bereich, wie jedes Ende aufgelöst wurde; Hinweise wie vertauschte Enden oder fehlende Pull-Request-Daten.

ParameterTypErforderlichBeschreibung
repositorystringneinPfad des Repositorys
branchstringneinBranch, dessen Verlauf beschrieben wird. Standard: der Standard-Branch (z. B. origin/main)
rangestringneinEin Bereich from..to (auch [from..to]); jedes Ende ein Tag, ein Datum (YYYY-MM-DD, optional mit Uhrzeit) oder ein Commit; offene Enden erlaubt (v1.3.0.., ..v1.0.0)
fromstringneinAnfang eines Bereichs, ausgeschlossen: Tag, Datum oder Commit
tostringneinEnde eines Bereichs, eingeschlossen: Tag, Datum oder Commit. Standard: der Branch
max_releasesintegerneinAnzahl der aufzunehmenden Releases, wenn kein Bereich angegeben ist, 0 bis 100. Standard 5
unreleased_onlybooleanneinNur die Änderungen nach dem neuesten Versions-Tag
include_internalbooleanneinAuch Doku, Tests, CI und Chores im Markdown aufführen. Standard false (in den Daten bleiben sie enthalten)
headerbooleanneinMit dem Titel # Changelog und der Einleitung von Keep a Changelog beginnen
languagestringneinISO-639-1-Code. Standard en. Die Überschriften werden für en, it, de, fr, es übersetzt; für andere Sprachen bleiben sie auf Englisch, und die Daten enthalten headingsTranslated: false

Geben Sie entweder range oder from/to an, nicht beides. Das Tool übersetzt die Beschreibungen der Änderungen nie.

changesets

Was in einen Branch kam, die neuesten Einträge zuerst, gruppiert nach Integration: gemergte Pull Requests und Merges mit den Commits, die sie gebracht haben, sowie direkte Commits. Gibt außerdem die Warnungen zum Verlauf zurück (Shallow Clone, keine Merges, Squash-Merges).

ParameterTypErforderlichBeschreibung
repositorystringneinPfad des Repositorys
branchstringneinZu beschreibender Branch. Standard: der Standard-Branch
basestringneinNur, was nach diesem Tag, Branch oder Commit hinzukam
sincestringneinIntegrationsdatum ab, YYYY-MM-DD
untilstringneinIntegrationsdatum bis, YYYY-MM-DD
searchstringneinText in Betreff, SHA, Branch-Name oder Titel des Pull Requests (auch innerhalb von Gruppen)
authorstringneinName oder E-Mail-Adresse von Autor oder Integrator
limitintegerneinMaximale Anzahl der Einträge, 1 bis 500. Standard 50

where_entered

Zu einem Commit: die Integration (Pull Request, Merge oder direkter Commit), die ihn in den Branch gebracht hat, wann, wer ihn integriert hat und das erste Tag, das ihn enthält.

ParameterTypErforderlichBeschreibung
repositorystringneinPfad des Repositorys
shastringjaCommit-SHA, mindestens 7 Hexadezimalzeichen
branchstringneinBranch. Standard: der Standard-Branch

Pull-Request-Daten

Ist in der Umgebung ein Token für den Hosting-Dienst des Repositorys gesetzt, ergänzen die Tools Titel, Nummern, Labels und verknüpfte Issues von Pull Requests (Merge Requests): GITHUB_TOKEN (oder GH_TOKEN) für GitHub, GITLAB_TOKEN (oder GL_TOKEN) für GitLab, AZURE_DEVOPS_EXT_PAT (ein persönliches Zugriffstoken) oder AZURE_DEVOPS_TOKEN (ein Token von Microsoft Entra) für Azure DevOps. Ohne Token verwenden sie nur lokale Git-Daten und nennen die Variable, die zu setzen ist.

Den Server ohne das Plugin verwenden

Der Server ist auch ein gewöhnlicher MCP-Server: ohne Skills, mit Tools namens mcp__mergecat__<tool>. Seine Anweisungen fordern den Client auf, die Compliance-Frage zu stellen und Dokumente dem Benutzer in der Unterhaltung zu übergeben, nicht als Dateien im Projekt.

Den Server beziehen

Laden Sie die einzelne Datei mergecat-mcp.cjs aus dem Download-Bereich herunter oder bauen Sie sie aus einem Klon mit npm run mcp:build (sie wird nach plugins/mergecat/server/mergecat-mcp.cjs geschrieben). Sie benötigt Node.js 20 oder neuer.

Zu Claude Code hinzufügen

claude mcp add --transport stdio --scope user mergecat -- node /path/to/mergecat-mcp.cjs

Um Umgebungsvariablen zu übergeben, fügen Sie -e NAME=value vor -- ein, zum Beispiel -e MERGECAT_COMPLIANCE_DIR=/path/to/records.

Prüfen

Starten Sie Claude Code in einem Git-Repository und führen Sie /mcp aus: Der Server mergecat sollte verbunden sein. Der Server schreibt seine Logs nach stderr und gibt beim Start mergecat MCP server 0.3.0 ready aus.

Andere MCP-Clients, die stdio-Server starten, führen ihn auf dieselbe Weise aus, node /path/to/mergecat-mcp.cjs: Zu GitHub Copilot, OpenAI Codex und GitLab Duo siehe Andere KI-Assistenten. Außerhalb von Claude Code ist CLAUDE_PROJECT_DIR nicht gesetzt: Der Server verwendet die im Client geöffneten Ordner, sofern der Client sie mitteilt; andernfalls setzen Sie MERGECAT_REPOSITORY oder übergeben repository an die Tools.

Umgebungsvariablen

VariableWirkung
GITHUB_TOKENGitHub-Token für Pull-Request-Daten; GH_TOKEN wird verwendet, wenn GITHUB_TOKEN nicht gesetzt ist
GITLAB_TOKENGitLab-Token (read_api) für Merge-Request-Daten; GL_TOKEN wird verwendet, wenn GITLAB_TOKEN nicht gesetzt ist
AZURE_DEVOPS_EXT_PATPersönliches Zugriffstoken für Azure DevOps für Pull-Request-Daten; AZURE_DEVOPS_TOKEN nimmt stattdessen ein Token von Microsoft Entra auf
MERGECAT_AI_SERVICEDer KI-Dienst, um den es in der Compliance-Frage geht, wenn der Client nicht erkannt wird: claude, copilot, openai, gitlab-duo oder ein anderer Name
MERGECAT_GIT_PATHGit-Programmdatei, wenn git nicht im PATH liegt
MERGECAT_COMPLIANCE_DIROrdner der KI-Nutzungsnachweise anstelle des Standardordners
MERGECAT_REPOSITORYRepository, das verwendet wird, wenn ein Tool keinen Parameter repository erhält; zugleich der Projektordner, den render_pdf schützt
CLAUDE_PROJECT_DIRVon Claude Code gesetzt: das Projekt, verwendet, wenn weder der Parameter noch MERGECAT_REPOSITORY angegeben ist

In Claude Code übergibt das Plugin die oben genannten Token-Variablen, MERGECAT_GIT_PATH und MERGECAT_COMPLIANCE_DIR aus der Umgebung, in der Sie Claude Code starten.
