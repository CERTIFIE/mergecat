Integrationen

Andere KI-Assistenten

Verwenden Sie das mergecat-Plugin und den MCP-Server mit GitHub Copilot, OpenAI Codex und GitLab Duo: mit der Compliance-Frage des jeweiligen Dienstes, dem Repository und den Pull-Request-Daten.

Auf GitHub bearbeiten

Mithilfe von KI aus dem Englischen übersetzt. Im Zweifel gilt die englische Fassung.

Das mergecat-Plugin ist nicht nur für Claude Code gedacht. Derselbe Ordner ist zugleich ein portables Paket im Format Agent Plugins, mit den beiden Skills (changelog und tags, im Format SKILL.md) und dem mergecat-MCP-Server. GitHub Copilot, OpenAI Codex und GitLab Duo laden diese Skills und starten lokale MCP-Server, daher funktionieren dort dieselben Tools und dieselben Schritte.

AssistentSo fügen Sie mergecat hinzuToolsSkills
GitHub Copilot in VS Codedie mergecat-Erweiterung für VS Code fügt den Server selbst hinzu; oder das Pluginjamit dem Plugin
GitHub Copilot CLIdas Plugin oder die MCP-Konfiguration von Copilotjamit dem Plugin
OpenAI Codex (CLI, IDE-Erweiterung, App)das Plugin oder config.tomljamit dem Plugin oder kopiert
GitLab Duo (VS Code, JetBrains, Duo CLI)mcp.json von GitLab Duojakopiert
ChatGPT im Web und in der Appnicht unterstützt——

Warum nicht ChatGPT

ChatGPT verbindet sich nur mit Remote-MCP-Servern, die über das Internet erreichbar sind. mergecat liest das Repository auf Ihrem Computer und sendet es nie an einen eigenen Server. Verwenden Sie Codex: Es führt den mergecat-Server lokal aus und funktioniert mit demselben ChatGPT-Konto.

Die Compliance-Frage des jeweiligen Assistenten

Der MCP-Server erkennt den Assistenten an dem Namen, den seine Client-Anwendung beim Verbinden meldet, und fragt nach den Business-Tarifen dieses Dienstes. Jede Antwort wird als KI-Nutzungsnachweis gespeichert, der den Dienst und die Client-Anwendung nennt.

AssistentDie erste Frage lautet, ob Sie Folgendes nutzen
Claudeein Claude-Team- oder -Enterprise-Konto
GitHub Copiloteine Lizenz für GitHub Copilot Business oder Enterprise
OpenAI (ChatGPT, Codex)einen Workspace von ChatGPT Business, Enterprise oder Edu oder einen OpenAI-API-Schlüssel einer Organisation
GitLab DuoGitLab Duo mit einem kostenpflichtigen GitLab-Abonnement (Premium oder Ultimate)
Jeder andere Clienteinen Business- oder Enterprise-Tarif dieses Clients

Wenn der Assistent nicht erkannt wird oder Sie sichergehen möchten, setzen Sie MERGECAT_AI_SERVICE in der Konfiguration des Servers: claude, copilot, openai, gitlab-duo oder den Namen eines anderen Dienstes. Die Konfigurationen für GitLab Duo weiter unten setzen die Variable.

GitHub Copilot

In VS Code, mit der mergecat-Erweiterung

Ist die mergecat-Erweiterung für VS Code installiert, bieten VS Code 1.101 und neuer den mergecat-MCP-Server ohne jede Konfiguration für Copilot an. Der Server ist in die Erweiterung eingebunden und läuft mit der Laufzeitumgebung von VS Code, daher wird Node.js nicht benötigt. Er liest den in VS Code geöffneten Ordner und stellt die Frage für GitHub Copilot.

Die Erweiterung fügt die Tools hinzu, nicht die Skills. Wenn Sie auch die Skills möchten, installieren Sie das Plugin (nächster Abschnitt) und schalten Sie die Einstellung mergecat.copilot.mcpServer aus, damit Copilot den Server nicht zweimal erhält.

Das Plugin, in VS Code und in Copilot CLI

Copilot liest Plugin-Marketplaces im Format von Claude Code, etwa den im mergecat-Repository. Fügen Sie in VS Code das Repository der Einstellung chat.plugins.marketplaces (experimentell) hinzu, als owner/repo für ein GitHub-Repository oder als Git-URL, und installieren Sie dann mergecat daraus. Das Plugin startet den Server mit node: Node.js 20 oder neuer muss im PATH liegen.

Konfiguration ohne das Plugin

Copilot in VS Code und Copilot CLI teilen sich die native Konfiguration: ~/.copilot/mcp-config.json für Sie persönlich oder .mcp.json im Stammverzeichnis eines Workspace. Verwenden Sie die einzelne Datei mergecat-mcp.cjs aus dem Download-Bereich:

{
  "mcpServers": {
    "mergecat": {
      "type": "stdio",
      "command": "node",
      "args": ["/path/to/mergecat-mcp.cjs"],
      "env": { "GITHUB_TOKEN": "${GITHUB_TOKEN}" },
      "tools": ["*"]
    }
  }
}

Copilot Business und Enterprise

Organisationen entscheiden, ob Copilot MCP-Server verwenden darf: Für Lizenzen von Copilot Business und Enterprise ist die Richtlinie standardmäßig ausgeschaltet. Bitten Sie einen Eigentümer der Organisation, sie zu erlauben.

OpenAI Codex

Das Plugin

Auch Codex liest Plugin-Marketplaces im Format von Claude Code. Fügen Sie das mergecat-Repository (oder einen lokalen Klon) als Marketplace hinzu:

codex plugin marketplace add CERTIFIE/mergecat

Installieren Sie dann mergecat über die Plugins der ChatGPT-Desktop-App und aktivieren Sie es für ein Projekt in .codex/config.toml:

[plugins."mergecat@mergecat"]
enabled = true

Konfiguration ohne das Plugin

Fügen Sie den Server in ~/.codex/config.toml hinzu. env_vars übergibt die Tokens aus der Umgebung, in der Codex gestartet wurde, ohne sie in die Datei zu schreiben:

[mcp_servers.mergecat]
command = "node"
args = ["/path/to/mergecat-mcp.cjs"]
env_vars = ["GITHUB_TOKEN", "GITLAB_TOKEN", "AZURE_DEVOPS_EXT_PAT"]

Für die Skills kopieren Sie die Ordner plugins/mergecat/skills/changelog und plugins/mergecat/skills/tags des mergecat-Repositorys nach ~/.agents/skills/ (für Sie persönlich) oder nach .agents/skills/ in einem Repository.

GitLab Duo

GitLab Duo Agentic Chat verwendet MCP-Server in VS Code, in JetBrains-IDEs und in der GitLab Duo CLI.

Externe MCP-Tools erlauben

Ein Owner der Gruppe auf oberster Ebene schaltet in den GitLab-Duo-Einstellungen der Gruppe Allow external MCP tools ein (unter GitLab Self-Managed zusätzlich das Feature-Flag mcp_client, für Flows und eigene Agents).

Den Server hinzufügen

Schreiben Sie ~/.gitlab/duo/mcp.json (Windows: %APPDATA%\GitLab\duo\mcp.json) oder .gitlab/duo/mcp.json in einem Projekt:

{
  "mcpServers": {
    "mergecat": {
      "type": "stdio",
      "command": "node",
      "args": ["/path/to/mergecat-mcp.cjs"],
      "env": { "MERGECAT_AI_SERVICE": "gitlab-duo" },
      "approvedTools": ["compliance_status", "repository_info", "tags", "changelog", "changesets", "where_entered"]
    }
  }
}

approvedTools genehmigt die nur lesenden Tools einmalig; record_compliance_answer und render_pdf, die Dateien auf Ihrem Computer schreiben, fragen weiterhin nach. Starten Sie die IDE oder die Duo CLI neu.

Die Skills hinzufügen

Kopieren Sie die Ordner plugins/mergecat/skills/changelog und plugins/mergecat/skills/tags nach .agents/skills/ im Projekt (oder in den Ordner für Benutzer-Skills der GitLab Duo CLI). GitLab Duo lädt sie in neuen Unterhaltungen.

Für Titel, Labels und verknüpfte Issues von Merge Requests starten Sie die IDE oder die CLI mit gesetztem GITLAB_TOKEN (ein Token mit dem Scope read_api).

Welches Repository

Außerhalb von Claude Code findet der Server das Repository in dieser Reihenfolge: über den Parameter repository des Tools, MERGECAT_REPOSITORY, die im Client geöffneten Ordner (VS Code meldet sie den MCP-Servern; bei mehreren Ordnern das erste Git-Repository), dann das Arbeitsverzeichnis des Servers.

Pull-Request-Daten

Die Tools ergänzen Daten von Pull Requests (Merge Requests), wenn ein Token für den Hosting-Dienst des Repositorys in der Umgebung des Servers gesetzt ist:

HostingVariablen
GitHubGITHUB_TOKEN oder GH_TOKEN
GitLabGITLAB_TOKEN oder GL_TOKEN
Azure DevOpsAZURE_DEVOPS_EXT_PAT (persönliches Zugriffstoken) oder AZURE_DEVOPS_TOKEN (Token von Microsoft Entra)

Ohne Token verwenden die Tools nur lokale Git-Daten und nennen die Variable, die zu setzen ist. Schreiben Sie ein Token nie in eine Konfigurationsdatei, die geteilt oder committet wird: Verweisen Sie stattdessen auf die Umgebung.
