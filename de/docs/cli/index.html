Integrationen

Kommandozeile

Geben Sie mit mergecat-log den gruppierten Verlauf eines Branches, Flow-Metriken, Änderungs-Audit-Berichte und Changeset-Blame im Terminal aus.

Auf GitHub bearbeiten

Mithilfe von KI aus dem Englischen übersetzt. Im Zweifel gilt die englische Fassung.

mergecat-log gibt den Verlauf eines Branches gruppiert nach Integration aus, wie die Desktop-App und VS Code, und exportiert ihn als JSON, Markdown, CSV oder HTML. Es berechnet außerdem Flow-Metriken, schreibt den Änderungs-Audit-Bericht und versieht jede Zeile einer Datei mit ihrer Integration. Es liest nur Git: kein Hosting-Dienst, keine Anmeldedaten, kein Netzwerk.

Ausführen

Die Kommandozeile ist Teil des mergecat-Quellcodes. Im Stammverzeichnis eines Klons (Node.js 20 oder neuer, Git im PATH):

npm install
npm run build -w @mergecat/core

Führen Sie es dann im Stammverzeichnis des Repositorys aus, entweder mit dem Befehl mergecat-log, den npm für den Workspace verlinkt, oder mit der gebauten Datei:

npx mergecat-log --repo ~/src/web-shop
node packages/core/dist/cli.cjs --repo ~/src/web-shop

Die folgenden Beispiele verwenden mergecat-log. Setzen Sie MERGECAT_GIT_PATH, wenn git nicht im PATH liegt.

Verwendung

mergecat-log [branch] [--repo <path>] [--base <ref>] [--since YYYY-MM-DD] [--until YYYY-MM-DD]
           [--grep <text>] [--author <text>] [--limit <n> | --all] [--format text|json|markdown|csv|html]
           [--show-forward-integration]
mergecat-log --metrics [--format text|json] [--since …] [--until …]
mergecat-log --audit [--base <ref>] [--format html|markdown|csv|json] [--env Name=ref|Name=tag:pattern]…
mergecat-log --blame <file> [--rev <rev>]

Optionen

OptionWertStandardWirkung
branchBranch, Tag oder CommitStandard-BranchDer zu gruppierende Verlauf. Standard: der Standard-Branch des Remotes (origin/HEAD), dann origin/main, origin/master, main, master, dann der aktuelle Branch
--repoPfadAktuelles VerzeichnisDas Repository (ein beliebiger Ordner darin)
--baseTag, Branch oder CommitkeineNur, was nach dieser Ref hinzukam, z. B. das vorherige Release
--sinceYYYY-MM-DDkeineIntegrationsdatum ab (einschließlich)
--untilYYYY-MM-DDkeineIntegrationsdatum bis (einschließlich)
--grepTextkeineBetreff, SHA-Präfix, Branch-Name, Nummer oder Titel des Pull Requests, auch innerhalb von Gruppen
--authorTextkeineName oder E-Mail-Adresse von Autor oder Integrator, auch innerhalb von Gruppen
--limitZahl50Maximale Anzahl der Einträge der obersten Ebene des Verlaufs
--allKein Limit
--formattext, json, markdown, csv, htmltext; html mit --auditAusgabeformat; siehe Ausgabeformate
--show-forward-integrationausgeblendetDie Commits „main in Feature mergen“ innerhalb von Gruppen anzeigen
--metricsFlow-Metriken statt des Verlaufs ausgeben
--auditDen Änderungs-Audit-Bericht ausgeben
--envName=ref oder Name=tag:patternkeineEine Umgebung für den Audit-Bericht; wiederholbar

--revRevisionArbeitsverzeichnisDie Revision, die --blame annotiert
-h, --helpDie Verwendung ausgeben

Die Filter (--base, --since, --until, --grep, --author) gelten für den Verlauf, die Metriken und den Audit-Bericht. Datumsangaben beziehen sich darauf, wann eine Änderung in den Branch kam.

Der Standard-Branch ist der Remote-Tracking-Branch, sofern es einen gibt. Führen Sie daher zuerst git fetch aus, um die neuesten Änderungen einzubeziehen, oder übergeben Sie den Branch, z. B. mergecat-log main.

Gruppierter Verlauf

mergecat-log --repo ~/src/web-shop
● 2026-11-19 2c08e10 Anna Rossi: Fix typo in README
■ 2026-11-19 611dccf Merge branch 'feature/login' [feature/login · merge-message]
    └ 75d09ca Anna Rossi: Validate password
    └ 4833211 Anna Rossi: Add login form
● 2026-11-19 5860bf5 Anna Rossi: Initial project structure

3 of 3 entries · 1 merges · 2 direct · 5 commits · 14 ms
  • ● ein direkter Commit, ■ eine Integration mit ihrem gemergten Branch und der Herkunft des Namens (hier die Merge-Nachricht), └ die Commits, die sie gebracht hat, ↺ ein Vorwärtsintegrations-Merge (mit --show-forward-integration).
  • Gruppen von Octopus-Merges zeigen eine Spur ▸ pro gemergtem Branch.
  • Kennzeichen wie squash-like oder mainline-inverted erscheinen in geschweiften Klammern hinter einer Zeile.
  • Die letzte Zeile zählt Einträge, Merges, direkte Commits und Commits; Warnungen (Shallow Clone, keine Merges, Squash-Merges) folgen mit ⚠.

Weitere Beispiele:

# What entered main since v1.2.0
mergecat-log main --base v1.2.0 --all

# Changes of one author in March 2026
mergecat-log --since 2026-03-01 --until 2026-03-31 --author anna@example.com

# Search in subjects, branch names and pull request titles
mergecat-log --grep login

Ausgabeformate

FormatVerlaufMetrikenAudit
textBaum wie oben gezeigt (Standard)Zusammenfassung (Standard)
jsonZusammenfassung, Einträge und die Commits jeder GruppeVollständiger MetrikberichtVollständiger Bericht mit Fingerabdruck
markdownDokument im Changelog-Stil, ein Abschnitt pro EintragZusammenfassung und Tabelle der Änderungen
csvEine Zeile pro Commit, mit den Spalten seines ChangesetsEine Zeile pro Änderung
htmlLesbares DokumentDruckbarer Bericht (Standard)

Schreiben Sie die Ausgabe mit Ihrer Shell in eine Datei, z. B. mergecat-log --all --format markdown > changesets.md.

Metriken

mergecat-log --metrics --since 2026-01-01

Beispielausgabe:

Metrics for main (2026-01-08 – 2026-03-27)
  entries 42 · integrations 31 (merges 28, squash 2, PR groups 1) · direct 11
  commits 156 · authors 7 · reverts 1 · +8213 −2944
  via pull request 74%
  lead time median 19 h · p90 6.5 d
  change size median 86 lines · p90 640
  risk: high 4, medium 13, low 25
MetrikBedeutung
entries, integrations, directChangesets des Zeitraums: Merges, Squash-Merges, Pull-Request-Gruppen und direkte Commits
commits, authors, reverts, linesCommits in allen Einträgen, unterschiedliche Autoren, Reverts, hinzugefügte und entfernte Zeilen
via pull requestAnteil der Einträge, die über einen Pull Request liefen
lead timeDurchlaufzeit vom ersten Commit einer Änderung bis zu ihrer Integration: Median und 90. Perzentil
change sizeGeänderte Zeilen pro Eintrag: Median und 90. Perzentil

--format json liefert den vollständigen Bericht: Summen, Verteilungen, eine Zeitreihe pro Woche oder Monat und die Mitwirkenden.

Audit-Bericht

# Everything since v1.1.0, as printable HTML
mergecat-log --audit --base v1.1.0 > audit.html

# As JSON, with the environments that run each change
mergecat-log --audit --base v1.1.0 --env 'Production=tag:v*' --env 'Staging=origin/staging' --format json > audit.json
  • --env Name=ref: Die Umgebung führt diesen Branch oder dieses Tag aus, z. B. Staging=origin/staging.
  • --env Name=tag:pattern: Die Umgebung führt das neueste Tag aus, das auf das Glob-Muster passt, z. B. Production=tag:v*.
  • Setzen Sie die Werte in Anführungszeichen: Shells expandieren *.

Die Kommandozeile liest nur Git, daher werden Genehmigungen als unbekannt gemeldet (oder als „No pull request“ bei Änderungen ohne Pull Request). Für Genehmigungen exportieren Sie den Bericht aus der Desktop-App oder VS Code bei verbundenem Hosting-Dienst. Inhalt, Risikofaktoren und Fingerabdruck: Änderungs-Audit-Berichte.

Changeset-Blame

mergecat-log --blame src/auth/login.ts
mergecat-log --blame src/auth/login.ts --rev v1.2.0
    1-1     4833211 feature/login                    Add login form
    2-2     75d09ca feature/login                    Validate password

Jeder Zeilenbereich zeigt den Commit, die Integration, die ihn in den analysierten Branch gebracht hat (gemergter Branch und Pull-Request-Nummer oder, bei einem direkten Commit, der Commit selbst), und den Betreff des Commits. Zeilen aus Commits, die den Branch noch nicht erreicht haben, zeigen not in <branch>; nicht committete Zeilen zeigen uncommitted. Ohne --rev wird die Datei im Arbeitsverzeichnis annotiert.

Exit-Codes

mergecat-log beendet sich bei Erfolg mit 0 und bei einem Fehler mit 1; den Fehler gibt es mit dem Präfix mergecat-log: auf stderr aus, zum Beispiel bei einer unbekannten Option oder einem Ordner, der kein Git-Repository ist.
