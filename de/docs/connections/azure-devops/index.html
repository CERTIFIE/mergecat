Verbindungen

Azure DevOps verbinden

Verbinden Sie mergecat über „Mit Microsoft anmelden“ oder ein persönliches Zugriffstoken mit Azure DevOps, und richten Sie die App in Microsoft Entra ID ein, die ein Administrator einmalig registriert.

Auf GitHub bearbeiten

Mithilfe von KI aus dem Englischen übersetzt. Im Zweifel gilt die englische Fassung.

Eine Verbindung mit Azure DevOps fügt Titel, Autoren und Links von Pull Requests, Namen gelöschter Branches, Squash- und Rebase-Merges, verknüpfte Work Items, Azure Pipelines, Umgebungen und Deployments hinzu. Merge-Nachrichten von Azure DevOps (Merged PR 12: Title) enthalten die Nummer und den Titel des Pull Requests, aber keinen Branch-Namen, daher ist die Verbindung hier besonders wichtig.

Anmelden

Öffnen Sie Datei › Verbindungen… (oder klicken Sie in der Symbolleiste auf Nur lokal · Verbinden) und verwenden Sie eine der beiden Optionen auf der Karte Azure DevOps.

Mit Microsoft anmelden. mergecat kopiert einen Code in Ihre Zwischenablage und öffnet die Microsoft-Anmeldeseite, wo Ihr Geschäftskonto, Ihr Single Sign-on und Ihre MFA gelten. Bestätigen Sie den Code; danach zeigt die Karte Ihr Konto. Die Anmeldung fordert Zugriff auf Azure DevOps (499b84ac-1321-427f-aa17-267ca6975798/.default) und ein Aktualisierungstoken (offline_access) an; mergecat erneuert das Zugriffstoken automatisch. Diese Option benötigt die Client-ID einer App-Registrierung in Microsoft Entra ID, die einmalig unter Einstellungen › Client-ID für Microsoft Entra ID (Azure DevOps) eingetragen wird (siehe Einrichtung durch den Administrator). Ohne sie ist die Schaltfläche deaktiviert, und die Karte weist darauf hin.

Persönliches Zugriffstoken verwenden. Fügen Sie ein Token ein und klicken Sie auf Verbinden. Token erstellen öffnet die Token-Seite von Azure DevOps. Das Token benötigt diese Scopes:

ScopeVerwendet für
Code (Read & write)Repository, Pull Requests; Schreibzugriff zum Erstellen von Pull Requests
Build (Read)Pipelines und Läufe
Environment (Read & manage)Umgebungen und Deployments
Work Items (Read)Verknüpfte Work Items

Sign in with Microsoft verwendet das eigene Microsoft-Konto von VS Code: Das ist das Single Sign-on, ohne Konfiguration und ohne App-Registrierung. Es funktioniert, wenn die Azure-DevOps-Organisation mit Ihrem Mandanten in Microsoft Entra ID verbunden ist (Geschäfts-, Schul- oder Unikonto).

Für Organisationen ohne Entra ID, für persönliche Microsoft-Konten und für Azure DevOps Server verwenden Sie ein persönliches Zugriffstoken mit den für die Desktop-App aufgeführten Scopes. Siehe VS-Code-Erweiterung.

Tokens werden mit dem Schlüsselbund des Systems verschlüsselt; siehe Wo Anmeldedaten gespeichert werden. Um die Verbindung zu entfernen, klicken Sie auf der Karte Azure DevOps auf Trennen.

Einrichtung durch den Administrator: App in Entra ID

Mit Microsoft anmelden in der Desktop-App benötigt eine App, die einmalig in Microsoft Entra ID registriert wird. Ihre Anwendungs-ID (Client-ID) ist nicht geheim, und ein Client Secret wird nicht benötigt.

Die App registrieren

Öffnen Sie im Microsoft Entra Admin Center App registrations und erstellen Sie eine neue Registrierung, zum Beispiel mit dem Namen „mergecat“. Wählen Sie die unterstützten Kontotypen:

  • multi-tenant (Konten in einem beliebigen Organisationsverzeichnis): Die Benutzer behalten den Standardmandanten organizations;
  • single-tenant: Die Benutzer tragen Ihre Mandanten-ID unter Einstellungen neben der Client-ID ein.

Public Client Flows erlauben

Setzen Sie unter Authentication die Option Allow public client flows auf Yes. Die Anmeldung per Gerätecode benötigt das.

Zugriff auf Azure DevOps gewähren

Fügen Sie unter API permissions die Berechtigung Azure DevOps › Delegated permissions › user_impersonation hinzu. Erteilen Sie die Administratoreinwilligung, wenn Ihre Benutzer nicht selbst einwilligen können.

Die Client-ID weitergeben

Kopieren Sie die Application (client) ID aus der Übersicht. Jede Person trägt sie unter Einstellungen › Client-ID für Microsoft Entra ID (Azure DevOps) ein, oder Sie stellen sie über MERGECAT_MICROSOFT_CLIENT_ID bereit (und den Mandanten über MERGECAT_MICROSOFT_TENANT).

Das Feld für den Mandanten akzeptiert organizations (jedes Geschäftskonto), eine Mandanten-ID oder eine Mandanten-Domain.

Umgebungsvariablen

VariableZweck
MERGECAT_MICROSOFT_CLIENT_IDClient-ID der App in Entra ID für Mit Microsoft anmelden. Füllt die Einstellung, wenn sie leer ist.
MERGECAT_MICROSOFT_TENANTMandant in Entra ID, Standard organizations.

Alle Variablen sind unter Konfiguration aufgeführt.

Erkannte Remotes

mergecat erkennt Azure-DevOps-Remotes auf dev.azure.com, die älteren Adressen *.visualstudio.com, SSH-Remotes auf ssh.dev.azure.com sowie URLs von Azure DevOps Server, die /_git/ enthalten.

Grenzen

  • Klassische Release-Pipelines werden nicht abgedeckt: Pipelines und Deployments stammen aus YAML-Pipelines und Umgebungen.
  • Checks von Pull Requests und Titel von Work Items werden noch nicht angezeigt.

SymptomAbhilfe
Mit Microsoft anmelden ist deaktiviertTragen Sie die Client-ID der App in Entra ID unter Einstellungen ein oder verwenden Sie ein persönliches Zugriffstoken.
Invalid Microsoft tenant: …Geben Sie im Feld für den Mandanten organizations, eine Mandanten-ID oder eine Domain ein.
Azure DevOps rejected the Microsoft sign-in. …Melden Sie sich erneut an. Schlägt es weiterhin fehl, ist die Organisation möglicherweise nicht mit Ihrem Mandanten in Entra ID verbunden, oder Ihr Konto ist kein Mitglied der Organisation: Verwenden Sie ein persönliches Zugriffstoken.
Azure DevOps rejected the personal access token: …Das Token ist möglicherweise abgelaufen oder wurde widerrufen, es fehlen ihm die erforderlichen Scopes, oder es gehört zu einer anderen Organisation.
Azure DevOps denied access to …Die Meldung nennt die fehlende Berechtigung, zum Beispiel Code (Read), View builds oder die Rolle Reader für die Umgebungen.
