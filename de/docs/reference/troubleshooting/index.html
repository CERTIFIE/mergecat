Fehlerbehebung und FAQ

Beheben Sie häufige Probleme mit Git, dem Eigentümer eines Repositorys, unsignierten Builds, Anmeldedaten, Verbindungen und dem Claude-Code-Plugin, und finden Sie Antworten auf häufige Fragen.

Auf GitHub bearbeiten

Mithilfe von KI aus dem Englischen übersetzt. Im Zweifel gilt die englische Fassung.

Die meisten Probleme haben ihre Ursache in der Umgebung, in der mergecat läuft: wo Git installiert ist, wem ein Repository gehört, welchen Schlüsselbund das System bietet oder wie das Team Pull Requests integriert. Suchen Sie unten die Meldung, die Sie sehen.

Git wurde nicht gefunden

Die Meldung lautet Git was not found. Install Git (https://git-scm.com/downloads) or set the path to the git executable in the settings.

mergecat verwendet zuerst den konfigurierten Pfad, dann git im PATH, dann die üblichen Installationsordner:

/opt/homebrew/bin/git, /usr/local/bin/git, /usr/bin/git.

Apps, die über das Dock oder den Finder gestartet werden, erhalten den PATH Ihrer Shell nicht; deshalb sucht mergecat auch in den Homebrew-Ordnern. /usr/bin/git benötigt die Xcode Command Line Tools; installieren Sie diese mit:

xcode-select --install

%ProgramFiles%\Git\cmd\git.exe, %ProgramFiles(x86)%\Git\cmd\git.exe und %LOCALAPPDATA%\Programs\Git\cmd\git.exe.

Installieren Sie Git for Windows oder suchen Sie in PowerShell nach einem vorhandenen Git:

Get-Command git

/usr/bin/git, /usr/local/bin/git.

Installieren Sie Git mit Ihrem Paketmanager, zum Beispiel sudo apt install git, oder suchen Sie ein vorhandenes Git mit which git.

Wenn Git an einem anderen Ort installiert ist, legen Sie seinen Pfad fest:

KomponenteWo
Desktop-AppEinstellungen › Git-Programmdatei; der Dialog zeigt die gefundene Version an
VS Codemergecat.gitPath (leer: git.path von VS Code, dann die üblichen Ordner)
Kommandozeile, MCP-ServerUmgebungsvariable MERGECAT_GIT_PATH

Git verweigert das Lesen des Repositorys

Die Meldung lautet Git refuses to read this repository because it is owned by another user, gefolgt von einem Befehl. Git schützt Sie vor Repositorys, die einem anderen Konto gehören („dubious ownership“), zum Beispiel auf einem externen Laufwerk, auf einer Netzwerkfreigabe, in einem von einem anderen Benutzer erstellten Ordner oder auf einem WSL- oder Container-Volume.

Wenn Sie dem Repository vertrauen, markieren Sie es als sicher und verwenden Sie dabei den Ordner aus der Meldung:

git config --global --add safe.directory "/path/to/repository"

Kein Git-Repository

Not a Git repository: … bedeutet, dass der Ordner nicht in einer Git-Arbeitskopie liegt. Öffnen Sie den Stammordner des Repositorys oder einen beliebigen Ordner darin. In VS Code durchsucht mergecat auch Unterordner des geöffneten Ordners (mergecat.repositoryScanDepth, standardmäßig zwei Ebenen).

Das System warnt, dass die App nicht signiert ist

Die Builds von mergecat sind noch nicht codesigniert oder notarisiert. Prüfen Sie zuerst den Download (siehe Unsignierte Builds) und gehen Sie dann so vor:

Wenn macOS meldet, dass mergecat nicht geöffnet werden kann, weil Apple es nicht auf Schadsoftware überprüfen kann:

  1. Versuchen Sie einmal, mergecat aus dem Ordner „Programme“ zu öffnen.
  2. Öffnen Sie Systemeinstellungen › Datenschutz & Sicherheit.
  3. Scrollen Sie zur Meldung zu mergecat, klicken Sie auf Dennoch öffnen und bestätigen Sie.

Wenn macOS meldet, dass die App beschädigt ist, steht der Download unter Quarantäne; nachdem Sie die Prüfsumme verifiziert haben, können Sie das Quarantäne-Attribut entfernen:

xattr -dr com.apple.quarantine /Applications/mergecat.app

Wenn Microsoft Defender SmartScreen Der Computer wurde durch Windows geschützt anzeigt, klicken Sie auf Weitere Informationen, prüfen Sie den Dateinamen und klicken Sie dann auf Trotzdem ausführen.

Linux prüft keine Signaturen von AppImages. Machen Sie das AppImage ausführbar, bevor Sie es starten:

chmod +x mergecat-linux-x86_64.AppImage

Anmeldedaten werden unter Linux nicht gespeichert

Die Meldung lautet Kein Secret Service (GNOME Keyring oder KWallet) gefunden: Anmeldedaten werden nur im Arbeitsspeicher gehalten, und nach einem Neustart der App müssen Sie sich erneut verbinden.

mergecat verschlüsselt Anmeldedaten mit dem Schlüsselbund des Systems und schreibt sie nie im Klartext. Ohne Secret Service hält es sie nur im Arbeitsspeicher. Installieren und entsperren Sie GNOME Keyring oder KWallet (die meisten Desktop-Umgebungen enthalten eines davon), starten Sie mergecat dann neu und verbinden Sie sich erneut. Auf Systemen ohne Secret Service verbinden Sie sich nach jedem Start erneut.

Auf jedem System hat Kein System-Schlüsselbund verfügbar dieselbe Bedeutung, und Anmeldedaten werden nur im Arbeitsspeicher gehalten (MERGECAT_MEMORY_CREDENTIALS ist gesetzt) bedeutet, dass die Umgebungsvariable MERGECAT_MEMORY_CREDENTIALS=1 gesetzt ist.

Fetch oder Tag-Push schlägt fehl

mergecat führt Git mit Ihren eigenen Anmeldedaten aus und fragt nie nach einem Passwort. Wenn Fetch oder Tag-Push fehlschlägt, führen Sie git fetch oder git push in einem Terminal im selben Repository aus: Fragt das nach einem Passwort, richten Sie einen Credential Helper (zum Beispiel Git Credential Manager) oder einen SSH-Schlüssel ein und versuchen Sie es dann in mergecat erneut.

Was mergecat im jeweiligen Fall zeigt, steht unter Grenzen und Integrationsarten.

Genehmigungen sind im Audit-Bericht „unknown“

Genehmigungen werden beim Hosting-Dienst gespeichert. Verbinden Sie GitHub, GitLab oder Azure DevOps, bevor Sie den Bericht exportieren; die Desktop-App und VS Code bieten beim Export an, eine Verbindung herzustellen. Die Kommandozeile stellt nie eine Verbindung her, daher zeigen ihre Berichte Genehmigungen immer als unbekannt. Siehe Änderungs-Audit-Berichte.

Eine Umgebung läuft mit einem Commit, der nicht in Ihrem Klon ist

Die Seite Deployments weist darauf hin, wenn in einer Umgebung ein Commit läuft, den Ihr Klon noch nicht hat, zum Beispiel nach einem Deployment aus einem neueren Build. Klicken Sie auf Abrufen (oder führen Sie git fetch aus) und vergleichen Sie erneut.

VS-Code-Befehle tun etwas Unerwartetes

„MergeCat for VS Code“ (mergecat.mergecat-vscode) ist eine fremde Erweiterung im Marketplace, die dieselben Befehls- und Einstellungsnamen registriert. Entfernen Sie sie:

code --uninstall-extension mergecat.mergecat-vscode

Claude-Code-Plugin

Die Compliance-Frage wird erneut gestellt

Das ist so vorgesehen. Die Antwort gehört zur Claude-Code-Sitzung: Jede Sitzung startet einen neuen Prozess des mergecat-MCP-Servers, der vor dem Senden der ersten Repository-Daten erneut fragt. Jede Antwort ist ein neuer KI-Nutzungsnachweis.

Claude meldet, dass eine Compliance-Bestätigung erforderlich ist

Die Repository-Tools sind gesperrt, bis die Frage mit einem Ergebnis beantwortet ist, das sie freigibt. Beantworten Sie die Frage, wenn Claude sie stellt. Wenn Sie früher in der Sitzung beide Fragen mit „nein“ beantwortet haben, fordern Sie die mergecat-Daten erneut an; Claude stellt die Frage dann noch einmal.

Die mergecat-Tools fehlen

  1. Führen Sie /mcp in Claude Code aus und prüfen Sie, ob der Server mergecat verbunden ist.
  2. Prüfen Sie, ob Node.js 20 oder neuer als node installiert ist: node --version.
  3. Prüfen Sie, ob das Plugin installiert ist: claude plugin list.
  4. Führen Sie nach dem Installieren oder Aktualisieren /reload-plugins aus oder starten Sie eine neue Sitzung.

Das Changelog enthält keine Titel von Pull Requests

Starten Sie Claude Code mit gesetztem Token für den Hosting-Dienst des Repositorys: GITHUB_TOKEN (oder GH_TOKEN) für GitHub, GITLAB_TOKEN (oder GL_TOKEN) für GitLab, AZURE_DEVOPS_EXT_PAT oder AZURE_DEVOPS_TOKEN für Azure DevOps. Erkannt werden nur Repositorys auf github.com, gitlab.com und Azure DevOps. Siehe Pull-Request-Daten.

Das PDF zeigt Fragezeichen

PDFs verwenden die Standard-PDF-Schriften, die nur Latin-1 abdecken. Fordern Sie für Sprachen mit anderen Schriftsystemen Markdown an. Siehe PDF-Ausgabe.

FAQ

Ändert mergecat mein Repository?

Nur wenn Sie einen Fetch ausführen, ein Tag erstellen oder pushen oder einen Pull Request erstellen. mergecat führt nie Commits, Checkouts oder Merges aus und schreibt nichts um. Siehe Sicherheit und Datenschutz.

Sendet mergecat meinen Code irgendwohin?

Die Desktop-App und VS Code kommunizieren nur mit dem Hosting-Dienst, den Sie verbinden. Das Claude-Code-Plugin sendet nach der Compliance-Frage Metadaten des Verlaufs (Commit-Nachrichten, Namen, E-Mail-Adressen, Datumsangaben, Branch- und Tag-Namen, Commit-SHAs und, mit einem Token, Pull-Request-Daten) an Claude; seine Tools senden weder Dateiinhalte noch Diffs. Claude Code selbst kann im Rahmen seiner eigenen Berechtigungen Dateien Ihres Projekts lesen.

Gibt es ein mergecat-Konto, einen mergecat-Server oder Telemetrie?

Nein. mergecat hat kein Konto, keinen Server und keine Telemetrie und sucht nicht nach Updates.

Funktioniert mergecat offline?

Ja, für alles, was den Hosting-Dienst nicht benötigt: Changesets, Diffs, Filter, Exporte, Branches, Tags und Audit-Berichte ohne Genehmigungen.

Warum fragt das Plugin nach einem Team- oder Enterprise-Konto?

Viele Organisationen erlauben Unternehmensdaten nur in KI-Konten, die durch eine Geschäftsvereinbarung abgedeckt sind. Die Frage und der Nachweis dokumentieren diese Entscheidung für jede Sitzung. Siehe EU-KI-Verordnung und NIS-2.
