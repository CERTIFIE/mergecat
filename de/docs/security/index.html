Compliance und Audit

Sicherheit und Datenschutz

Was mergecat in Ihrem Repository ändert, welche Daten Ihren Computer verlassen und wohin, wie Anmeldedaten gespeichert werden und was mergecat lokal aufbewahrt.

Auf GitHub bearbeiten

Mithilfe von KI aus dem Englischen übersetzt. Im Zweifel gilt die englische Fassung.

mergecat ist ein lokales Werkzeug: Es liest Ihre Repositorys mit Ihrem eigenen Git, kommuniziert nur mit den Hosting-Diensten, die Sie verbinden, und hat keinen eigenen Server. Diese Seite listet auf, was es ändern kann, welche Daten Ihren Computer verlassen, wie es Anmeldedaten speichert und was es auf der Festplatte ablegt.

Auf einen Blick

ThemaWie mergecat damit umgeht
RepositoryStandardmäßig nur lesend; schreibt nur auf ausdrückliche Befehle
NetzwerkNur die Hosting-Dienste, die Sie verbinden (GitHub, GitLab, Azure DevOps), und deren Anmeldeseiten; Claude nur über das Claude-Code-Plugin, nach der Compliance-Antwort
AnmeldedatenMit dem Schlüsselbund des Betriebssystems verschlüsselt; nur im Arbeitsspeicher, wenn kein Schlüsselbund verfügbar ist
TelemetrieKeine: keine Nutzungsstatistiken, keine Absturzberichte, keine Update-Prüfungen, kein mergecat-Server
Lokale DatenEinstellungen, verschlüsselte Anmeldedaten und ein Pull-Request-Cache im Datenordner der App; nie im Repository

Standardmäßig nur lesend

mergecat liest den Verlauf mit git log, git blame und ähnlichen Befehlen. Es führt nie Commits, Checkouts, Merges oder Rebases aus, schreibt nichts um und rührt nie Ihr Arbeitsverzeichnis oder Ihre lokalen Branches an. Nur diese Aktionen ändern etwas, und nur, wenn Sie sie starten:

AktionWas sie ändertWo
AbrufenFührt git fetch --all --tags --prune aus: aktualisiert Remote-Tracking-Branches und Tags und entfernt die auf dem Remote gelöschten. Lokale Branches und Dateien werden nicht angetastet.Desktop-App (Seite Branches), VS Code (Seite Branches, Fetch All Remotes)
Tag erstellenErstellt ein lokales Tag auf dem gewählten Commit; annotiert, wenn Sie eine Nachricht eingebenDesktop-App, VS Code (Seite Tags, Create Tag…, Create Tag Here…)
Tag pushenPusht genau dieses eine Tag zum RemoteDesktop-App, VS Code (Seite Tags)
Pull Request erstellenErstellt einen Pull Request (GitLab: Merge Request) beim Hosting-DienstDesktop-App, VS Code (Seite Pull Requests, Create Pull Request…)

Exporte und Audit-Berichte werden nur dort geschrieben, wo Sie sie speichern. Der MCP-Server des Claude-Code-Plugins ändert das Repository nie: Er schreibt nur die KI-Nutzungsnachweise und, auf Anfrage, PDF-Dateien außerhalb des Projekts. Claude aktualisiert CHANGELOG.md nur, wenn Sie ausdrücklich darum bitten.

So führt mergecat Git aus:

  • Ihre eigene Programmdatei git, direkt gestartet, nie über eine Shell;
  • mit GIT_TERMINAL_PROMPT=0: Fetch und Tag-Push verwenden Ihren Credential Helper oder SSH-Schlüssel und fragen nie nach einem Passwort;
  • mit GIT_OPTIONAL_LOCKS=0, damit das Lesen keine optionalen Sperren von Git setzt.

Daten, die Ihren Computer verlassen

ZielWannWas
Ihre Git-RemotesFetch und Tag-PushWas Git austauscht, mit Ihren Git-Anmeldedaten
APIs der Hosting-Dienste: GitHub, GitLab, Azure DevOpsNur wenn der Dienst verbunden istAbfragen von Pull Requests, Genehmigungen, verknüpften Issues, Pipelines und Deployments des Repositorys; die Pull Requests, die Sie erstellen
Anmeldeseiten: github.com, login.microsoftonline.com, Ihre GitLab-InstanzWenn Sie sich über den Browser anmeldenDie Anmeldung per Device Flow; dort gelten SSO und MFA Ihrer Organisation
Claude (Anthropic) oder der KI-Assistent, in dem Sie den mergecat-MCP-Server ausführen (GitHub Copilot, OpenAI Codex, GitLab Duo)Nur über den mergecat-MCP-Server, nachdem die Compliance-Frage es erlaubt hatMetadaten des Verlaufs: Commit-Nachrichten, Namen und E-Mail-Adressen von Autoren und Committern, Datumsangaben, Branch- und Tag-Namen, Commit-SHAs; mit einem Token des Hosting-Dienstes Titel, Nummern, Labels und verknüpfte Issues von Pull Requests

Sonst nichts. mergecat hat keine Telemetrie: Es erhebt keine Nutzungsstatistiken und sendet keine Absturzberichte. Es sucht nicht nach Updates und hat keinen mergecat-Server und kein Konto. Die Desktop-App bringt ihre Schriftarten mit und lädt nichts von einem CDN.

Die mergecat-MCP-Tools geben Claude Metadaten des Verlaufs, nicht den Inhalt Ihrer Dateien oder Diffs. Claude Code selbst kann im Rahmen seiner eigenen Berechtigungen Dateien Ihres Projekts lesen; der Changelog-Skill liest zum Beispiel CHANGELOG.md.

KI-Nutzung wird aufgezeichnet

Bevor die ersten Repository-Daten einer Claude-Code-Sitzung gesendet werden, fragt mergecat, ob Sie ein Claude-Team- oder -Enterprise-Konto nutzen, und zeichnet die Antwort auf. Siehe EU-KI-Verordnung und NIS-2.

Anmeldedaten

Desktop-App

Tokens werden mit dem Schlüsselbund des Betriebssystems (Electron safeStorage) verschlüsselt und in credentials.bin im Datenordner der App gespeichert.

Der Verschlüsselungsschlüssel wird im Schlüsselbund (Keychain) von macOS aufbewahrt.

Die Daten werden mit DPAPI von Windows für Ihr Benutzerkonto verschlüsselt.

Der Verschlüsselungsschlüssel wird von einem Secret Service aufbewahrt: GNOME Keyring (libsecret) oder KWallet. Ohne einen solchen hält mergecat die Anmeldedaten nur im Arbeitsspeicher und zeigt eine Warnung an: Sie müssen sich nach einem Neustart der App erneut verbinden. Siehe Fehlerbehebung.

  • Wenn kein Schlüsselbund verfügbar ist, werden Anmeldedaten nur im Arbeitsspeicher gehalten und nie im Klartext geschrieben.
  • Die Anmeldung über die GitHub CLI speichert kein Token: mergecat führt gh auth token aus, wenn es eines braucht.
  • Anmeldetokens der Browser-Abläufe werden erneuert, bevor sie ablaufen.
  • Trennen im Dialog Verbindungen löscht die gespeicherten Anmeldedaten dieses Dienstes.

VS-Code-Erweiterung

  • GitHub und Azure DevOps (Sign in with Microsoft) verwenden die Konten, die VS Code bereits verwaltet. Das Token bleibt in VS Code; mergecat fragt VS Code bei Bedarf danach.
  • Persönliche Zugriffstokens und GitLab-Anmeldetokens werden im SecretStorage von VS Code gespeichert (gestützt auf den Schlüsselbund des Betriebssystems), eines pro Dienst und Host. Sie werden nie in Einstellungen oder Logs geschrieben.

Claude-Code-Plugin und Kommandozeile

  • Der MCP-Server liest GITHUB_TOKEN (oder GH_TOKEN) aus seiner Umgebung, für Pull-Request-Daten von Repositorys auf github.com. Er speichert das Token nicht.
  • Die Kommandozeile verwendet keinen Hosting-Dienst und keine Anmeldedaten außer Ihrer Git-Einrichtung.

Minimale Rechte

Geben Sie Tokens nur die Scopes, die mergecat benötigt. Zum Lesen genügen Lese-Scopes; nur das Erstellen von Pull Requests erfordert Schreibzugriff (zum Beispiel genügt bei GitLab read_api zum Lesen, api ist zum Erstellen von Merge Requests nötig). Die Scopes pro Dienst sind unter Verbindungen aufgeführt.

mergecat schreibt nie Caches oder Einstellungen in Ihr Repository.

Der Datenordner der Desktop-App:

~/Library/Application Support/mergecat/
%APPDATA%\mergecat\
~/.config/mergecat/

Oder $XDG_CONFIG_HOME/mergecat/, wenn XDG_CONFIG_HOME gesetzt ist.

Um alles zu entfernen, trennen Sie die Dienste, beenden Sie die App und löschen Sie diesen Ordner. Unter macOS und Windows liegen die Compliance-Nachweise in seinem Unterordner compliance: Bewahren Sie sie auf, wenn Sie sie für Audits benötigen.

Härtung der Desktop-App

  • Der Fensterinhalt läuft in einem Renderer in einer Sandbox, mit Context Isolation und ohne Node.js-Zugriff; er kommuniziert mit dem Hauptprozess über eine schmale Schnittstelle.
  • Das Fenster navigiert nie aus der App heraus. Links öffnen sich in Ihrem Standardbrowser, und nur https://-Links werden geöffnet.
  • Es läuft immer nur eine Instanz der App gleichzeitig.

Unsignierte Builds

Codesignierung und Notarisierung sind noch nicht eingerichtet, daher warnen macOS und Windows, wenn Sie mergecat zum ersten Mal öffnen (so öffnen Sie es). Bevor Sie bestätigen:

  • laden Sie mergecat nur von der Release-Seite des Projekts oder aus dem Download-Bereich herunter;
  • vergleichen Sie die SHA-256-Prüfsumme der Datei mit der im Release veröffentlichten (SHA256SUMS.txt, auch in den Release Notes aufgeführt):
shasum -a 256 ~/Downloads/mergecat-mac-arm64.dmg
Get-FileHash "$HOME\Downloads\mergecat-windows-x64-setup.exe" -Algorithm SHA256
sha256sum ~/Downloads/mergecat-linux-x86_64.AppImage
  • wenn Ihre Richtlinie keine unsignierte Software erlaubt, bauen Sie mergecat aus dem Quellcode (siehe Installation) oder warten Sie auf signierte Releases.
