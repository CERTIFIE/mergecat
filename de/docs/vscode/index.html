Integrationen

VS-Code-Erweiterung

Installieren Sie die mergecat-Erweiterung für VS Code und nutzen Sie ihre Ansichten, Repository-Seiten, Befehle und Einstellungen.

Auf GitHub bearbeiten

Mithilfe von KI aus dem Englischen übersetzt. Im Zweifel gilt die englische Fassung.

Die mergecat-Erweiterung bringt die Changeset-Ansicht in VS Code: den Verlauf eines Branches gruppiert nach Integration, die Repository-Seiten (Branches, Tags, Pull Requests, Pipelines, Deployments) als Editor-Tabs, Changeset-Blame, Metriken und den Änderungs-Audit-Bericht. Sie meldet sich mit den GitHub- und Microsoft-Konten an, die VS Code bereits kennt.

Voraussetzungen: VS Code 1.90 oder neuer und Git. Die Konfliktprüfung der Seite Branches benötigt Git 2.38 oder neuer.

Installieren

Noch nicht im Marketplace

Die Erweiterung ist noch nicht im Visual Studio Marketplace veröffentlicht. Installieren Sie sie aus der .vsix-Datei eines Releases oder bauen Sie sie aus dem Quellcode.

Laden Sie mergecat-vscode.vsix aus dem Download-Bereich herunter und installieren Sie die Datei auf eine von zwei Arten.

Kommandozeile:

code --install-extension mergecat-vscode.vsix

VS Code: Öffnen Sie die Ansicht der Erweiterungen, klicken Sie oben in der Ansicht auf das Menü …, wählen Sie Install from VSIX… und wählen Sie die Datei aus.

Im Stammverzeichnis eines Klons des mergecat-Repositorys (Node.js 20 oder neuer):

npm install
npm run vscode:install

Das Skript baut und paketiert die Erweiterung und installiert sie in VS Code; es findet den Befehl code auch dann, wenn er nicht im PATH liegt. Führen Sie es nach Änderungen erneut aus. Um die Erweiterung zu entfernen:

npm run vscode:install -- --uninstall

Führen Sie dann Developer: Reload Window aus, öffnen Sie einen Ordner, der ein Git-Repository enthält, und klicken Sie in der Aktivitätsleiste auf das Symbol mergecat.

Eine andere Erweiterung mit ähnlichem Namen

„MergeCat for VS Code“ (mergecat.mergecat-vscode) im Marketplace ist eine fremde Erweiterung, die dieselben Befehls- und Einstellungsnamen registriert. Installieren Sie nicht beide. Ist sie installiert, entfernen Sie sie:

code --uninstall-extension mergecat.mergecat-vscode

Ansichten

Das mergecat-Symbol in der Aktivitätsleiste öffnet drei Ansichten.

Welches Repository? Liegt der geöffnete Ordner in einem Git-Repository, wird dieses Repository angezeigt. Andernfalls durchsucht mergecat seine Unterordner (standardmäßig zwei Ebenen, mergecat.repositoryScanDepth). Findet es ein Repository, öffnet es dieses; bei mehreren zeigt es das zuletzt verwendete oder das der Datei im Editor oder fordert Sie zur Auswahl auf (auch über die Repository-Schaltfläche in der Titelleiste).

Changesets

Der gruppierte Verlauf des ausgewählten Branches, in zwei Layouts. Wechseln Sie mit List | Graph in der Kopfzeile oder mit Show Commit Graph / Show Changesets List.

  • List: direkte Commits als einzelne Zeilen, Integrationen (Merges und, bei bestehender Verbindung, per Rebase gemergte Pull Requests) als aufklappbare Gruppen. Die zweite Zeile jedes Eintrags zeigt kurzen SHA, Autor, Datum, Risiko und die Umgebungen, die die Änderung bereits enthalten. Klicken Sie auf einen Commit, um seine Änderungen zu öffnen; verwenden Sie die Diff-Schaltfläche der Zeile oder das Kontextmenü, um die kombinierten Änderungen einer Gruppe zu öffnen.
  • Graph: jeder Commit mit seinen Spuren; der Chip in der zweiten Zeile zeigt, welches Changeset den Commit in den Branch gebracht hat.

Die Kopfzeile zeigt Repository und Branch (zum Wechseln anklicken), das Suchfeld, die aktiven Filter als entfernbare Chips, Warnungen, die Anzahl der Einträge und den Verbindungsstatus. Klicken Sie mit der rechten Maustaste auf eine Zeile, um ihre Aktionen aufzurufen: Änderungen öffnen, Herkunft des Commits ermitteln, Pull Request öffnen, SHA kopieren. Tastatur: ↑ ↓ zum Bewegen, ← → zum Zu- und Aufklappen, Enter zum Öffnen.

Environments

Was wo deployt ist und welche Integrationen des Branches dort noch nicht deployt sind. Klicken Sie auf einen Eintrag, um ihn anzuzeigen; die Inline-Aktion schaltet die Ansicht Changesets auf „was noch nicht in dieser Umgebung ist“ um.

Eine Umgebung ist ein Branch, der auf den deployten Code zeigt (zum Beispiel origin/production), oder ein Tag-Muster, dessen neuestes Tag die deployte Version ist (zum Beispiel prod-*). Ohne Konfiguration werden Branches namens production, staging, test oder develop sowie Release-Tags erkannt; mit einer Verbindung kommen die letzten erfolgreichen Deployments des Hosting-Dienstes hinzu. Konfigurieren Sie die Umgebungen mit mergecat.environments.definitions:

"mergecat.environments.definitions": [
  { "name": "Production", "tagPattern": "prod-*" },
  { "name": "Staging", "ref": "origin/staging" }
]

Connections

Die Hosting-Connectors (GitHub, GitLab, Azure DevOps; Bitbucket folgt in Kürze), wie die Anmeldung bei jedem erfolgt ist und was eine Verbindung hinzufügt. Das Remote des Repositorys entscheidet, welcher Connector verwendet wird.

Repository-Seiten

Fünf Seiten öffnen sich als Editor-Tabs: über die Schaltflächen unter der Kopfzeile von Changesets (Branches · Tags · PRs · Pipelines · Deploys), über das Menü … der Ansicht oder mit den Befehlen mergecat: Open ….

SeiteInhaltVerbindung
BranchesJeder lokale Branch und die Remote-Branches ohne lokale Kopie: eingehende und ausgehende Commits, not on origin, upstream deleted, Vorsprung/Rückstand gegenüber der Basis, merged, Konflikte mit der Basis (mit Dateiliste), Alter. Fetch führt git fetch --all --prune --tags aus.Lokal
TagsName, Commit, Datum, Ersteller, Nachricht, annotiert oder leichtgewichtig, Version, auf origin oder local only mit einer Schaltfläche Push. New tag prüft den Namen während der Eingabe und kann das Tag pushen.Lokal
Pull RequestsOffen, geschlossen oder alle, mit Status, Reviewern und ihren Bewertungen sowie Checks; Details mit Commits und verknüpften Issues. New pull request füllt Titel und Beschreibung aus den Commits vor.Verbunden
PipelinesGitHub Actions, GitLab CI/CD und Azure Pipelines: Activity (Stages, Jobs, Schritte, Abhängigkeiten), Text (das YAML) und Runs (Status und Dauer jedes Jobs).Verbunden
DeploymentsDas aktive Deployment jeder Umgebung und die früheren mit ihren Tags; Compare environments mit Release Notes und Audit-Bericht; was jedes Deployment gebracht hat.Verbunden

Ohne Verbindung zeigt die Seite Deployments die lokal gefundenen Umgebungen (Einstellungen, Branch- und Tag-Namen) und vergleicht sie auf dieselbe Weise.

Einblicke

  • Changeset-Blame: mergecat: Toggle Changeset Blame (auch in der Titelleiste des Editors) versieht die Zeile unter dem Cursor mit der Integration, die sie in den analysierten Branch gebracht hat: Pull Request oder gemergter Branch, Titel, Datum und die Umgebungen, die sie erreicht hat. Der Hover ergänzt Commit, Integrator, Genehmigungen und verknüpfte Issues (bei Verbindung), das erste Release-Tag und das Risiko.
  • Changesets That Shaped This File listet die Integrationen auf, die die aktuelle Datei geschrieben haben, die mit dem größten Anteil zuerst.
  • Risiko pro Integration: ein Wert aus Umfang, Anzahl der Dateien, sensiblen Bereichen, ohne Tests geändertem Code, direkten Commits und lokalen Merges ohne Pull Request, Merges ohne Genehmigung (bei Verbindung) und Reverts. Filtern Sie mit Filter… › Risk…. Die Faktoren sind unter Änderungs-Audit-Berichte aufgeführt.
  • Metriken: mergecat: Show Metrics zeigt eingegangene Änderungen, den Anteil über Pull Requests, Durchlaufzeit, Änderungsgröße, Reverts, Autoren, Aktivität pro Woche oder Monat, Risikoverteilung und die aktivsten Mitwirkenden. Bei einer Verbindung mit GitHub kommt die Zeit bis zum Merge hinzu.

Audit-Bericht

Führen Sie mergecat: Export Audit Report… aus (Befehlspalette oder Menü … der Ansicht Changesets) und wählen Sie den Bereich: die aktuelle Ansicht, Between two releases…, Between two environments… oder Not yet in einer Umgebung. Wählen Sie HTML, Markdown, CSV oder JSON und den Speicherort. Die Seite Deployments bietet denselben Bericht für die Änderungen von Compare environments an.

Genehmigungen stammen vom Hosting-Dienst: Ohne Verbindung warnt der Befehl, dass sie als „unknown“ gemeldet werden, und bietet an, eine Verbindung herzustellen. Details: Änderungs-Audit-Berichte.

Anmeldung pro Dienst

Verbinden Sie sich über die Ansicht Connections, die Pille Local only · Connect in der Kopfzeile von Changesets oder mergecat: Connect….

DienstAnmeldungHinweise
GitHub (github.com)GitHub-Konto von VS CodeSSO der Organisation inbegriffen; Scope repo; das Token bleibt in VS Code
Azure DevOps (dev.azure.com)Sign in with Microsoft mit dem Microsoft-Konto von VS CodeFunktioniert, wenn die Azure-DevOps-Organisation mit Microsoft Entra ID verbunden ist (Geschäfts-, Schul- oder Unikonto)
Azure DevOps (Alternative, auch Azure DevOps Server)Persönliches ZugriffstokenScopes Code (Read & write), Build (Read), Environment (Read & manage), Work Items (Read)
GitLab (gitlab.com)Persönliches ZugriffstokenScope api (read_api genügt zum Lesen; api ist zum Erstellen von Merge Requests nötig)
GitLab (optional)Sign in with GitLab im Browser (GitLab 17.2 oder neuer)Benötigt die Anwendungs-ID einer nicht vertraulichen OAuth-Anwendung in mergecat.gitlab.clientId

Persönliche Zugriffstokens und Tokens der GitLab-Anmeldung werden im SecretStorage von VS Code gespeichert, eines pro Dienst und Host, und nie in Einstellungen oder Logs. Trennen Sie Verbindungen über die Ansicht Connections. Siehe auch Sicherheit und Datenschutz.

Einstellungen

EinstellungStandardBeschreibung
mergecat.gitPathleerGit-Programmdatei. Leer: git.path der integrierten Git-Erweiterung, dann die üblichen Installationsorte
mergecat.pageSize200Einträge der obersten Ebene, die auf einmal geladen werden (20 bis 5000)
mergecat.hideForwardIntegrationMergestrueDie Merges des Main-Branches in einen Feature-Branch innerhalb von Gruppen ausblenden
mergecat.defaultBranchleerBranch, der beim Öffnen eines Repositorys analysiert wird, z. B. origin/main. Leer: der Standard-Branch des Remotes, dann main/master, dann der aktuelle Branch
mergecat.repositoryScanDepth2Ebenen von Unterordnern, die nach Repositorys durchsucht werden, wenn der geöffnete Ordner kein Repository ist (0 bis 5; 0 = nur der geöffnete Ordner)
mergecat.environments.definitions[]Umgebungen: { "name", "ref" } oder { "name", "tagPattern" }
mergecat.environments.autoDetecttrueUmgebungen aus Branch-Namen und Release-Tags ableiten, wenn keine konfiguriert sind
mergecat.risk.sensitiveAreas[]Ersetzt die standardmäßigen sensiblen Bereiche des Risikowerts; jedes Element { "id", "label", "points", "patterns" }. Leer: Standardwerte
mergecat.risk.testPatterns[]Globs der Testdateien für den Faktor „keine Tests geändert“. Leer: Standardwerte
mergecat.gitlab.clientIdleerAnwendungs-ID einer GitLab-OAuth-Anwendung für Sign in with GitLab. Leer: persönliches Zugriffstoken

Beispiel für eigene sensible Bereiche:

"mergecat.risk.sensitiveAreas": [
  { "id": "billing", "label": "Billing", "points": 3, "patterns": ["src/billing/**"] }
]

Unterschiede zur Desktop-App

Beide Apps lesen denselben Verlauf mit derselben Engine und haben dieselben Repository-Seiten. Die Unterschiede:

VS-Code-ErweiterungDesktop-App
Ansicht ChangesetsAnsicht in der Seitenleiste, Diffs im Diff-Editor von VS CodeGanzes Fenster mit Detailbereich
Changeset-Blame, Changesets That Shaped This Filejanein
Metrikbereichjanein
Risiko und Umgebungen in jeder Zeilejanein
Umgebungsdefinitionenmergecat.environments.definitionsaus den Deployments des Hosting-Dienstes
Spalte Umgebungen im Audit-Berichtgefülltleer
GitHub-AnmeldungGitHub-Konto von VS CodeMit GitHub anmelden (OAuth App), GitHub CLI oder Token
Azure-DevOps-AnmeldungMicrosoft-Konto von VS Code oder TokenMit Microsoft anmelden (App in Entra ID) oder Token
Speicherung der AnmeldedatenKonten und SecretStorage von VS CodeSchlüsselbund des Betriebssystems

Zur Desktop-App siehe Installation und Verlauf. Bekannte Grenzen beider stehen unter Grenzen und Integrationsarten.
