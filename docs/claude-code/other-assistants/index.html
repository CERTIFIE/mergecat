Integrations

Other AI assistants

Use the mergecat plugin and MCP server with GitHub Copilot, OpenAI Codex and GitLab Duo, with the compliance question of each service, the repository and pull request data.

Edit on GitHub

The mergecat plugin is not only for Claude Code. The same folder is also a portable Agent Plugins package, with the two skills (changelog and tags, in the SKILL.md format) and the mergecat MCP server. GitHub Copilot, OpenAI Codex and GitLab Duo load these skills and start local MCP servers, so the same tools and the same steps work there.

Why not ChatGPT

ChatGPT connects only to remote MCP servers, reachable over the internet. mergecat reads the repository on your computer and never sends it to a server of its own. Use Codex, which runs the mergecat server locally and works with the same ChatGPT account.

The compliance question of each assistant

The MCP server recognizes the assistant from the name its client application reports when it connects, and asks about that service’s business plans. Every answer is saved as an AI usage record that names the service and the client application.

AssistantThe first question asks whether you use
Claudea Claude Team or Enterprise account
GitHub Copilota GitHub Copilot Business or Enterprise license
OpenAI (ChatGPT, Codex)a ChatGPT Business, Enterprise or Edu workspace, or an organization’s OpenAI API key
GitLab DuoGitLab Duo with a paid GitLab subscription (Premium or Ultimate)
Any other clienta business or enterprise plan of that client

If the assistant is not recognized, or you want to be sure, set MERGECAT_AI_SERVICE in the server configuration: claude, copilot, openai, gitlab-duo, or the name of another service. The configurations below for GitLab Duo set it.

GitHub Copilot

In VS Code, with the mergecat extension

With the mergecat VS Code extension installed, VS Code 1.101 and later offer the mergecat MCP server to Copilot without any configuration. The server is bundled with the extension and runs with the runtime of VS Code, so Node.js is not needed. It reads the folder open in VS Code and asks the GitHub Copilot question.

The extension adds the tools, not the skills. For the skills too, install the plugin (next section) and turn off the setting mergecat.copilot.mcpServer, so that Copilot does not get two copies of the server.

The plugin, in VS Code and in Copilot CLI

Copilot reads plugin marketplaces in the Claude Code format, such as the one in the mergecat repository. In VS Code, add the repository to the setting chat.plugins.marketplaces (experimental), as owner/repo for a GitHub repository or as a Git URL, then install mergecat from it. The plugin starts the server with node: Node.js 20 or newer must be on the PATH.

Configuration without the plugin

Copilot in VS Code and Copilot CLI share the native configuration: ~/.copilot/mcp-config.json for you, or .mcp.json at the root of a workspace. Use the single file mergecat-mcp.cjs from the download section:

{
  "mcpServers": {
    "mergecat": {
      "type": "stdio",
      "command": "node",
      "args": ["/path/to/mergecat-mcp.cjs"],
      "env": { "GITHUB_TOKEN": "${GITHUB_TOKEN}" },
      "tools": ["*"]
    }
  }
}

Copilot Business and Enterprise

Organizations decide whether Copilot can use MCP servers: the policy is off by default for Copilot Business and Enterprise licenses. Ask an owner of the organization to allow it.

OpenAI Codex

The plugin

Codex reads plugin marketplaces in the Claude Code format too. Add the mergecat repository (or a local clone) as a marketplace:

codex plugin marketplace add CERTIFIE/mergecat

Then install mergecat from the plugins of the ChatGPT desktop app, and enable it for a project in .codex/config.toml:

[plugins."mergecat@mergecat"]
enabled = true

Configuration without the plugin

Add the server to ~/.codex/config.toml. env_vars passes the tokens from the environment Codex was started in, without writing them in the file:

[mcp_servers.mergecat]
command = "node"
args = ["/path/to/mergecat-mcp.cjs"]
env_vars = ["GITHUB_TOKEN", "GITLAB_TOKEN", "AZURE_DEVOPS_EXT_PAT"]

For the skills, copy the folders plugins/mergecat/skills/changelog and plugins/mergecat/skills/tags of the mergecat repository to ~/.agents/skills/ (for you) or to .agents/skills/ in a repository.

GitLab Duo

GitLab Duo Agentic Chat uses MCP servers in VS Code, in JetBrains IDEs and in the GitLab Duo CLI.

Allow external MCP tools

An Owner of the top-level group turns on Allow external MCP tools in the GitLab Duo settings of the group (on GitLab Self-Managed also the mcp_client feature flag, for flows and custom agents).

Add the server

Write ~/.gitlab/duo/mcp.json (Windows: %APPDATA%\GitLab\duo\mcp.json), or .gitlab/duo/mcp.json in a project:

{
  "mcpServers": {
    "mergecat": {
      "type": "stdio",
      "command": "node",
      "args": ["/path/to/mergecat-mcp.cjs"],
      "env": { "MERGECAT_AI_SERVICE": "gitlab-duo" },
      "approvedTools": ["compliance_status", "repository_info", "tags", "changelog", "changesets", "where_entered"]
    }
  }
}

approvedTools approves the read-only tools once; record_compliance_answer and render_pdf, which write files on your computer, still ask. Restart the IDE or the Duo CLI.

Add the skills

Copy the folders plugins/mergecat/skills/changelog and plugins/mergecat/skills/tags to .agents/skills/ in the project (or to the user skills folder of the GitLab Duo CLI). GitLab Duo loads them in new conversations.

For merge request titles, labels and linked issues, start the IDE or the CLI with GITLAB_TOKEN set (a token with the read_api scope).

Which repository

Outside Claude Code, the server finds the repository in this order: the repository parameter of the tool, MERGECAT_REPOSITORY, the folders open in the client (VS Code reports them to MCP servers; with several folders, the first Git repository), then the working directory of the server.

Pull request data

The tools add pull request (merge request) data when a token of the repository’s hosting service is in the environment of the server:

HostingVariables
GitHubGITHUB_TOKEN, or GH_TOKEN
GitLabGITLAB_TOKEN, or GL_TOKEN
Azure DevOpsAZURE_DEVOPS_EXT_PAT (personal access token), or AZURE_DEVOPS_TOKEN (Microsoft Entra token)

Without a token, the tools use local Git data only and say which variable to set. Never write a token in a configuration file that is shared or committed: reference it from the environment instead.
