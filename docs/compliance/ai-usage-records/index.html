Compliance and audit

AI usage records

The compliance question the mergecat Claude Code plugin asks before it sends repository data to Claude, and the audit records it keeps on your computer.

Edit on GitHub

Before the mergecat Claude Code plugin sends any data of your repository to Claude, it asks a compliance question and records the answer. This page lists the exact questions, when they are asked, every field of the record, where the records are stored and how to collect them for an audit.

Evidence of a declaration

A record documents what the user declared at the time of use: the account type and, if needed, the decision to proceed. mergecat does not verify the account type with the AI provider. For the legal context, see EU AI Act and NIS2.

When the question is asked

  • Only in AI assistants, through the mergecat MCP server: Claude Code, and GitHub Copilot, OpenAI Codex or GitLab Duo. The desktop app, the VS Code extension and the command line never send data to an AI service, so they never ask.
  • Once per session. Claude Code (like the other assistants) starts one mergecat MCP server process per session, and the answer lives in the memory of that process. A new session asks again.
  • Before the first repository data is read. The skills /mergecat:tags and /mergecat:changelog call compliance_status first. If Claude calls a repository tool before the question is answered, the tool refuses to run and returns the questions instead.
  • Again after a “no”. When you chose not to proceed, the repository tools stay locked for the session. If you later ask for mergecat data in the same session, Claude asks again and a new record is written.

The questions

Claude asks the questions translated into the language of the conversation, as yes/no questions, and waits for your answer: the skills and the server’s instructions tell Claude never to answer for you. The record stores the English text below, the language the questions were asked in and your answers as you wrote them.

  1. Always asked:

    Are you using a Claude Team or Enterprise account? mergecat is about to send data of this Git repository to Claude (commit messages, authors, dates, branch and tag names, and pull request data when available). Your answer is recorded for EU AI Act and NIS2 compliance. Please answer yes or no.

  2. Asked only when the first answer is no:

    You are not using a Claude Team or Enterprise account. Are you aware of the EU AI Act and the NIS2 directive, and do you want to proceed anyway? Please answer yes or no.

These are the questions in Claude Code. With another assistant they name its service and its business plans, for example “Are you using a GitHub Copilot Business or Enterprise license? mergecat is about to send data of this Git repository to GitHub Copilot …” (see Other AI assistants); the record stores the questions as asked, and its AI service field names the service and the client application.

Outcomes

AnswersOutcomeRepository toolsCopy in the conversation
1: yesproceedunlocked for the sessionfull record
1: no, 2: yesproceedunlocked for the sessionfull record
1: no, 2: nostoppedstay locked; no repository data is sent to Clauderedacted record (see below)

The tools that enforce it

Two MCP tools handle the question. Neither reads the history of the repository. The full reference is on MCP server and tools.

compliance_status

No parameters. Returns whether the session is confirmed and what to ask.

FieldMeaning
confirmedtrue once an answer with outcome proceed was recorded in this session
askedThisSessiontrue if any answer was recorded in this session
lastOutcomeproceed, stopped or null
lastRecordedAtDate and time of the last record, or null
lastRecordFilePath of the last Markdown record, or null
questions.accountThe first question
questions.proceedIfNotTeamOrEnterpriseThe second question
recordsFolderThe folder where records are written

record_compliance_answer

Writes the record and, on outcome proceed, unlocks the repository tools for the session.

ParameterTypeRequiredDescription
team_or_enterprise_accountbooleanyesAnswer to the first question
aware_and_proceedbooleanwhen the first answer is falseAnswer to the second question; the call fails without it when the first answer is false
requested_actionstringyesWhat you asked mergecat for, e.g. changelog v1.2.0..v1.3.0 (up to 500 characters are kept)
answers_verbatimstringnoYour answers as you wrote them, or the options you chose (up to 2,000 characters are kept)
languagestringnoLanguage of the questions, ISO 639-1 (e.g. it)
ai_modelstringnoThe Claude model that asked
repositorystringnoPath of the repository; default: the Claude Code project

It returns the outcome, the record ID, the paths of the Markdown record and of the log, and the record as Markdown for the conversation.

Where records are stored

Records are written on the computer that runs Claude Code, in the mergecat data folder of the user:

~/Library/Application Support/mergecat/compliance/
%APPDATA%\mergecat\compliance\
$XDG_DATA_HOME/mergecat/compliance/

Without XDG_DATA_HOME: ~/.local/share/mergecat/compliance/.

Each Markdown record is named after the time, the repository and the outcome, for example 2026-03-31T09-14-22-418Z-web-shop-proceed.md (no-repository when the folder is not a Git repository). On macOS and Linux the files are created readable and writable by your user only.

Use another folder

Set MERGECAT_COMPLIANCE_DIR to an absolute folder before you start Claude Code; the plugin passes it to the MCP server. mergecat creates the folder if it does not exist.

export MERGECAT_COMPLIANCE_DIR="$HOME/Compliance/mergecat"
claude

Add the export line to ~/.zshrc to keep it.

setx MERGECAT_COMPLIANCE_DIR "D:\Compliance\mergecat"

setx applies to terminals opened afterwards: open a new terminal, then start claude.

export MERGECAT_COMPLIANCE_DIR="$HOME/compliance/mergecat"
claude

Add the export line to your shell profile (for example ~/.bashrc) to keep it.

Central collection

If your organisation collects the records centrally, point MERGECAT_COMPLIANCE_DIR at a backed-up or synchronised folder, one folder per user. The records contain names, e-mail addresses, computer names and repository paths: make sure only authorised people can read that folder.

The copy in the conversation

record_compliance_answer also returns the record as Markdown, and Claude gives it to you as a document of the conversation: a Markdown artifact, a file sent in the chat named compliance-record-<repository>-<YYYY-MM-DD>.md, or a Markdown block in the reply. It is never written into your project. Claude also tells you in one line where the record is stored on your computer.

When the outcome is stopped, you did not agree to send data to Claude, so the copy in the conversation leaves out these rows: User (operating system), User (Git configuration), Computer, Repository, Repository folder and Repository remote. A note says that these details are only in the copy stored on your computer. The stored record is always complete.

Collect the records for an audit

Find the folder

Use the folder for your operating system shown above, or the value of MERGECAT_COMPLIANCE_DIR. compliance_status also returns it as recordsFolder.

Copy or archive it

The folder contains one Markdown file per decision and the log compliance-log.jsonl. Copy the whole folder, or archive it:

cd ~/Library/Application\ Support/mergecat
zip -r ~/Desktop/mergecat-compliance.zip compliance
Compress-Archive -Path "$env:APPDATA\mergecat\compliance" -DestinationPath "$HOME\Desktop\mergecat-compliance.zip"
tar -czf ~/mergecat-compliance.tar.gz -C "${XDG_DATA_HOME:-$HOME/.local/share}/mergecat" compliance

Query the log

One JSON line per decision makes the log easy to summarise.

cd ~/Library/Application\ Support/mergecat/compliance   # Linux: ~/.local/share/mergecat/compliance

# Decisions per outcome
jq -s 'group_by(.outcome) | map({outcome: .[0].outcome, count: length})' compliance-log.jsonl

# Every "stopped" decision
jq -c 'select(.outcome == "stopped") | {recordedAt, requestedAction, user: .user.osUser, host}' compliance-log.jsonl

# Decisions in the first quarter of 2026
jq -c 'select(.recordedAt >= "2026-01-01" and .recordedAt < "2026-04-01")' compliance-log.jsonl

# CSV for a spreadsheet
jq -rs '(["recordedAt","outcome","teamOrEnterprise","awareAndProceed","requestedAction","osUser","computer","repository","aiModel"] | @csv),
  (.[] | [.recordedAt, .outcome, .teamOrEnterpriseAccount, .awareAndProceed, .requestedAction, .user.osUser, .host, .repository.name, .aiModel] | @csv)' \
  compliance-log.jsonl > compliance-log.csv
$log = "$env:APPDATA\mergecat\compliance\compliance-log.jsonl"
$records = Get-Content -Path $log -Encoding UTF8 | ForEach-Object { $_ | ConvertFrom-Json }

# Decisions per outcome
$records | Group-Object outcome | Select-Object Name, Count

# Every "stopped" decision
$records | Where-Object { $_.outcome -eq 'stopped' } | Select-Object recordedAt, requestedAction, host

# CSV for a spreadsheet
$records | Select-Object recordedAt, outcome, teamOrEnterpriseAccount, awareAndProceed, requestedAction,
    @{ Name = 'osUser'; Expression = { $_.user.osUser } }, host,
    @{ Name = 'repository'; Expression = { $_.repository.name } }, aiModel |
  Export-Csv -Path compliance-log.csv -NoTypeInformation -Encoding UTF8

Hand over the evidence

Give the auditor the log (or the CSV) for the overview and the Markdown records for individual decisions. The Markdown files are readable as they are and can be printed or converted to PDF.

Retention

mergecat never deletes records; how long you keep them is up to your organisation. Some suggestions:

  • Keep the records at least as long as your AI policy, your audit cycle or your other security logs require. As a reference point, the AI Act asks deployers of high-risk AI systems to keep the logs of those systems for at least six months.
  • The records contain personal data (names, e-mail addresses, computer names). Under the GDPR, keep them no longer than you need them, and restrict who can read them.
  • Archive the folder together with the release documentation or the audit evidence of the period, and delete local copies according to your retention schedule.
