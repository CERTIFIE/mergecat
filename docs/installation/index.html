Getting started

Installation

Install the mergecat desktop app on macOS, Windows or Linux, and set up the VS Code extension, the Claude Code plugin or a build from source.

Edit on GitHub

The desktop app is a single download per operating system. It needs Git and nothing else: no account, no server, no runtime to install. The VS Code extension and the Claude Code plugin are installed separately and do not need the desktop app.

Installing on another system?

The instructions on this page are tabbed by operating system. The docs select your system first, but you can pick another tab: every tab group follows the same choice and remembers it, so you can read on a Mac and follow the Windows steps.

Requirements

RequirementDetails
Operating systemmacOS on Apple silicon or Intel, Windows on x64 or ARM64, Linux on x86_64 or ARM64: AppImage for any distribution, .deb for Debian and Ubuntu, .rpm for Fedora, RHEL and openSUSE. ChromeOS is not supported.
GitOn PATH, or its path set in Settings › Git executable. Git 2.38 or later for the conflict check of the Branches page.
A local clonemergecat reads the history from the clone on your disk. A shallow clone works but shows a warning.

Install Git

Skip this step if git --version already prints a version in a terminal.

Install the Xcode Command Line Tools, which include Git:

xcode-select --install

Or install Git with Homebrew:

brew install git

mergecat looks for Git on PATH and in /opt/homebrew/bin, /usr/local/bin and /usr/bin.

Install Git for Windows, or use winget in a terminal:

winget install --id Git.Git -e

mergecat looks for Git on PATH, in Git\cmd under the Program Files folders and in %LOCALAPPDATA%\Programs\Git\cmd.

Install Git with the package manager of your distribution:

# Debian, Ubuntu
sudo apt install git

# Fedora
sudo dnf install git

# Arch Linux
sudo pacman -S git

mergecat looks for Git on PATH and in /usr/bin and /usr/local/bin.

If Git is installed somewhere else, start mergecat anyway: the welcome screen says that Git was not found and Open settings lets you enter the path of the git executable.

Download and install

Choose Apple silicon for Macs with an M1 chip or later, Intel for older Macs.

macOS (Apple silicon) mergecat-mac-arm64.dmg macOS (Intel) mergecat-mac-x64.dmg All releases →
  1. Open the downloaded .dmg file.
  2. Drag mergecat to the Applications folder.
  3. Eject the disk image.

Choose x64 for PCs with an Intel or AMD processor, ARM64 for PCs with an ARM processor such as Snapdragon. Settings › System › About shows it under System type.

Windows (x64) mergecat-windows-x64-setup.exe Windows (ARM64) mergecat-windows-arm64-setup.exe All releases →
  1. Run mergecat-windows-x64-setup.exe (or mergecat-windows-arm64-setup.exe).
  2. Follow the installer. You can change the installation folder.

Choose the packages of your processor: x86_64 (amd64) for Intel and AMD, ARM64 (aarch64) for ARM computers; uname -m prints it. The AppImage runs on most distributions without installation. The .deb package installs mergecat system-wide on Debian and Ubuntu, the .rpm package on Fedora, RHEL and openSUSE.

Linux (AppImage) mergecat-linux-x86_64.AppImage Linux (.deb) mergecat-linux-amd64.deb Linux (.rpm) mergecat-linux-x86_64.rpm Linux ARM64 (AppImage) mergecat-linux-aarch64.AppImage Linux ARM64 (.deb) mergecat-linux-arm64.deb Linux ARM64 (.rpm) mergecat-linux-aarch64.rpm All releases →

The commands below use the x86_64 files; on ARM64 the names end in aarch64 (AppImage, .rpm) or arm64 (.deb).

AppImage: make the file executable, then run it.

chmod +x mergecat-linux-x86_64.AppImage
./mergecat-linux-x86_64.AppImage

Debian or Ubuntu package:

sudo apt install ./mergecat-linux-amd64.deb

Fedora, RHEL or openSUSE package (the packages are not signed yet, see First launch):

# Fedora, RHEL
sudo dnf install ./mergecat-linux-x86_64.rpm

# openSUSE
sudo zypper install --allow-unsigned-rpm ./mergecat-linux-x86_64.rpm

First launch

The builds are not code-signed yet

Code signing and notarisation are not configured yet, so your system warns that it cannot verify the developer the first time you open mergecat. Allow it once as shown below; later launches start normally.

  1. Open mergecat from the Applications folder. macOS refuses to open it and shows a warning.
  2. Open System Settings › Privacy & Security and scroll down to Security.
  3. Click Open Anyway next to the message about mergecat, then confirm with Open (and your password if asked).

On macOS 14 and earlier you can instead Control-click the app in Finder, choose Open, then click Open again.

If macOS says that mergecat “is damaged and can’t be opened”, remove the quarantine flag that the browser added to the download, then open the app again:

xattr -dr com.apple.quarantine /Applications/mergecat.app
  1. Run the installer or mergecat. Microsoft Defender SmartScreen shows Windows protected your PC.
  2. Click More info, then Run anyway.

There is no signature prompt on Linux. The AppImage only needs the executable permission set above.

If the AppImage does not start and reports a FUSE error, install the FUSE 2 package of your distribution or use the .deb or .rpm package instead.

mergecat opens on the welcome screen. Its footer shows the Git version that mergecat found and the app version. Click Open a repository… and continue with the Quick start.

The welcome screen: open a repository, or pick a recent one.

Where mergecat keeps its data

mergecat writes nothing into your repositories. Its settings, credentials and caches live in the app’s data folder:

~/Library/Application Support/mergecat
%APPDATA%\mergecat
~/.config/mergecat
ItemWhat it contains
settings.jsonPreferences of this computer: Git executable, sign-in client IDs, Microsoft tenant, entries per page, recent repositories. No secrets.
credentials.binYour connections to GitHub, GitLab and Azure DevOps, encrypted with the system keychain. Removed when you disconnect every service.
pull-request-cachePull request data cached per commit SHA, so it stays valid across fetches.

The theme and the List or Graph choice are window preferences, stored in the same folder.

How credentials are protected

Tokens are encrypted with the operating system keychain through Electron safeStorage: Keychain on macOS, DPAPI on Windows, libsecret or KWallet on Linux. Without a keychain (for example Linux without GNOME Keyring or KWallet) they are kept in memory only and never written in clear text: you connect again after restarting the app. See Local only vs connected.

The environment variable MERGECAT_USER_DATA_DIR makes the app use another folder, for example to run a test profile next to your own. All variables are listed in Configuration.

Update

The app does not update itself yet. Download the new version and install it over the old one, as above. Your settings and connections are kept, because they live in the data folder, not next to the app.

Uninstall

  1. Quit mergecat.
  2. Drag mergecat from the Applications folder to the Trash.
  3. To remove settings, connections and caches too, delete the data folder:
rm -rf ~/Library/Application\ Support/mergecat
  1. Open Settings › Apps › Installed apps (Apps & features on Windows 10).
  2. Find mergecat, open its menu and choose Uninstall.
  3. To remove settings, connections and caches too, delete the data folder in PowerShell:
Remove-Item -Recurse -Force "$env:APPDATA\mergecat"

AppImage: delete the .AppImage file.

Debian or Ubuntu package:

sudo apt remove mergecat

Fedora, RHEL or openSUSE package:

# Fedora, RHEL
sudo dnf remove mergecat

# openSUSE
sudo zypper remove mergecat

To remove settings, connections and caches too, delete the data folder:

rm -rf ~/.config/mergecat

Uninstalling does not revoke access at the hosting service. Revoke personal access tokens or OAuth authorisations there if you no longer need them.

VS Code extension

The extension brings the Changesets view, the repository pages and native diffs into VS Code. It signs in with your VS Code GitHub and Microsoft accounts, so GitHub and Azure DevOps need no setup.

Download mergecat-vscode.vsix from the downloads, then run Extensions: Install from VSIX… from the Command Palette, or install it from a terminal:

code --install-extension mergecat-vscode.vsix

Open a folder with a Git repository and click the mergecat icon in the activity bar. Everything else is in VS Code extension.

Claude Code plugin

The plugin gives Claude Code the changesets, the tags and Keep a Changelog drafts of a repository through a read-only MCP server, with the skills /mergecat:tags and /mergecat:changelog. Add the marketplace, then install the plugin:

claude plugin marketplace add CERTIFIE/mergecat
claude plugin install mergecat@mergecat

Start Claude Code in any Git repository and run /mergecat:tags or /mergecat:changelog. Once per session the plugin asks whether you use a Claude Team or Enterprise account and keeps the answer as an AI usage record. Details: Claude Code plugin.

Build from source

You need Node.js 20 or newer and Git. Clone the repository:

git clone https://github.com/CERTIFIE/mergecat.git

Then, in the cloned folder, install the dependencies and start the desktop app in development mode (with hot reload):

npm install
npm run desktop

Other useful commands:

CommandWhat it does
npm run fixturesCreates sample repositories in .fixtures/. Open .fixtures/demo from the welcome screen.
npm start -w @mergecat/desktopBuilds the desktop app and runs it without hot reload.
npm run dist -w @mergecat/desktopPackages the app for this computer with electron-builder, unsigned: dmg on macOS, NSIS installer on Windows, AppImage, deb and rpm on Linux.
npm run vscode:installBuilds, packages and installs the VS Code extension into your VS Code.
npm run mcp:buildBuilds the MCP server used by the Claude Code plugin.

Dependencies are installed from the public npm registry (the repository’s .npmrc sets it), regardless of a company registry in your global ~/.npmrc.
