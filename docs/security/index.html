Compliance and audit

Security and privacy

What mergecat changes in your repository, which data leaves your computer and where, how credentials are stored, and what mergecat keeps locally.

Edit on GitHub

mergecat is a local tool: it reads your repositories with your own Git, talks only to the hosting services you connect and has no server of its own. This page lists what it can change, which data leaves your computer, how it stores credentials and what it keeps on disk.

At a glance

TopicHow mergecat handles it
RepositoryRead-only by default; writes only on explicit commands
NetworkOnly the hosting services you connect (GitHub, GitLab, Azure DevOps) and their sign-in pages; Claude only through the Claude Code plugin, after the compliance answer
CredentialsEncrypted with the operating system keychain; memory only when no keychain is available
TelemetryNone: no usage statistics, no crash reports, no update checks, no mergecat server
Local dataSettings, encrypted credentials and a pull request cache in the app data folder; never in the repository

Read-only by default

mergecat reads the history with git log, git blame and similar commands. It never commits, checks out, merges, rebases or rewrites anything, and it never touches your working tree or your local branches. Only these actions change something, and only when you start them:

ActionWhat it changesWhere
FetchRuns git fetch --all --tags --prune: updates remote-tracking branches and tags, removes the ones deleted on the remote. Local branches and files are not touched.Desktop app (Branches page), VS Code (Branches page, Fetch All Remotes)
Create tagCreates a local tag at the commit you choose; annotated when you enter a messageDesktop app, VS Code (Tags page, Create Tag…, Create Tag Here…)
Push tagPushes that one tag to the remoteDesktop app, VS Code (Tags page)
Create pull requestCreates a pull request (GitLab: merge request) on the hosting serviceDesktop app, VS Code (Pull requests page, Create Pull Request…)

Exports and audit reports are written only where you save them. The Claude Code plugin’s MCP server never changes the repository: it writes only the AI usage records and, on request, PDF files outside the project. Claude updates CHANGELOG.md only when you explicitly ask for it.

How mergecat runs Git:

  • your own git executable, started directly, never through a shell;
  • with GIT_TERMINAL_PROMPT=0: fetch and tag push use your credential helper or SSH key and never prompt for a password;
  • with GIT_OPTIONAL_LOCKS=0, so that reading does not take Git’s optional locks.

Data that leaves your computer

DestinationWhenWhat
Your Git remotesFetch and tag pushWhatever Git exchanges, with your Git credentials
Hosting service APIs: GitHub, GitLab, Azure DevOpsOnly when the service is connectedRequests for pull requests, approvals, linked issues, pipelines and deployments of the repository; the pull requests you create
Sign-in pages: github.com, login.microsoftonline.com, your GitLab instanceWhen you sign in with the browserThe device-flow sign-in; your organisation’s SSO and MFA apply there
Claude (Anthropic), or the AI assistant you run the mergecat MCP server in (GitHub Copilot, OpenAI Codex, GitLab Duo)Only through the mergecat MCP server, after the compliance question allowed itHistory metadata: commit messages, author and committer names and e-mail addresses, dates, branch and tag names, commit SHAs; with a token of the hosting service, pull request titles, numbers, labels and linked issues

Nothing else. mergecat has no telemetry: it collects no usage statistics and sends no crash reports. It does not check for updates and has no mergecat server or account. The desktop app bundles its fonts and loads nothing from a CDN.

The mergecat MCP tools give Claude history metadata, not the content of your files or diffs. Claude Code itself can read files of your project under its own permissions; for example, the changelog skill reads CHANGELOG.md.

AI usage is recorded

Before the first repository data of a Claude Code session is sent, mergecat asks whether you use a Claude Team or Enterprise account and records the answer. See EU AI Act and NIS2.

Credentials

Desktop app

Tokens are encrypted with the operating system’s keychain (Electron safeStorage) and stored in credentials.bin in the app data folder.

The encryption key is kept in the macOS Keychain.

The data is encrypted with Windows DPAPI for your user account.

The encryption key is kept by a secret service: GNOME Keyring (libsecret) or KWallet. Without one, mergecat keeps the credentials in memory only and shows a warning: you need to connect again after restarting the app. See Troubleshooting.

  • When no keychain is available, credentials are kept in memory only, never written in clear text.
  • GitHub CLI sign-in stores no token: mergecat runs gh auth token when it needs one.
  • Sign-in tokens of the browser flows are refreshed before they expire.
  • Disconnect in the Connections dialog deletes the stored credential of that service.

VS Code extension

  • GitHub and Azure DevOps (Sign in with Microsoft) use the accounts VS Code already manages. The token stays in VS Code; mergecat asks VS Code for it when needed.
  • Personal access tokens and GitLab sign-in tokens are stored in VS Code’s SecretStorage (backed by the operating system keychain), one per service and host. They are never written to settings or logs.

Claude Code plugin and command line

  • The MCP server reads GITHUB_TOKEN (or GH_TOKEN) from its environment, for pull request data of github.com repositories. It does not store it.
  • The command line uses no hosting service and no credentials besides your Git setup.

Least privilege

Give tokens only the scopes mergecat needs. Reading needs read scopes; only creating pull requests needs write access (for example GitLab read_api is enough to read, api is needed to create merge requests). The scopes per service are listed in Connections.

Local data and caches

WhatWhereContent
Settings (desktop)settings.json in the app data folderGit path, sign-in client IDs, Microsoft tenant, page size, the last 10 repositories
Credentials (desktop)credentials.bin in the app data folderEncrypted tokens
Pull request cache (desktop)pull-request-cache/ in the app data folder, one file per repositoryPull request data per commit SHA. Merged pull requests are kept; “no pull request” answers are checked again after 6 hours and open pull requests after 1 hour
Pull request cache (VS Code)The extension’s global storage folder of VS CodeThe same data, per commit SHA
AI usage recordsThe mergecat compliance folderSee AI usage records
PDFs from Claude CodeClaude’s scratchpad, or the mergecat folder in the system temporary folderOnly when you ask for a PDF

mergecat never writes caches or settings into your repository.

The app data folder of the desktop app:

~/Library/Application Support/mergecat/
%APPDATA%\mergecat\
~/.config/mergecat/

Or $XDG_CONFIG_HOME/mergecat/ when XDG_CONFIG_HOME is set.

To remove everything, disconnect the services, quit the app and delete this folder. On macOS and Windows the compliance records are in its compliance subfolder: keep them if you need them for audits.

Desktop app hardening

  • The window content runs in a sandboxed renderer with context isolation and no Node.js access; it talks to the main process through a narrow interface.
  • The window never navigates away from the app. Links open in your default browser, and only https:// links are opened.
  • Only one instance of the app runs at a time.

Unsigned builds

Code signing and notarisation are not configured yet, so macOS and Windows warn when you open mergecat for the first time (how to open it). Before you confirm:

  • download mergecat only from the project’s releases page or the download section;
  • compare the SHA-256 checksum of the file with the one published in the release (SHA256SUMS.txt, also listed in the release notes):
shasum -a 256 ~/Downloads/mergecat-mac-arm64.dmg
Get-FileHash "$HOME\Downloads\mergecat-windows-x64-setup.exe" -Algorithm SHA256
sha256sum ~/Downloads/mergecat-linux-x86_64.AppImage
  • if your policy does not allow unsigned software, build mergecat from source (see Installation) or wait for signed releases.
