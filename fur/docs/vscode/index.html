Integrazions

Estension par VS Code

Instale la estension di mergecat par VS Code e dopre lis sôs viodudis, lis pagjinis dal repository, i comants e lis impostazions.

Modifiche su GitHub

Tradusude dal inglês cul jutori de IA. In câs di dubi e vâl la version in inglês.

La estension di mergecat e puarte in VS Code la viodude dai changeset: la storie di un branch metude in grups par integrazion, lis pagjinis dal repository (branch, tag, pull request, pipeline, deployment) come schedis dal editôr, il changeset blame, lis metrichis e il rapuart di audit des modifichis. E jentre cui account GitHub e Microsoft che VS Code al cognòs za.

Recuisîts: VS Code 1.90 o plui gnûf e Git. Il control dai conflits de pagjine Branches al à bisugne di Git 2.38 o plui gnûf.

Instalazion

No ancjemò sul Marketplace

La estension no je ancjemò publicade sul Visual Studio Marketplace. Instalile dal file .vsix di une release, o compilile dal codiç sorzint.

Discjarie mergecat-vscode.vsix de sezion Discjarie, po instalile intun di chescj doi mûts.

Rie di comant:

code --install-extension mergecat-vscode.vsix

VS Code: vierç la viodude Extensions, fâs clic sul menù … in alt te viodude, sielç Install from VSIX… e selezione il file.

De lidrîs di un clon dal repository di mergecat (Node.js 20 o plui gnûf):

npm install
npm run vscode:install

Il script al compile e al impachete la estension e le instale in VS Code; al cjate il comant code ancje cuant che nol è tal PATH. Tornilu a eseguî dopo des modifichis. Par gjavâ la estension:

npm run vscode:install -- --uninstall

Po eseguìs Developer: Reload Window, vierç une cartele che e conten un repository Git e fâs clic su la icone mergecat te sbare des ativitâts.

Une altre estension cuntun non simil

“MergeCat for VS Code” (mergecat.mergecat-vscode) sul Marketplace e je une estension che no à nuie a ce fâ cun mergecat e che e regjistre i stes nons di comants e di impostazions. No sta instalâlis dutis dôs. Se e je instalade, gjavile:

code --uninstall-extension mergecat.mergecat-vscode

Viodudis

La icone di mergecat te sbare des ativitâts e vierç trê viodudis.

Cuâl repository? Se la cartele vierte e je dentri di un repository Git, al ven mostrât chel repository. Se no mergecat al cîr tes sôs sotcartelis (doi nivei par impostazion predefinide, mergecat.repositoryScanDepth). Cuntun sôl repository lu vierç; cun plui di un al mostre l’ultin doprât o chel dal file tal editôr, o ti domande di sielzi (ancje dal boton dal repository te sbare dal titul).

Changesets

La storie in grups dal branch selezionât, in dôs disposizions. Passe di une a chê altre cun List | Graph te intestazion, o cun Show Commit Graph / Show Changesets List.

  • List: i commit direts come riis singulis, lis integrazions (merge e, cuant che si è conetûts, pull request integradis cun rebase merge) come grups di slargjâ. La seconde rie di ogni element e mostre il SHA curt, l’autôr, la date, il risi e i ambients che a contegnin za la modifiche. Fâs clic suntun commit par vierzi lis sôs modifichis; dopre il boton dal diff de rie o il menù contestuâl par vierzi lis modifichis combinadis di un grup.
  • Graph: ogni commit cu lis sôs liniis; la etichete su la seconde rie e dîs cuâl changeset che al à puartât il commit tal branch.

La intestazion e mostre il repository e il branch (fâs clic par cambiâ), la casele di ricercje, i filtris atîfs come etichetis che si puedin gjavâ, i avertiments, il numar di elements e il stât de conession. Fâs clic cul boton diestri suntune rie pes sôs azions: vierç lis modifichis, dulà che al è jentrât, vierç la pull request, copie il SHA. Tastiere: ↑ ↓ par movisi, ← → par strenzi e slargjâ, Enter par vierzi.

Ambients (Environments)

Ce che al è distribuît e dulà, e cualis integrazions dal branch che no son ancjemò distribuidis li. Fâs clic suntun element par mostrâlu; la azion te rie e fâs passâ la viodude Changesets a “ce che nol è ancjemò in chest ambient”.

Un ambient al è un branch che al ponte al codiç distribuît (par esempli origin/production) o un model di tag che il so tag plui gnûf al è la version distribuide (par esempli prod-*). Cence configurazion, a vegnin rilevâts i branch clamâts production, staging, test o develop e i tag di release; cuntune conession, si zontin i ultins deployment lâts ben dal servizi di hosting. Configuriju cun mergecat.environments.definitions:

"mergecat.environments.definitions": [
  { "name": "Production", "tagPattern": "prod-*" },
  { "name": "Staging", "ref": "origin/staging" }
]

Conessions (Connections)

I conetôrs di hosting (GitHub, GitLab, Azure DevOps; Bitbucket ca di pôc), cemût che al è stât fat l’acès a ognidun e ce che si zonte conetintsi. Il remote dal repository al decît cuâl conetôr che al ven doprât.

Pagjinis dal repository

Cinc pagjinis si vierzin come schedis dal editôr: dai botons sot de intestazion di Changesets (Branches · Tags · PRs · Pipelines · Deploys), dal menù … de viodude, o cui comants mergecat: Open ….

PagjineCe che e mostreConession
BranchesOgni branch locâl e i branch remots cence copie locâl: commit in jentrade e in jessude, not on origin, upstream deleted, indenant/indaûr rispiet ae base, merged, conflits cu la base (cu la liste dai file), etât. Fetch al eseguìs git fetch --all --prune --tags.Locâl
TagsNon, commit, date, autôr dal tag, messaç, anotât o lizêr, version, su origin o local only cuntun boton Push. New tag al controle il non intant che tu scrivis e al pues fâ il push dal tag.Locâl
Pull RequestsViertis, sieradis o dutis, cun stât, revisôrs e vôts, controi; detais cui commit e lis issue colegadis. New pull request al compile za titul e descrizion partint dai commit.Conetût
PipelinesGitHub Actions, GitLab CI/CD e Azure Pipelines: Activity (stage, job, step, dipendencis), Text (il YAML) e Runs (stât e durade di ogni job).Conetût
DeploymentsIl deployment atîf di ogni ambient e chei precedents cui lôr tag; Compare environments cun notis di release e il rapuart di audit; ce che al à puartât ogni deployment.Conetût

Cence une conession, la pagjine Deployments e mostre i ambients cjatâts in locâl (impostazions, nons di branch e di tag) e ju confronte te stesse maniere.

Analisis

  • Changeset blame: mergecat: Toggle Changeset Blame (ancje te sbare dal titul dal editôr) al anote la rie sot dal cursôr cu la integrazion che le à puartade tal branch analizât: pull request o branch integrât, titul, date e i ambients dulà che e je rivade. Passant parsore si zontin il commit, l’integradôr, lis aprovazions e lis issue colegadis (cun conession), il prin tag di release e il risi.
  • Changesets That Shaped This File al liste lis integrazions che a àn scrit il file atuâl, cu la part plui grande prime.
  • Risi par integrazion: un puntezi calcolât su la dimension, tancj file, areis sensibilis, codiç cambiât cence test, commit direts e merge locâi cence pull request, merge cence aprovazion (cun conession) e revert. Filtre cun Filter… › Risk…. I fatôrs a son listâts in Rapuarts di audit des modifichis.
  • Metrichis: mergecat: Show Metrics al mostre lis modifichis jentradis, la part passade par pull request, il lead time, la dimension des modifichis, i revert, i autôrs, la ativitât par setemane o par mês, la distribuzion dal risi e i contributôrs principâi. Cuntune conession a GitHub al zonte il timp fin al merge.

Rapuart di audit

Eseguìs mergecat: Export Audit Report… (de Command Palette o dal menù … de viodude Changesets) e sielç l’ambit: la viodude atuâl, Between two releases…, Between two environments… o Not yet in un ambient. Sielç HTML, Markdown, CSV o JSON e dulà salvâlu. La pagjine Deployments e propon il stes rapuart pes modifichis di Compare environments.

Lis aprovazions a vegnin dal servizi di hosting: cence une conession il comant al avise che a saran indicadis come “unknown” e al propon di conetisi. Detais: Rapuarts di audit des modifichis.
