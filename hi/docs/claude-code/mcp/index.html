MCP सर्वर और टूल

mergecat MCP सर्वर का रेफ़रेंस: हर टूल और उसके पैरामीटर, कंप्लायंस लॉक, एनवायरनमेंट वेरिएबल, और प्लगइन के बिना सर्वर का उपयोग कैसे करें।

GitHub पर एडिट करें

AI की मदद से अंग्रेज़ी से अनूदित। संदेह होने पर अंग्रेज़ी संस्करण मान्य है।

mergecat MCP सर्वर किसी AI असिस्टेंट को किसी ब्रांच के चेंजसेट, उसके टैग और रिलीज़, और Keep a Changelog ड्राफ़्ट देता है। यह stdio के ज़रिए लोकल रूप से चलता है, आपके Git से रिपॉज़िटरी पढ़ता है और उसे कभी नहीं बदलता। Claude Code प्लगइन इसे स्किल के साथ इंस्टॉल करता है; आप इसे अलग से भी जोड़ सकते हैं, और GitHub Copilot, OpenAI Codex और GitLab Duo के साथ इसका उपयोग कर सकते हैं।

टूल के नाम

किस रूप में इंस्टॉलClaude Code में टूल के नाम
प्लगइनmcp__plugin_mergecat_mergecat__<tool>
mergecat नाम का स्टैंडअलोन सर्वरmcp__mergecat__<tool>

कंप्लायंस लॉक

रिपॉज़िटरी टूल (repository_info, tags, changelog, changesets, where_entered) तब तक लॉक रहते हैं जब तक सेशन के कंप्लायंस सवाल का जवाब proceed नतीजे के साथ नहीं दे दिया जाता। लॉक रहते हुए वे एक त्रुटि लौटाते हैं, जिसमें पूछे जाने वाले सवाल और record_compliance_answer को कॉल करने का निर्देश होता है; वे कुछ भी नहीं पढ़ते।

compliance_status, record_compliance_answer और render_pdf लॉक नहीं होते: वे रिपॉज़िटरी का इतिहास नहीं पढ़ते।

हर सेशन में एक जवाब

जवाब सर्वर प्रोसेस की मेमोरी में रखा जाता है। Claude Code, दूसरे क्लाइंट की तरह, हर सेशन के लिए एक प्रोसेस शुरू करता है, इसलिए हर नया सेशन दोबारा पूछता है, और हर जवाब एक ऑडिट रिकॉर्ड के रूप में लिखा जाता है। सवाल में क्लाइंट की AI सेवा का नाम होता है: Claude Code में Claude Team या Enterprise अकाउंट, Copilot में GitHub Copilot Business या Enterprise लाइसेंस, इत्यादि (देखें हर असिस्टेंट का सवाल)। देखें AI उपयोग रिकॉर्ड।

कौन-सी रिपॉज़िटरी

हर रिपॉज़िटरी टूल एक वैकल्पिक repository पैरामीटर लेता है: किसी Git रिपॉज़िटरी का पाथ (उसके अंदर का कोई भी फ़ोल्डर)। इसके बिना सर्वर इस क्रम में उपयोग करता है:

  1. MERGECAT_REPOSITORY;
  2. CLAUDE_PROJECT_DIR (Claude Code प्रोजेक्ट);
  3. क्लाइंट में खुले फ़ोल्डर, जब क्लाइंट उन्हें MCP सर्वर को बताता है (VS Code बताता है): उनमें से पहला फ़ोल्डर जो Git रिपॉज़िटरी है;
  4. सर्वर की वर्तमान डायरेक्टरी।

टूल

compliance_status

क्या इस सेशन में कंप्लायंस सवाल का जवाब दिया गया है, और पूछे जाने वाले सटीक सवाल। कोई पैरामीटर नहीं। रिपॉज़िटरी नहीं पढ़ता।

aiService (वह AI सेवा जिसके बारे में सवाल हैं), confirmed, askedThisSession, lastOutcome, lastRecordedAt, lastRecordFile, questions.account, questions.proceedIfNotTeamOrEnterprise और recordsFolder लौटाता है। फ़ील्ड का विवरण: AI उपयोग रिकॉर्ड।

record_compliance_answer

उपयोगकर्ता ने बातचीत में जो जवाब दिए, उन्हें इस कंप्यूटर पर एक ऑडिट रिकॉर्ड (Markdown दस्तावेज़ और JSON Lines लॉग) के रूप में रिकॉर्ड करता है, और नतीजा proceed होने पर सेशन के लिए रिपॉज़िटरी टूल अनलॉक करता है।

पैरामीटरप्रकारज़रूरीविवरण
team_or_enterprise_accountbooleanहाँtrue अगर उपयोगकर्ता पहले सवाल में बताया गया बिज़नेस या एंटरप्राइज़ प्लान इस्तेमाल करता है (Claude Code में: Claude Team या Enterprise अकाउंट)
aware_and_proceedbooleanजब पहला जवाब false होtrue अगर उपयोगकर्ता EU AI Act और NIS2 के बारे में जानता है और फिर भी आगे बढ़ना चाहता है
requested_actionstringहाँउपयोगकर्ता ने क्या माँगा, जैसे changelog v1.2.0..v1.3.0 या tags
answers_verbatimstringनहींउपयोगकर्ता के जवाब जैसे लिखे गए, या चुने गए विकल्प
languagestringनहींवह भाषा जिसमें सवाल पूछे गए (ISO 639-1)
ai_modelstringनहींअसिस्टेंट की मॉडल ID
repositorystringनहींरिपॉज़िटरी का पाथ

नतीजा, रिकॉर्ड ID, रिकॉर्ड और लॉग के पाथ, और Markdown के रूप में रिकॉर्ड लौटाता है। जब नतीजा stopped होता है, तो उस Markdown में उपयोगकर्ता, कंप्यूटर और रिपॉज़िटरी का विवरण शामिल नहीं होता।

render_pdf

किसी Markdown दस्तावेज़ (चेंजलॉग, रिलीज़ नोट्स, कंप्लायंस रिकॉर्ड) को PDF फ़ाइल में कन्वर्ट करता है। रिपॉज़िटरी नहीं पढ़ता।

पैरामीटरप्रकारज़रूरीविवरण
markdownstringहाँMarkdown दस्तावेज़ (2,000,000 वर्णों तक)
file_namestringनहींफ़ाइल का नाम, जैसे changelog-web-v1.3.0.pdf। डिफ़ॉल्ट: शीर्षक से
folderstringनहींफ़ाइल के लिए एब्सोल्यूट फ़ोल्डर। डिफ़ॉल्ट: सिस्टम के अस्थायी फ़ोल्डर में mergecat
titlestringनहींPDF मेटाडेटा और पेज फ़ुटर के लिए दस्तावेज़ का शीर्षक। डिफ़ॉल्ट: पहली # हेडिंग
allow_in_projectbooleanनहींप्रोजेक्ट फ़ोल्डर के अंदर लिखने की अनुमति दें; केवल तब जब उपयोगकर्ता ने PDF वहाँ सहेजने को कहा हो

सर्वर प्रोजेक्ट के अंदर (कौन-सी रिपॉज़िटरी वाला फ़ोल्डर) लिखने से मना करता है, जब तक allow_in_project सेट न हो। फ़ाइल नाम में अक्षर, अंक, ., _ और - बने रहते हैं। file, pages और bytes लौटाता है। फ़ॉन्ट की सीमाओं के लिए देखें चेंजलॉग।

repository_info

डिफ़ॉल्ट ब्रांच, वर्तमान ब्रांच, होस्टिंग सेवा और डिफ़ॉल्ट ब्रांच पर मौजूद वर्शन टैग उनकी तिथियों के साथ (नवीनतम पहले, 30 तक)। यह भी बताता है कि पुल रिक्वेस्ट डेटा उपलब्ध है या नहीं (GitHub (GITHUB_TOKEN set) या none (local Git data only)), अंतिम फ़ेच, और क्लोन शैलो है या नहीं।

पैरामीटरप्रकारज़रूरीविवरण
repositorystringनहींरिपॉज़िटरी का पाथ

tags

हर टैग, नवीनतम पहले: तिथि, कमिट, एनोटेटेड या लाइटवेट, संदेश, टैगर, वह वर्शन जैसा दिखता है या नहीं और वह ब्रांच पर है या नहीं। ब्रांच पर मौजूद वर्शन टैग के लिए: पिछला वर्शन टैग और उसके बाद से चेंजसेट की संख्या। साथ में अभी रिलीज़ न हुए चेंजसेट की संख्या और नवीनतम वर्शन टैग।

पैरामीटरप्रकारज़रूरीविवरण
repositorystringनहींरिपॉज़िटरी का पाथ
branchstringनहींवह ब्रांच जिससे रिलीज़ बनाई जाती हैं। डिफ़ॉल्ट: डिफ़ॉल्ट ब्रांच
patternstringनहींनाम में शामिल टेक्स्ट, या * और ? वाला glob (जैसे v2.*); अक्षरों के केस से फ़र्क नहीं पड़ता
versions_onlybooleanनहींकेवल वे टैग जो वर्शन जैसे दिखते हैं (v1.2.3, 1.2)
limitintegerनहींअधिकतम टैग, 1 से 500। डिफ़ॉल्ट 50

changelog

ब्रांच में जो आया उसका Keep a Changelog ड्राफ़्ट, हर चेंजसेट के लिए एक लाइन, रिलीज़ (वर्शन टैग) और सेक्शन (Added, Changed, Deprecated, Removed, Fixed, Security) के अनुसार समूहित। Markdown ड्राफ़्ट और संरचित डेटा लौटाता है: हर चेंजसेट का सेक्शन और कारण, पुल रिक्वेस्ट का नंबर और लिंक, ब्रांच, कमिट, और breaking और internal फ़्लैग; किसी रेंज के लिए, हर छोर को कैसे हल किया गया; उलटे छोर या गायब पुल रिक्वेस्ट डेटा जैसे नोट।

पैरामीटरप्रकारज़रूरीविवरण
repositorystringनहींरिपॉज़िटरी का पाथ
branchstringनहींवह ब्रांच जिसके इतिहास का वर्णन किया जाता है। डिफ़ॉल्ट: डिफ़ॉल्ट ब्रांच (जैसे origin/main)
rangestringनहींएक रेंज from..to ([from..to] भी); हर छोर एक टैग, एक तिथि (YYYY-MM-DD, चाहें तो समय के साथ) या एक कमिट; खुले छोर की अनुमति है (v1.3.0.., ..v1.0.0)
fromstringनहींरेंज की शुरुआत, शामिल नहीं: टैग, तिथि या कमिट
tostringनहींरेंज का अंत, शामिल: टैग, तिथि या कमिट। डिफ़ॉल्ट: ब्रांच
max_releasesintegerनहींकोई रेंज न दी गई हो तो शामिल की जाने वाली रिलीज़, 0 से 100। डिफ़ॉल्ट 5
unreleased_onlybooleanनहींकेवल नवीनतम वर्शन टैग के बाद के बदलाव
include_internalbooleanनहींMarkdown में डॉक्स, टेस्ट, CI और अन्य छोटे काम भी सूचीबद्ध करें। डिफ़ॉल्ट false (वे डेटा में बने रहते हैं)
headerbooleanनहीं# Changelog शीर्षक और Keep a Changelog प्रस्तावना से शुरू करें
languagestringनहींISO 639-1 कोड। डिफ़ॉल्ट en। हेडिंग en, it, de, fr, es के लिए अनुवादित होती हैं; दूसरी भाषाओं के लिए वे अंग्रेज़ी में रहती हैं और डेटा में headingsTranslated: false होता है

या तो range दें या from/to, दोनों नहीं। टूल बदलावों के विवरण का कभी अनुवाद नहीं करता।

changesets

किसी ब्रांच में क्या आया, नवीनतम पहले, इंटीग्रेशन के अनुसार समूहित: मर्ज हुई पुल रिक्वेस्ट और मर्ज, उनके लाए कमिट के साथ, और डायरेक्ट कमिट। इतिहास की चेतावनियाँ (शैलो क्लोन, कोई मर्ज नहीं, स्क्वैश मर्ज) भी लौटाता है।

पैरामीटरप्रकारज़रूरीविवरण
repositorystringनहींरिपॉज़िटरी का पाथ
branchstringनहींवह ब्रांच जिसका वर्णन करना है। डिफ़ॉल्ट: डिफ़ॉल्ट ब्रांच
basestringनहींकेवल वह जो इस टैग, ब्रांच या कमिट के बाद आया
sincestringनहींइंटीग्रेशन की शुरुआती तिथि, YYYY-MM-DD
untilstringनहींइंटीग्रेशन की अंतिम तिथि, YYYY-MM-DD
searchstringनहींविषय, SHA, ब्रांच के नाम या पुल रिक्वेस्ट के शीर्षक में टेक्स्ट (समूहों के अंदर भी)
authorstringनहींलेखक या इंटीग्रेटर का नाम या ई-मेल
limitintegerनहींअधिकतम एंट्री, 1 से 500। डिफ़ॉल्ट 50

where_entered

किसी कमिट के लिए: वह इंटीग्रेशन (पुल रिक्वेस्ट, मर्ज या डायरेक्ट कमिट) जो उसे ब्रांच में लाया, कब, उसे किसने इंटीग्रेट किया, और उसे शामिल करने वाला पहला टैग।

पुल रिक्वेस्ट डेटा

जब एनवायरनमेंट में रिपॉज़िटरी की होस्टिंग सेवा का टोकन होता है, तो टूल पुल रिक्वेस्ट (मर्ज रिक्वेस्ट) के शीर्षक, नंबर, लेबल और लिंक किए गए इश्यू जोड़ते हैं: GitHub के लिए GITHUB_TOKEN (या GH_TOKEN), GitLab के लिए GITLAB_TOKEN (या GL_TOKEN), Azure DevOps के लिए AZURE_DEVOPS_EXT_PAT (पर्सनल एक्सेस टोकन) या AZURE_DEVOPS_TOKEN (Microsoft Entra टोकन)। टोकन के बिना वे केवल लोकल Git डेटा का उपयोग करते हैं और बताते हैं कि कौन-सा वेरिएबल सेट करना है।

प्लगइन के बिना सर्वर का उपयोग करें

यह सर्वर एक सामान्य MCP सर्वर भी है: कोई स्किल नहीं, टूल के नाम mcp__mergecat__<tool>। इसके निर्देश क्लाइंट से कहते हैं कि वह कंप्लायंस सवाल पूछे और दस्तावेज़ उपयोगकर्ता को बातचीत में दे, प्रोजेक्ट में फ़ाइलों के रूप में नहीं।

सर्वर पाएँ

डाउनलोड सेक्शन से एक फ़ाइल mergecat-mcp.cjs डाउनलोड करें, या किसी क्लोन से npm run mcp:build के साथ इसे बिल्ड करें (यह plugins/mergecat/server/mergecat-mcp.cjs में लिखी जाती है)। इसके लिए Node.js 20 या नया वर्शन चाहिए।

इसे Claude Code में जोड़ें

claude mcp add --transport stdio --scope user mergecat -- node /path/to/mergecat-mcp.cjs

एनवायरनमेंट वेरिएबल पास करने के लिए -- से पहले -e NAME=value जोड़ें, उदाहरण के लिए -e MERGECAT_COMPLIANCE_DIR=/path/to/records।

इसे जाँचें

किसी Git रिपॉज़िटरी में Claude Code शुरू करें और /mcp चलाएँ: mergecat सर्वर कनेक्टेड दिखना चाहिए। सर्वर stderr पर लॉग करता है और शुरू होने पर mergecat MCP server 0.3.0 ready प्रिंट करता है।

stdio सर्वर शुरू करने वाले दूसरे MCP क्लाइंट भी इसे इसी तरह चलाते हैं, node /path/to/mergecat-mcp.cjs: GitHub Copilot, OpenAI Codex और GitLab Duo के लिए देखें अन्य AI सहायक। Claude Code के बाहर CLAUDE_PROJECT_DIR सेट नहीं होता: अगर क्लाइंट अपने खुले फ़ोल्डर बताता है, तो सर्वर उनका उपयोग करता है, वरना MERGECAT_REPOSITORY सेट करें या टूल को repository पास करें।

एनवायरनमेंट वेरिएबल

वेरिएबलप्रभाव
GITHUB_TOKENपुल रिक्वेस्ट डेटा के लिए GitHub टोकन; GITHUB_TOKEN सेट न होने पर GH_TOKEN का उपयोग होता है
GITLAB_TOKENमर्ज रिक्वेस्ट डेटा के लिए GitLab टोकन (read_api); GITLAB_TOKEN सेट न होने पर GL_TOKEN का उपयोग होता है
AZURE_DEVOPS_EXT_PATपुल रिक्वेस्ट डेटा के लिए Azure DevOps पर्सनल एक्सेस टोकन; इसके बजाय AZURE_DEVOPS_TOKEN में Microsoft Entra टोकन दिया जा सकता है
MERGECAT_AI_SERVICEवह AI सेवा जिसके बारे में कंप्लायंस सवाल है, जब क्लाइंट पहचाना नहीं जाता: claude, copilot, openai, gitlab-duo या कोई दूसरा नाम
MERGECAT_GIT_PATHGit एक्ज़ीक्यूटेबल, जब git PATH पर न हो
MERGECAT_COMPLIANCE_DIRडिफ़ॉल्ट फ़ोल्डर के बजाय AI उपयोग रिकॉर्ड का फ़ोल्डर
MERGECAT_REPOSITORYवह रिपॉज़िटरी जिसका उपयोग तब होता है जब किसी टूल को repository पैरामीटर नहीं मिलता; साथ ही वह प्रोजेक्ट फ़ोल्डर जिसकी render_pdf सुरक्षा करता है
CLAUDE_PROJECT_DIRClaude Code द्वारा सेट: प्रोजेक्ट, जिसका उपयोग तब होता है जब न पैरामीटर दिया गया हो न MERGECAT_REPOSITORY

Claude Code में, प्लगइन ऊपर दिए टोकन वेरिएबल, MERGECAT_GIT_PATH और MERGECAT_COMPLIANCE_DIR को उस एनवायरनमेंट से पास करता है जिसमें आप Claude Code शुरू करते हैं।
