ट्रबलशूटिंग और FAQ

Git, रिपॉज़िटरी के स्वामित्व, बिना साइन किए बिल्ड, क्रेडेंशियल, कनेक्शन और Claude Code प्लगइन से जुड़ी आम समस्याएँ ठीक करें, और अक्सर पूछे जाने वाले सवालों के जवाब पाएँ।

GitHub पर एडिट करें

AI की मदद से अंग्रेज़ी से अनूदित। संदेह होने पर अंग्रेज़ी संस्करण मान्य है।

ज़्यादातर समस्याएँ उस एनवायरनमेंट से आती हैं जिसमें mergecat चलता है: Git कहाँ इंस्टॉल है, रिपॉज़िटरी का मालिक कौन है, सिस्टम कौन-सी कीचेन देता है, या टीम पुल रिक्वेस्ट को कैसे इंटीग्रेट करती है। नीचे वह संदेश ढूँढें जो आपको दिख रहा है।

Git नहीं मिला

संदेश है Git was not found. Install Git (https://git-scm.com/downloads) or set the path to the git executable in the settings.

mergecat पहले कॉन्फ़िगर किया गया पाथ इस्तेमाल करता है, फिर PATH पर git, फिर सामान्य इंस्टॉल फ़ोल्डर:

/opt/homebrew/bin/git, /usr/local/bin/git, /usr/bin/git।

Dock या Finder से शुरू किए गए ऐप को आपके शेल का PATH नहीं मिलता, इसीलिए mergecat Homebrew फ़ोल्डरों में भी देखता है। /usr/bin/git के लिए Xcode Command Line Tools चाहिए; उन्हें इससे इंस्टॉल करें:

xcode-select --install

%ProgramFiles%\Git\cmd\git.exe, %ProgramFiles(x86)%\Git\cmd\git.exe और %LOCALAPPDATA%\Programs\Git\cmd\git.exe।

Git for Windows इंस्टॉल करें, या PowerShell में पहले से मौजूद Git ढूँढें:

Get-Command git

/usr/bin/git, /usr/local/bin/git।

अपने पैकेज मैनेजर से Git इंस्टॉल करें, उदाहरण के लिए sudo apt install git, या which git से पहले से मौजूद Git ढूँढें।

अगर Git किसी और जगह इंस्टॉल है, तो उसका पाथ सेट करें:

कॉम्पोनेंटकहाँ
डेस्कटॉप ऐपसेटिंग्स › Git एक्ज़ीक्यूटेबल; डायलॉग मिला हुआ वर्शन दिखाता है
VS Codemergecat.gitPath (ख़ाली: VS Code का git.path, फिर सामान्य फ़ोल्डर)
कमांड लाइन, MCP सर्वरएनवायरनमेंट वेरिएबल MERGECAT_GIT_PATH

Git रिपॉज़िटरी पढ़ने से मना करता है

संदेश है Git refuses to read this repository because it is owned by another user, जिसके बाद एक कमांड होती है। Git आपको उन रिपॉज़िटरी से बचाता है जिनका मालिक कोई दूसरा अकाउंट है (“dubious ownership”), उदाहरण के लिए किसी एक्सटर्नल ड्राइव, नेटवर्क शेयर, किसी दूसरे यूज़र के बनाए फ़ोल्डर, या WSL या कंटेनर वॉल्यूम पर।

अगर आप रिपॉज़िटरी पर भरोसा करते हैं, तो संदेश में दिए फ़ोल्डर का उपयोग करके उसे सुरक्षित के रूप में चिह्नित करें:

git config --global --add safe.directory "/path/to/repository"

Git रिपॉज़िटरी नहीं है

Not a Git repository: … का मतलब है कि फ़ोल्डर किसी Git वर्किंग कॉपी के अंदर नहीं है। रिपॉज़िटरी का रूट फ़ोल्डर या उसके अंदर का कोई भी फ़ोल्डर खोलें। VS Code में mergecat खोले गए फ़ोल्डर के सबफ़ोल्डरों में भी खोजता है (mergecat.repositoryScanDepth, डिफ़ॉल्ट रूप से दो स्तर)।

सिस्टम चेतावनी देता है कि ऐप साइन नहीं किया गया है

mergecat बिल्ड अभी कोड-साइन या नोटराइज़ नहीं किए गए हैं। पहले डाउनलोड को सत्यापित करें (देखें बिना साइन किए बिल्ड), फिर:

अगर macOS कहता है कि mergecat नहीं खोला जा सकता क्योंकि Apple उसमें मैलिशियस सॉफ़्टवेयर की जाँच नहीं कर सकता:

  1. Applications फ़ोल्डर से mergecat को एक बार खोलने की कोशिश करें।
  2. System Settings › Privacy & Security खोलें।
  3. mergecat वाले संदेश तक स्क्रॉल करें और Open Anyway पर क्लिक करें, फिर पुष्टि करें।

अगर macOS कहता है कि ऐप damaged है, तो डाउनलोड क्वारंटीन में है; चेकसम सत्यापित करने के बाद आप क्वारंटीन एट्रिब्यूट हटा सकते हैं:

xattr -dr com.apple.quarantine /Applications/mergecat.app

अगर Microsoft Defender SmartScreen Windows protected your PC दिखाता है, तो More info पर क्लिक करें, फ़ाइल का नाम जाँचें, फिर Run anyway पर।

Linux AppImage के सिग्नेचर नहीं जाँचता। AppImage चलाने से पहले उसे एक्ज़ीक्यूटेबल बनाएँ:

chmod +x mergecat-linux-x86_64.AppImage

Linux पर क्रेडेंशियल याद नहीं रहते

संदेश है कोई सीक्रेट सर्विस (GNOME Keyring या KWallet) नहीं मिली: क्रेडेंशियल केवल मेमोरी में रखे जाते हैं और ऐप रीस्टार्ट करने के बाद आपको फिर से कनेक्ट करना होगा।

mergecat क्रेडेंशियल को सिस्टम कीचेन से एन्क्रिप्ट करता है और उन्हें कभी सादे टेक्स्ट में नहीं लिखता। सीक्रेट सर्विस के बिना वह उन्हें केवल मेमोरी में रखता है। GNOME Keyring या KWallet इंस्टॉल और अनलॉक करें (ज़्यादातर डेस्कटॉप एनवायरनमेंट में इनमें से एक शामिल होता है), फिर mergecat रीस्टार्ट करें और फिर से कनेक्ट करें। जिन सिस्टम पर सीक्रेट सर्विस नहीं है, वहाँ हर बार शुरू करने के बाद फिर से कनेक्ट करें।

किसी भी सिस्टम पर, कोई सिस्टम कीचेन उपलब्ध नहीं है का मतलब यही है, और क्रेडेंशियल केवल मेमोरी में रखे जाते हैं (MERGECAT_MEMORY_CREDENTIALS सेट है) का मतलब है कि एनवायरनमेंट वेरिएबल MERGECAT_MEMORY_CREDENTIALS=1 सेट है।

फ़ेच या टैग पुश विफल होता है

mergecat Git को आपके अपने क्रेडेंशियल के साथ चलाता है और कभी पासवर्ड नहीं माँगता। अगर फ़ेच या टैग पुश विफल होता है, तो उसी रिपॉज़िटरी में टर्मिनल में git fetch या git push चलाएँ: अगर वह पासवर्ड माँगता है, तो एक credential helper (उदाहरण के लिए Git Credential Manager) या SSH की सेट अप करें, फिर mergecat में दोबारा कोशिश करें।

मर्ज और स्क्वैश से जुड़ी चेतावनियाँ

चेतावनीमतलब
इस ब्रांच में कोई मर्ज कमिट नहीं है: हर कमिट डायरेक्ट कमिट के रूप में दिखाया गया है।पुल रिक्वेस्ट रीबेस या फ़ास्ट-फ़ॉरवर्ड से पूरी की जाती हैं। उन्हें पुल रिक्वेस्ट के अनुसार समूहित करने के लिए होस्टिंग सेवा कनेक्ट करें
यह ब्रांच नो-फ़ास्ट-फ़ॉरवर्ड मर्ज से इंटीग्रेट नहीं होती: पुल रिक्वेस्ट शायद स्क्वैश-मर्ज की जाती हैं…हर पुल रिक्वेस्ट एक ही कमिट है। मूल कमिट देखने के लिए कनेक्ट करें
मिश्रित इंटीग्रेशन तरीके: … पुल रिक्वेस्ट स्क्वैश-मर्ज की हुई लगती हैं…कुछ पुल रिक्वेस्ट स्क्वैश-मर्ज की गई थीं; वे एक-एक कमिट के रूप में दिखती हैं
… मर्ज ने “main” को किसी और चीज़ में मर्ज किया…ब्रांच पर git pull वाला मर्ज या किसी फ़ीचर ब्रांच पर फ़ास्ट-फ़ॉरवर्ड: उस बिंदु के बाद ग्रुपिंग गलत हो सकती है
यह एक शैलो क्लोन है…पुराना इतिहास गायब है। git fetch --unshallow चलाएँ

हर स्थिति में mergecat क्या दिखाता है, इसके लिए देखें सीमाएं और इंटीग्रेशन स्टाइल।

ऑडिट रिपोर्ट में स्वीकृतियाँ “unknown” हैं

स्वीकृतियाँ होस्टिंग सेवा में संग्रहीत होती हैं। रिपोर्ट एक्सपोर्ट करने से पहले GitHub, GitLab या Azure DevOps कनेक्ट करें; एक्सपोर्ट करते समय डेस्कटॉप ऐप और VS Code कनेक्ट करने का विकल्प देते हैं। कमांड लाइन कभी कनेक्ट नहीं होती, इसलिए उसकी रिपोर्ट में स्वीकृतियाँ हमेशा अज्ञात दिखती हैं। देखें चेंज ऑडिट रिपोर्ट।

किसी एनवायरनमेंट पर ऐसा कमिट चल रहा है जो आपके क्लोन में नहीं है

जब किसी एनवायरनमेंट पर ऐसा कमिट चल रहा हो जो आपके क्लोन में अभी नहीं है, उदाहरण के लिए किसी नए बिल्ड से डिप्लॉयमेंट के बाद, तो डिप्लॉयमेंट पेज यह बताता है। फ़ेच करें पर क्लिक करें (या git fetch चलाएँ) और फिर से तुलना करें।

VS Code कमांड कुछ अप्रत्याशित करती हैं

“MergeCat for VS Code” (mergecat.mergecat-vscode) Marketplace का एक असंबंधित एक्सटेंशन है जो वही कमांड और सेटिंग नाम रजिस्टर करता है। उसे हटाएँ:

code --uninstall-extension mergecat.mergecat-vscode

Claude Code प्लगइन

कंप्लायंस सवाल दोबारा पूछा जाता है

ऐसा होना अपेक्षित है। जवाब Claude Code सेशन का होता है: हर सेशन एक नया mergecat MCP सर्वर प्रोसेस शुरू करता है, जो रिपॉज़िटरी का पहला डेटा भेजे जाने से पहले दोबारा पूछता है। हर जवाब एक नया AI उपयोग रिकॉर्ड होता है।

Claude कहता है कि कंप्लायंस पुष्टि ज़रूरी है

रिपॉज़िटरी टूल तब तक लॉक रहते हैं जब तक सवाल का जवाब ऐसे नतीजे के साथ नहीं दिया जाता जो उनकी अनुमति देता हो। जब Claude सवाल पूछे, तो उसका जवाब दें। अगर आपने सेशन में पहले दोनों सवालों का जवाब “नहीं” दिया था, तो mergecat डेटा फिर से माँगें और Claude सवाल फिर से पूछेगा।

mergecat टूल नहीं दिख रहे

  1. Claude Code में /mcp चलाएँ और जाँचें कि mergecat सर्वर कनेक्टेड है।
  2. जाँचें कि Node.js 20 या नया वर्शन node के रूप में इंस्टॉल है: node --version।
  3. जाँचें कि प्लगइन इंस्टॉल है: claude plugin list।
  4. इंस्टॉल या अपडेट करने के बाद /reload-plugins चलाएँ या नया सेशन शुरू करें।

चेंजलॉग में पुल रिक्वेस्ट शीर्षक नहीं हैं

Claude Code को रिपॉज़िटरी की होस्टिंग सेवा का टोकन सेट करके शुरू करें: GitHub के लिए GITHUB_TOKEN (या GH_TOKEN), GitLab के लिए GITLAB_TOKEN (या GL_TOKEN), Azure DevOps के लिए AZURE_DEVOPS_EXT_PAT या AZURE_DEVOPS_TOKEN। केवल github.com, gitlab.com और Azure DevOps की रिपॉज़िटरी पहचानी जाती हैं। देखें पुल रिक्वेस्ट डेटा।

PDF में प्रश्नचिह्न दिखते हैं

PDF स्टैंडर्ड PDF फ़ॉन्ट का उपयोग करती हैं, जो केवल Latin-1 को कवर करते हैं। दूसरी लिपियों में लिखी जाने वाली भाषाओं के लिए Markdown माँगें। देखें PDF आउटपुट।

FAQ

क्या mergecat मेरी रिपॉज़िटरी बदलता है?

केवल तब जब आप फ़ेच चलाते हैं, कोई टैग बनाते या पुश करते हैं, या कोई पुल रिक्वेस्ट बनाते हैं। यह कभी कमिट, चेकआउट, मर्ज या कुछ भी रीराइट नहीं करता। देखें सिक्योरिटी और प्राइवेसी।

क्या mergecat मेरा कोड कहीं भेजता है?

डेस्कटॉप ऐप और VS Code केवल उसी होस्टिंग सेवा से बात करते हैं जिसे आप कनेक्ट करते हैं। Claude Code प्लगइन कंप्लायंस सवाल के बाद इतिहास का मेटाडेटा (कमिट संदेश, नाम, ई-मेल पते, तिथियाँ, ब्रांच और टैग के नाम, कमिट SHA, और टोकन होने पर पुल रिक्वेस्ट डेटा) Claude को भेजता है; इसके टूल फ़ाइलों की सामग्री या डिफ़ नहीं भेजते। Claude Code ख़ुद अपनी अनुमतियों के तहत आपके प्रोजेक्ट की फ़ाइलें पढ़ सकता है।

क्या कोई mergecat अकाउंट, सर्वर या टेलीमेट्री है?

नहीं। mergecat का कोई अकाउंट, कोई सर्वर और कोई टेलीमेट्री नहीं है, और यह अपडेट की जाँच नहीं करता।

क्या mergecat ऑफ़लाइन काम करता है?

हाँ, उन सभी चीज़ों के लिए जिन्हें होस्टिंग सेवा की ज़रूरत नहीं होती: चेंजसेट, डिफ़, फ़िल्टर, एक्सपोर्ट, ब्रांच, टैग और बिना स्वीकृतियों वाली ऑडिट रिपोर्ट।

प्लगइन Team या Enterprise अकाउंट के बारे में क्यों पूछता है?

कई संगठन कंपनी का डेटा केवल उन AI अकाउंट पर अनुमति देते हैं जो किसी बिज़नेस एग्रीमेंट के तहत आते हैं। सवाल और रिकॉर्ड हर सेशन के लिए उस फ़ैसले को दर्ज करते हैं। देखें EU AI Act और NIS2।
