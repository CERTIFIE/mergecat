कंप्लायंस और ऑडिट

सिक्योरिटी और प्राइवेसी

mergecat आपकी रिपॉज़िटरी में क्या बदलता है, कौन-सा डेटा आपके कंप्यूटर से बाहर जाता है और कहाँ, क्रेडेंशियल कैसे संग्रहीत होते हैं, और mergecat लोकल रूप से क्या रखता है।

GitHub पर एडिट करें

AI की मदद से अंग्रेज़ी से अनूदित। संदेह होने पर अंग्रेज़ी संस्करण मान्य है।

mergecat एक लोकल टूल है: यह आपकी रिपॉज़िटरी को आपके अपने Git से पढ़ता है, केवल उन होस्टिंग सेवाओं से बात करता है जिन्हें आप कनेक्ट करते हैं, और इसका अपना कोई सर्वर नहीं है। यह पेज बताता है कि यह क्या बदल सकता है, कौन-सा डेटा आपके कंप्यूटर से बाहर जाता है, यह क्रेडेंशियल कैसे संग्रहीत करता है, और डिस्क पर क्या रखता है।

एक नज़र में

विषयmergecat इसे कैसे संभालता है
रिपॉज़िटरीडिफ़ॉल्ट रूप से रीड-ओनली; केवल स्पष्ट कमांड पर लिखता है
नेटवर्ककेवल वे होस्टिंग सेवाएँ जिन्हें आप कनेक्ट करते हैं (GitHub, GitLab, Azure DevOps) और उनके साइन-इन पेज; Claude केवल Claude Code प्लगइन के ज़रिए, कंप्लायंस जवाब के बाद
क्रेडेंशियलऑपरेटिंग सिस्टम की कीचेन से एन्क्रिप्ट किए जाते हैं; कीचेन उपलब्ध न होने पर केवल मेमोरी में
टेलीमेट्रीकोई नहीं: कोई उपयोग आँकड़े नहीं, कोई क्रैश रिपोर्ट नहीं, कोई अपडेट जाँच नहीं, कोई mergecat सर्वर नहीं
लोकल डेटाऐप डेटा फ़ोल्डर में सेटिंग्स, एन्क्रिप्ट किए गए क्रेडेंशियल और पुल रिक्वेस्ट कैश; कभी रिपॉज़िटरी में नहीं

डिफ़ॉल्ट रूप से रीड-ओनली

mergecat इतिहास को git log, git blame और इसी तरह के कमांड से पढ़ता है। यह कभी कुछ कमिट, चेक आउट, मर्ज, रीबेस या रीराइट नहीं करता, और कभी आपके वर्किंग ट्री या आपकी लोकल ब्रांच को नहीं छूता। केवल ये कार्रवाइयाँ कुछ बदलती हैं, और केवल तब जब आप उन्हें शुरू करते हैं:

कार्रवाईयह क्या बदलती हैकहाँ
फ़ेच करेंgit fetch --all --tags --prune चलाती है: remote-tracking ब्रांच और टैग अपडेट करती है, और उन्हें हटा देती है जो रिमोट पर हटा दिए गए हैं। लोकल ब्रांच और फ़ाइलों को छुआ नहीं जाता।डेस्कटॉप ऐप (ब्रांच पेज), VS Code (Branches पेज, Fetch All Remotes)
टैग बनाएँआपके चुने गए कमिट पर एक लोकल टैग बनाती है; संदेश डालने पर एनोटेटेड टैगडेस्कटॉप ऐप, VS Code (Tags पेज, Create Tag…, Create Tag Here…)
टैग पुश करेंकेवल उसी एक टैग को रिमोट पर पुश करती हैडेस्कटॉप ऐप, VS Code (Tags पेज)
पुल रिक्वेस्ट बनाएँहोस्टिंग सेवा पर एक पुल रिक्वेस्ट (GitLab: मर्ज रिक्वेस्ट) बनाती हैडेस्कटॉप ऐप, VS Code (Pull requests पेज, Create Pull Request…)

एक्सपोर्ट और ऑडिट रिपोर्ट केवल वहीं लिखी जाती हैं जहाँ आप उन्हें सहेजते हैं। Claude Code प्लगइन का MCP सर्वर कभी रिपॉज़िटरी नहीं बदलता: यह केवल AI उपयोग रिकॉर्ड लिखता है और, अनुरोध करने पर, प्रोजेक्ट के बाहर PDF फ़ाइलें। Claude CHANGELOG.md को केवल तभी अपडेट करता है जब आप स्पष्ट रूप से ऐसा कहते हैं।

mergecat Git को कैसे चलाता है:

  • आपका अपना git एक्ज़ीक्यूटेबल, सीधे शुरू किया गया, कभी शेल के ज़रिए नहीं;
  • GIT_TERMINAL_PROMPT=0 के साथ: फ़ेच और टैग पुश आपके credential helper या SSH कुंजी का उपयोग करते हैं और कभी पासवर्ड नहीं माँगते;
  • GIT_OPTIONAL_LOCKS=0 के साथ, ताकि पढ़ते समय Git के वैकल्पिक लॉक न लिए जाएँ।

आपके कंप्यूटर से बाहर जाने वाला डेटा

गंतव्यकबक्या
आपके Git रिमोटफ़ेच और टैग पुशGit जो भी आदान-प्रदान करता है, आपके Git क्रेडेंशियल के साथ
होस्टिंग सेवा API: GitHub, GitLab, Azure DevOpsकेवल जब सेवा कनेक्टेड होरिपॉज़िटरी की पुल रिक्वेस्ट, स्वीकृतियों, लिंक किए गए इश्यू, पाइपलाइन और डिप्लॉयमेंट के लिए अनुरोध; आपकी बनाई पुल रिक्वेस्ट
साइन-इन पेज: github.com, login.microsoftonline.com, आपका GitLab इंस्टेंसजब आप ब्राउज़र से साइन इन करते हैंडिवाइस-फ़्लो साइन-इन; वहाँ आपके संगठन का SSO और MFA लागू होता है
Claude (Anthropic), या वह AI असिस्टेंट जिसमें आप mergecat MCP सर्वर चलाते हैं (GitHub Copilot, OpenAI Codex, GitLab Duo)केवल mergecat MCP सर्वर के ज़रिए, जब कंप्लायंस सवाल ने इसकी अनुमति दी होइतिहास का मेटाडेटा: कमिट संदेश, लेखक और कमिटर के नाम और ई-मेल पते, तिथियाँ, ब्रांच और टैग के नाम, कमिट SHA; होस्टिंग सेवा के टोकन के साथ, पुल रिक्वेस्ट के शीर्षक, नंबर, लेबल और लिंक किए गए इश्यू

इसके अलावा कुछ नहीं। mergecat में कोई टेलीमेट्री नहीं है: यह कोई उपयोग आँकड़े इकट्ठा नहीं करता और कोई क्रैश रिपोर्ट नहीं भेजता। यह अपडेट की जाँच नहीं करता, और इसका कोई mergecat सर्वर नहीं है, न कोई अकाउंट। डेस्कटॉप ऐप अपने फ़ॉन्ट साथ लेकर आता है और किसी CDN से कुछ भी लोड नहीं करता।

mergecat के MCP टूल Claude को इतिहास का मेटाडेटा देते हैं, आपकी फ़ाइलों या डिफ़ की सामग्री नहीं। Claude Code ख़ुद अपनी अनुमतियों के तहत आपके प्रोजेक्ट की फ़ाइलें पढ़ सकता है; उदाहरण के लिए, चेंजलॉग स्किल CHANGELOG.md पढ़ती है।

AI उपयोग दर्ज किया जाता है

किसी Claude Code सेशन में रिपॉज़िटरी का पहला डेटा भेजे जाने से पहले, mergecat पूछता है कि क्या आप Claude Team या Enterprise अकाउंट का उपयोग करते हैं, और जवाब दर्ज करता है। EU AI Act और NIS2 (यूरोपीय संघ का AI अधिनियम और साइबर सुरक्षा पर EU का NIS2 निर्देश) देखें।

क्रेडेंशियल

डेस्कटॉप ऐप

टोकन ऑपरेटिंग सिस्टम की कीचेन (Electron safeStorage) से एन्क्रिप्ट किए जाते हैं और ऐप डेटा फ़ोल्डर में credentials.bin में संग्रहीत होते हैं।

एन्क्रिप्शन कुंजी macOS Keychain में रखी जाती है।

डेटा आपके उपयोगकर्ता अकाउंट के लिए Windows DPAPI से एन्क्रिप्ट किया जाता है।

एन्क्रिप्शन कुंजी एक सीक्रेट सर्विस रखती है: GNOME Keyring (libsecret) या KWallet। इसके बिना mergecat क्रेडेंशियल केवल मेमोरी में रखता है और एक चेतावनी दिखाता है: ऐप रीस्टार्ट करने के बाद आपको फिर से कनेक्ट करना होगा। ट्रबलशूटिंग देखें।

  • जब कोई कीचेन उपलब्ध नहीं होती, तो क्रेडेंशियल केवल मेमोरी में रखे जाते हैं, कभी सादे टेक्स्ट में नहीं लिखे जाते।
  • GitHub CLI साइन-इन कोई टोकन संग्रहीत नहीं करता: ज़रूरत पड़ने पर mergecat gh auth token चलाता है।
  • ब्राउज़र फ़्लो के साइन-इन टोकन उनकी समय-सीमा समाप्त होने से पहले रीफ़्रेश किए जाते हैं।
  • कनेक्शन डायलॉग में डिस्कनेक्ट करें उस सेवा का संग्रहीत क्रेडेंशियल हटा देता है।

VS Code एक्सटेंशन

  • GitHub और Azure DevOps (Sign in with Microsoft) उन अकाउंट का उपयोग करते हैं जिन्हें VS Code पहले से प्रबंधित करता है। टोकन VS Code में ही रहता है; ज़रूरत पड़ने पर mergecat उसे VS Code से माँगता है।
  • पर्सनल एक्सेस टोकन और GitLab साइन-इन टोकन VS Code के SecretStorage में संग्रहीत होते हैं (जो ऑपरेटिंग सिस्टम की कीचेन पर आधारित है), हर सेवा और होस्ट के लिए एक। वे कभी सेटिंग्स या लॉग में नहीं लिखे जाते।

Claude Code प्लगइन और कमांड लाइन

  • MCP सर्वर github.com रिपॉज़िटरी के पुल रिक्वेस्ट डेटा के लिए अपने एनवायरनमेंट वेरिएबल से GITHUB_TOKEN (या GH_TOKEN) पढ़ता है। यह उसे संग्रहीत नहीं करता।
  • कमांड लाइन कोई होस्टिंग सेवा इस्तेमाल नहीं करती, और आपके Git सेटअप के अलावा कोई क्रेडेंशियल नहीं।

न्यूनतम अधिकार

टोकन को केवल वे स्कोप दें जिनकी mergecat को ज़रूरत है। पढ़ने के लिए read स्कोप चाहिए; केवल पुल रिक्वेस्ट बनाने के लिए write एक्सेस चाहिए (उदाहरण के लिए GitLab में पढ़ने के लिए read_api काफ़ी है, मर्ज रिक्वेस्ट बनाने के लिए api ज़रूरी है)। हर सेवा के स्कोप कनेक्शन में दिए गए हैं।

लोकल डेटा और कैश

क्याकहाँसामग्री
सेटिंग्स (डेस्कटॉप)ऐप डेटा फ़ोल्डर में settings.jsonGit पाथ, साइन-इन क्लाइंट ID, Microsoft टेनेंट, पेज का आकार, पिछली 10 रिपॉज़िटरी
क्रेडेंशियल (डेस्कटॉप)ऐप डेटा फ़ोल्डर में credentials.binएन्क्रिप्ट किए गए टोकन
पुल रिक्वेस्ट कैश (डेस्कटॉप)ऐप डेटा फ़ोल्डर में pull-request-cache/, हर रिपॉज़िटरी की एक फ़ाइलहर कमिट SHA के अनुसार पुल रिक्वेस्ट डेटा। मर्ज की गई पुल रिक्वेस्ट रखी जाती हैं; “कोई पुल रिक्वेस्ट नहीं” वाले जवाब 6 घंटे बाद और खुली पुल रिक्वेस्ट 1 घंटे बाद फिर से जाँची जाती हैं
पुल रिक्वेस्ट कैश (VS Code)VS Code में एक्सटेंशन का global storage फ़ोल्डरवही डेटा, हर कमिट SHA के अनुसार
AI उपयोग रिकॉर्डmergecat का कंप्लायंस फ़ोल्डरAI उपयोग रिकॉर्ड देखें
Claude Code से बनी PDFClaude का scratchpad, या सिस्टम के अस्थायी फ़ोल्डर में mergecat फ़ोल्डरकेवल जब आप PDF माँगते हैं

mergecat कभी आपकी रिपॉज़िटरी में कैश या सेटिंग्स नहीं लिखता।

डेस्कटॉप ऐप का ऐप डेटा फ़ोल्डर:

~/Library/Application Support/mergecat/
%APPDATA%\mergecat\
~/.config/mergecat/

या, जब XDG_CONFIG_HOME सेट हो, तो $XDG_CONFIG_HOME/mergecat/।

सब कुछ हटाने के लिए सेवाओं को डिस्कनेक्ट करें, ऐप बंद करें और यह फ़ोल्डर डिलीट करें। macOS और Windows पर कंप्लायंस रिकॉर्ड इसके compliance सबफ़ोल्डर में होते हैं: अगर ऑडिट के लिए उनकी ज़रूरत है, तो उन्हें रखें।

डेस्कटॉप ऐप की हार्डनिंग

  • विंडो की सामग्री एक सैंडबॉक्स किए गए रेंडरर में चलती है, context isolation के साथ और बिना Node.js एक्सेस के; यह एक सीमित इंटरफ़ेस के ज़रिए मुख्य प्रोसेस से बात करती है।
  • विंडो कभी ऐप से बाहर नेविगेट नहीं करती। लिंक आपके डिफ़ॉल्ट ब्राउज़र में खुलते हैं, और केवल https:// लिंक ही खोले जाते हैं।
  • एक समय में ऐप का केवल एक इंस्टेंस चलता है।

बिना साइन किए बिल्ड

कोड साइनिंग और notarisation अभी कॉन्फ़िगर नहीं हैं, इसलिए जब आप पहली बार mergecat खोलते हैं, तो macOS और Windows चेतावनी देते हैं (इसे कैसे खोलें)। पुष्टि करने से पहले:

  • mergecat केवल प्रोजेक्ट के releases पेज या डाउनलोड सेक्शन से डाउनलोड करें;
  • फ़ाइल के SHA-256 चेकसम की तुलना रिलीज़ में प्रकाशित चेकसम (SHA256SUMS.txt, जो रिलीज़ नोट्स में भी दिया गया है) से करें:
shasum -a 256 ~/Downloads/mergecat-mac-arm64.dmg
Get-FileHash "$HOME\Downloads\mergecat-windows-x64-setup.exe" -Algorithm SHA256
sha256sum ~/Downloads/mergecat-linux-x86_64.AppImage
  • अगर आपकी नीति बिना साइन किए सॉफ़्टवेयर की अनुमति नहीं देती, तो mergecat को सोर्स से बिल्ड करें (इंस्टॉलेशन देखें) या साइन की गई रिलीज़ का इंतज़ार करें।
