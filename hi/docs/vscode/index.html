इंटीग्रेशन

VS Code एक्सटेंशन

VS Code के लिए mergecat एक्सटेंशन इंस्टॉल करें और इसके व्यू, रिपॉज़िटरी पेज, कमांड और सेटिंग्स का उपयोग करें।

GitHub पर एडिट करें

AI की मदद से अंग्रेज़ी से अनूदित। संदेह होने पर अंग्रेज़ी संस्करण मान्य है।

mergecat एक्सटेंशन चेंजसेट व्यू को VS Code में लाता है: किसी ब्रांच का इतिहास इंटीग्रेशन के अनुसार समूहित, रिपॉज़िटरी पेज (ब्रांच, टैग, पुल रिक्वेस्ट, पाइपलाइन, डिप्लॉयमेंट) एडिटर टैब के रूप में, changeset blame, मेट्रिक्स और चेंज ऑडिट रिपोर्ट। यह उन GitHub और Microsoft अकाउंट से साइन इन करता है जिन्हें VS Code पहले से जानता है।

आवश्यकताएँ: VS Code 1.90 या नया वर्शन और Git। ब्रांच पेज की कॉन्फ़्लिक्ट जाँच के लिए Git 2.38 या नया वर्शन चाहिए।

इंस्टॉल करें

अभी Marketplace पर नहीं

एक्सटेंशन अभी Visual Studio Marketplace पर प्रकाशित नहीं हुआ है। इसे किसी रिलीज़ की .vsix फ़ाइल से इंस्टॉल करें, या सोर्स से बिल्ड करें।

डाउनलोड सेक्शन से mergecat-vscode.vsix डाउनलोड करें, फिर इसे इन दो में से किसी एक तरीके से इंस्टॉल करें।

कमांड लाइन:

code --install-extension mergecat-vscode.vsix

VS Code: Extensions व्यू खोलें, व्यू के ऊपर … मेन्यू पर क्लिक करें, Install from VSIX… चुनें और फ़ाइल चुनें।

mergecat रिपॉज़िटरी के किसी क्लोन के रूट से (Node.js 20 या नया वर्शन):

npm install
npm run vscode:install

यह स्क्रिप्ट एक्सटेंशन को बिल्ड और पैकेज करके VS Code में इंस्टॉल करती है; code कमांड PATH पर न होने पर भी यह उसे ढूँढ लेती है। बदलावों के बाद इसे फिर से चलाएँ। एक्सटेंशन हटाने के लिए:

npm run vscode:install -- --uninstall

फिर Developer: Reload Window चलाएँ, Git रिपॉज़िटरी वाला कोई फ़ोल्डर खोलें और ऐक्टिविटी बार में mergecat आइकन पर क्लिक करें।

मिलते-जुलते नाम वाला एक अलग एक्सटेंशन

Marketplace पर “MergeCat for VS Code” (mergecat.mergecat-vscode) एक असंबंधित एक्सटेंशन है जो वही कमांड और सेटिंग नाम रजिस्टर करता है। दोनों को इंस्टॉल न करें। अगर वह इंस्टॉल है, तो उसे हटाएँ:

code --uninstall-extension mergecat.mergecat-vscode

व्यू

ऐक्टिविटी बार का mergecat आइकन तीन व्यू खोलता है।

कौन-सी रिपॉज़िटरी? अगर खोला गया फ़ोल्डर किसी Git रिपॉज़िटरी के अंदर है, तो वही रिपॉज़िटरी दिखाई जाती है। वरना mergecat उसके सबफ़ोल्डरों में खोजता है (डिफ़ॉल्ट रूप से दो स्तर, mergecat.repositoryScanDepth)। एक रिपॉज़िटरी मिलने पर वह उसे खोल देता है; कई मिलने पर वह पिछली बार इस्तेमाल की गई रिपॉज़िटरी या एडिटर में खुली फ़ाइल की रिपॉज़िटरी दिखाता है, या आपसे चुनने को कहता है (टाइटल बार के रिपॉज़िटरी बटन से भी)।

Changesets

चुनी गई ब्रांच का समूहित इतिहास, दो लेआउट में। हेडर में List | Graph से, या Show Commit Graph / Show Changesets List से बदलें।

  • List: डायरेक्ट कमिट अलग-अलग पंक्तियों के रूप में, इंटीग्रेशन (मर्ज और, कनेक्ट होने पर, रीबेस-मर्ज की गई पुल रिक्वेस्ट) विस्तृत किए जा सकने वाले समूहों के रूप में। हर पंक्ति की दूसरी लाइन में छोटा SHA, लेखक, तिथि, risk और वे environments दिखते हैं जिनमें बदलाव पहले से मौजूद है। किसी कमिट के बदलाव खोलने के लिए उस पर क्लिक करें; किसी समूह के संयुक्त बदलाव खोलने के लिए पंक्ति के डिफ़ बटन या कॉन्टेक्स्ट मेन्यू का उपयोग करें।
  • Graph: हर कमिट अपनी लेन के साथ; दूसरी लाइन की चिप बताती है कि कौन-सा चेंजसेट उस कमिट को ब्रांच में लाया।

हेडर में रिपॉज़िटरी और ब्रांच (बदलने के लिए क्लिक करें), सर्च बॉक्स, हटाए जा सकने वाले चिप के रूप में सक्रिय फ़िल्टर, चेतावनियाँ, एंट्री की संख्या और कनेक्शन की स्थिति दिखती है। किसी पंक्ति की कार्रवाइयों के लिए उस पर राइट-क्लिक करें: बदलाव खोलें, वह कहाँ आया, पुल रिक्वेस्ट खोलें, SHA कॉपी करें। कीबोर्ड: ऊपर-नीचे जाने के लिए ↑ ↓, संक्षिप्त और विस्तृत करने के लिए ← →, खोलने के लिए Enter।

Environments

कहाँ क्या डिप्लॉय है, और ब्रांच के कौन-से इंटीग्रेशन वहाँ अभी डिप्लॉय नहीं हुए। किसी एंट्री को दिखाने के लिए उस पर क्लिक करें; इनलाइन कार्रवाई Changesets व्यू को “इस एनवायरनमेंट में अभी क्या नहीं है” पर ले जाती है।

एनवायरनमेंट या तो एक ब्रांच है जो डिप्लॉय किए गए कोड की ओर इशारा करती है (उदाहरण के लिए origin/production), या एक टैग पैटर्न जिसका नवीनतम टैग डिप्लॉय किया गया वर्शन है (उदाहरण के लिए prod-*)। बिना कॉन्फ़िगरेशन के, production, staging, test या develop नाम की ब्रांच और रिलीज़ टैग पहचाने जाते हैं; कनेक्शन होने पर होस्टिंग सेवा के नवीनतम सफल डिप्लॉयमेंट भी जोड़े जाते हैं। इन्हें mergecat.environments.definitions से कॉन्फ़िगर करें:

"mergecat.environments.definitions": [
  { "name": "Production", "tagPattern": "prod-*" },
  { "name": "Staging", "ref": "origin/staging" }
]

Connections

होस्टिंग कनेक्टर (GitHub, GitLab, Azure DevOps; Bitbucket जल्द आ रहा है), हर एक में कैसे साइन इन किया गया है, और कनेक्ट करने से क्या जुड़ता है। कौन-सा कनेक्टर उपयोग होगा, यह रिपॉज़िटरी का रिमोट तय करता है।

रिपॉज़िटरी पेज

पाँच पेज एडिटर टैब के रूप में खुलते हैं: Changesets हेडर के नीचे के बटनों (Branches · Tags · PRs · Pipelines · Deploys) से, व्यू के … मेन्यू से, या mergecat: Open … कमांड से।

पेजयह क्या दिखाता हैकनेक्शन
Branchesहर लोकल ब्रांच और बिना लोकल कॉपी वाली रिमोट ब्रांच: आने वाले और जाने वाले कमिट, not on origin, upstream deleted, बेस से आगे/पीछे, merged, बेस के साथ कॉन्फ़्लिक्ट (फ़ाइलें सूचीबद्ध), उम्र। Fetch git fetch --all --prune --tags चलाता है।लोकल
Tagsनाम, कमिट, तिथि, टैगर, संदेश, एनोटेटेड या लाइटवेट, वर्शन, origin पर या Push बटन के साथ local only। New tag टाइप करते समय नाम जाँचता है और टैग को पुश कर सकता है।लोकल
Pull Requestsखुली, बंद या सभी, स्थिति, रिव्यूअर और वोट, चेक के साथ; कमिट और लिंक किए गए इश्यू के साथ विवरण। New pull request कमिट से शीर्षक और विवरण पहले से भर देता है।कनेक्टेड
PipelinesGitHub Actions, GitLab CI/CD और Azure Pipelines: Activity (स्टेज, जॉब, स्टेप, निर्भरताएँ), Text (YAML) और Runs (हर जॉब की स्थिति और अवधि)।कनेक्टेड
Deploymentsहर एनवायरनमेंट का लाइव डिप्लॉयमेंट और पिछले डिप्लॉयमेंट उनके टैग के साथ; रिलीज़ नोट्स और ऑडिट रिपोर्ट के साथ Compare environments; हर डिप्लॉयमेंट क्या लाया।कनेक्टेड

कनेक्शन के बिना, Deployments पेज लोकल रूप से मिले एनवायरनमेंट (सेटिंग्स, ब्रांच और टैग के नाम) दिखाता है और उनकी तुलना उसी तरह करता है।

इनसाइट्स

  • Changeset blame: mergecat: Toggle Changeset Blame (एडिटर टाइटल बार में भी) कर्सर वाली लाइन पर वह इंटीग्रेशन दिखाता है जो उसे विश्लेषित ब्रांच में लाया: पुल रिक्वेस्ट या मर्ज की गई ब्रांच, शीर्षक, तिथि और वे एनवायरनमेंट जहाँ तक वह पहुँची। होवर में कमिट, इंटीग्रेटर, स्वीकृतियाँ और लिंक किए गए इश्यू (कनेक्ट होने पर), पहला रिलीज़ टैग और जोखिम भी दिखते हैं।
  • Changesets That Shaped This File उन इंटीग्रेशन को सूचीबद्ध करता है जिन्होंने वर्तमान फ़ाइल लिखी, सबसे बड़े हिस्से वाले पहले।
  • हर इंटीग्रेशन का जोखिम: एक स्कोर, जो आकार, बहुत सारी फ़ाइलों, संवेदनशील क्षेत्रों, बिना टेस्ट के बदले गए कोड, बिना पुल रिक्वेस्ट के डायरेक्ट कमिट और लोकल मर्ज, बिना स्वीकृति के मर्ज (कनेक्ट होने पर) और revert से बनता है। Filter… › Risk… से फ़िल्टर करें। फ़ैक्टर चेंज ऑडिट रिपोर्ट में सूचीबद्ध हैं।
  • Metrics: mergecat: Show Metrics आए हुए बदलाव, पुल रिक्वेस्ट से आए बदलावों का हिस्सा, लीड टाइम, बदलाव का आकार, revert, लेखक, हर हफ़्ते या महीने की गतिविधि, जोखिम का वितरण और शीर्ष योगदानकर्ता दिखाता है। GitHub से कनेक्ट होने पर इसमें मर्ज होने तक का समय भी जुड़ता है।

ऑडिट रिपोर्ट

mergecat: Export Audit Report… चलाएँ (Command Palette से या Changesets व्यू के … मेन्यू से) और दायरा चुनें: वर्तमान व्यू, Between two releases…, Between two environments… या किसी एनवायरनमेंट के लिए Not yet in। HTML, Markdown, CSV या JSON चुनें और यह भी कि इसे कहाँ सहेजना है। Deployments पेज Compare environments के बदलावों के लिए यही रिपोर्ट देता है।

स्वीकृतियाँ होस्टिंग सेवा से आती हैं: कनेक्शन के बिना कमांड चेतावनी देती है कि उन्हें “unknown” के रूप में दिखाया जाएगा, और कनेक्ट करने का विकल्प देती है। विवरण: चेंज ऑडिट रिपोर्ट।

हर सेवा के लिए साइन-इन

Connections व्यू, Changesets हेडर की Local only · Connect पिल, या mergecat: Connect… से कनेक्ट करें।

Azure DevOps (dev.azure.com)VS Code के Microsoft अकाउंट के साथ Sign in with Microsoftतब काम करता है जब Azure DevOps संगठन Microsoft Entra ID (वर्क या स्कूल अकाउंट) से जुड़ा हो
Azure DevOps (विकल्प, Azure DevOps Server के लिए भी)पर्सनल एक्सेस टोकनस्कोप Code (Read & write), Build (Read), Environment (Read & manage), Work Items (Read)
GitLab (gitlab.com)पर्सनल एक्सेस टोकनस्कोप api (पढ़ने के लिए read_api काफ़ी है; मर्ज रिक्वेस्ट बनाने के लिए api ज़रूरी है)
GitLab (वैकल्पिक)ब्राउज़र में Sign in with GitLab (GitLab 17.2 या नया वर्शन)mergecat.gitlab.clientId में किसी non-confidential OAuth एप्लिकेशन की एप्लिकेशन ID चाहिए

पर्सनल एक्सेस टोकन और GitLab साइन-इन टोकन VS Code के SecretStorage में संग्रहीत होते हैं, हर सेवा और होस्ट के लिए एक, और कभी सेटिंग्स या लॉग में नहीं। Connections व्यू से डिस्कनेक्ट करें। यह भी देखें: सिक्योरिटी और प्राइवेसी।

सेटिंग्स

सेटिंगडिफ़ॉल्टविवरण
mergecat.gitPathख़ालीGit एक्ज़ीक्यूटेबल। ख़ाली: बिल्ट-इन Git एक्सटेंशन का git.path, फिर सामान्य इंस्टॉल लोकेशन
mergecat.pageSize200एक बार में लोड होने वाली टॉप-लेवल एंट्री (20 से 5000)
mergecat.hideForwardIntegrationMergestrueसमूहों के अंदर मुख्य ब्रांच के फ़ीचर ब्रांच में हुए मर्ज छिपाएँ
mergecat.defaultBranchख़ालीरिपॉज़िटरी खुलने पर विश्लेषित होने वाली ब्रांच, जैसे origin/main। ख़ाली: रिमोट की डिफ़ॉल्ट ब्रांच, फिर main/master, फिर वर्तमान ब्रांच
mergecat.repositoryScanDepth2खोला गया फ़ोल्डर रिपॉज़िटरी न होने पर रिपॉज़िटरी के लिए खोजे जाने वाले सबफ़ोल्डरों के स्तर (0 से 5; 0 = केवल खोला गया फ़ोल्डर)
mergecat.environments.definitions[]एनवायरनमेंट: { "name", "ref" } या { "name", "tagPattern" }
mergecat.environments.autoDetecttrueजब कोई एनवायरनमेंट कॉन्फ़िगर न हो, तो ब्रांच नामों और रिलीज़ टैग से एनवायरनमेंट का अनुमान लगाएँ
mergecat.risk.sensitiveAreas[]जोखिम स्कोर के डिफ़ॉल्ट संवेदनशील क्षेत्रों को बदलें; हर आइटम { "id", "label", "points", "patterns" }। ख़ाली: डिफ़ॉल्ट
mergecat.risk.testPatterns[]“no tests changed” फ़ैक्टर के लिए टेस्ट फ़ाइलों के glob। ख़ाली: डिफ़ॉल्ट
mergecat.gitlab.clientIdख़ालीSign in with GitLab के लिए GitLab OAuth एप्लिकेशन की एप्लिकेशन ID। ख़ाली: पर्सनल एक्सेस टोकन

कस्टम संवेदनशील क्षेत्रों का उदाहरण:

"mergecat.risk.sensitiveAreas": [
  { "id": "billing", "label": "Billing", "points": 3, "patterns": ["src/billing/**"] }
]

डेस्कटॉप ऐप से अंतर

दोनों ऐप एक ही इंजन से एक ही इतिहास पढ़ते हैं और इनके रिपॉज़िटरी पेज एक जैसे हैं। अंतर ये हैं:

VS Code एक्सटेंशनडेस्कटॉप ऐप
चेंजसेट व्यूसाइडबार व्यू, डिफ़ VS Code के diff editor मेंविवरण पैनल के साथ पूरी विंडो
Changeset blame, Changesets That Shaped This Fileहाँनहीं
मेट्रिक्स पैनलहाँनहीं
हर पंक्ति पर जोखिम और एनवायरनमेंटहाँनहीं
एनवायरनमेंट की परिभाषाएँmergecat.environments.definitionsहोस्टिंग सेवा के डिप्लॉयमेंट से
ऑडिट रिपोर्ट में एनवायरनमेंट कॉलमभरा हुआख़ाली
GitHub साइन-इनVS Code का GitHub अकाउंटGitHub से साइन इन करें (OAuth app), GitHub CLI या टोकन
Azure DevOps साइन-इनVS Code का Microsoft अकाउंट या टोकनMicrosoft से साइन इन करें (Entra ID ऐप) या टोकन
क्रेडेंशियल स्टोरेजVS Code अकाउंट और SecretStorageऑपरेटिंग सिस्टम की कीचेन

डेस्कटॉप ऐप के लिए देखें इंस्टॉलेशन और इतिहास। दोनों की ज्ञात सीमाएँ सीमाएं और इंटीग्रेशन स्टाइल पर हैं।
