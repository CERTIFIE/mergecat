Server MCP e strumenti

Riferimento del server MCP di mergecat: ogni strumento con i suoi parametri, il blocco di conformità, le variabili d'ambiente e come usare il server senza il plugin.

Modifica su GitHub

Tradotta dall'inglese con l'aiuto dell'IA. In caso di dubbio fa fede la versione inglese.

Il server MCP di mergecat fornisce a un assistente AI i changeset di un branch, i suoi tag e le sue release, e bozze Keep a Changelog. Gira in locale su stdio, legge il repository con il tuo Git e non lo modifica mai. Il plugin per Claude Code lo installa insieme alle skill; puoi anche aggiungerlo da solo e usarlo con GitHub Copilot, OpenAI Codex e GitLab Duo.

Nomi degli strumenti

Installato comeNomi degli strumenti in Claude Code
Pluginmcp__plugin_mergecat_mergecat__<tool>
Server autonomo chiamato mergecatmcp__mergecat__<tool>

Blocco di conformità

Gli strumenti per il repository (repository_info, tags, changelog, changesets, where_entered) sono bloccati finché alla domanda di conformità della sessione non è stata data una risposta con esito proceed. Finché sono bloccati restituiscono un errore con le domande da porre e l’istruzione di chiamare record_compliance_answer; non leggono nulla.

compliance_status, record_compliance_answer e render_pdf non sono bloccati: non leggono la cronologia del repository.

Una risposta per sessione

La risposta è conservata nella memoria del processo del server. Claude Code, come gli altri client, avvia un processo per sessione, quindi ogni nuova sessione pone di nuovo la domanda, e ogni risposta viene scritta come registro di audit. La domanda nomina il servizio AI del client: un account Claude Team o Enterprise in Claude Code, una licenza GitHub Copilot Business o Enterprise in Copilot, e così via (vedi la domanda di ciascun assistente). Vedi Registri di utilizzo dell’AI.

Quale repository

Ogni strumento per il repository accetta un parametro facoltativo repository: il percorso di un repository Git (qualsiasi cartella al suo interno). Senza di esso, il server usa, in questo ordine:

  1. MERGECAT_REPOSITORY;
  2. CLAUDE_PROJECT_DIR (il progetto di Claude Code);
  3. le cartelle aperte nel client, quando le comunica ai server MCP (VS Code lo fa): la prima che è un repository Git;
  4. la directory corrente del server.

Strumenti

compliance_status

Indica se alla domanda di conformità è stata data risposta in questa sessione, e le domande esatte da porre. Nessun parametro. Non legge il repository.

Restituisce aiService (il servizio AI a cui si riferiscono le domande), confirmed, askedThisSession, lastOutcome, lastRecordedAt, lastRecordFile, questions.account, questions.proceedIfNotTeamOrEnterprise e recordsFolder. Descrizione dei campi: Registri di utilizzo dell’AI.

record_compliance_answer

Registra le risposte date dall’utente nella conversazione come registro di audit su questo computer (documento Markdown e log JSON Lines) e, quando l’esito è proceed, sblocca gli strumenti per il repository per la sessione.

ParametroTipoObbligatorioDescrizione
team_or_enterprise_accountbooleansìtrue se l’utente usa il piano business o enterprise nominato nella prima domanda (in Claude Code: un account Claude Team o Enterprise)
aware_and_proceedbooleanquando la prima risposta è falsetrue se l’utente è a conoscenza dell’AI Act UE (il regolamento europeo sull’intelligenza artificiale) e della direttiva NIS2 e vuole procedere comunque
requested_actionstringsìCiò che l’utente ha chiesto, es. changelog v1.2.0..v1.3.0 o tags
answers_verbatimstringnoLe risposte dell’utente così come le ha scritte, o le opzioni scelte
languagestringnoLingua in cui sono state poste le domande (ISO 639-1)
ai_modelstringnoL’ID del modello dell’assistente
repositorystringnoPercorso del repository

Restituisce l’esito, l’ID del registro, i percorsi del registro e del log, e il registro in Markdown. Quando l’esito è stopped, quel Markdown omette i dettagli su utente, computer e repository.

render_pdf

Converte un documento Markdown (un changelog, note di rilascio, un registro di conformità) in un file PDF. Non legge il repository.

ParametroTipoObbligatorioDescrizione
markdownstringsìIl documento Markdown (fino a 2.000.000 di caratteri)
file_namestringnoNome del file, es. changelog-web-v1.3.0.pdf. Predefinito: ricavato dal titolo
folderstringnoCartella assoluta per il file. Predefinita: mergecat nella cartella temporanea di sistema
titlestringnoTitolo del documento per i metadati del PDF e il piè di pagina. Predefinito: il primo titolo #
allow_in_projectbooleannoConsente di scrivere nella cartella del progetto; solo quando l’utente ha chiesto di salvare lì il PDF

Il server si rifiuta di scrivere all’interno del progetto (la cartella indicata in Quale repository) a meno che non sia impostato allow_in_project. Il nome del file conserva lettere, cifre, ., _ e -. Restituisce file, pages e bytes. Per i limiti dei font vedi Changelog.

repository_info

Il branch predefinito, il branch corrente, il servizio di hosting e i tag di versione sul branch predefinito con le loro date (dal più recente, fino a 30). Indica anche se sono disponibili i dati delle pull request (GitHub (GITHUB_TOKEN set) o none (local Git data only)), l’ultimo fetch e se il clone è shallow.

ParametroTipoObbligatorioDescrizione
repositorystringnoPercorso del repository

tags

Ogni tag, dal più recente: data, commit, annotato o leggero, messaggio, autore del tag, se sembra una versione e se è sul branch. Per i tag di versione sul branch: il tag di versione precedente e il numero di changeset da quel tag. Inoltre il numero di changeset non ancora rilasciati e il tag di versione più recente.

ParametroTipoObbligatorioDescrizione
repositorystringnoPercorso del repository
branchstringnoBranch da cui vengono fatte le release. Predefinito: il branch predefinito
patternstringnoTesto contenuto nel nome, oppure un glob con * e ? (es. v2.*); senza distinzione tra maiuscole e minuscole
versions_onlybooleannoSolo i tag che sembrano versioni (v1.2.3, 1.2)
limitintegernoNumero massimo di tag, da 1 a 500. Predefinito 50

changelog

Una bozza Keep a Changelog di ciò che è entrato nel branch, una riga per changeset, raggruppata per release (tag di versione) e per sezione (Added, Changed, Deprecated, Removed, Fixed, Security). Restituisce la bozza Markdown e dati strutturati: per ogni changeset la sezione e il motivo, numero e link della pull request, il branch, i commit e i flag breaking e internal; per un intervallo, come è stato risolto ogni estremo; note come estremi invertiti o dati delle pull request mancanti.

ParametroTipoObbligatorioDescrizione
repositorystringnoPercorso del repository
branchstringnoBranch di cui si descrive la cronologia. Predefinito: il branch predefinito (es. origin/main)
rangestringnoUn intervallo from..to (anche [from..to]); ogni estremo è un tag, una data (YYYY-MM-DD, facoltativamente con un’ora) o un commit; estremi aperti ammessi (v1.3.0.., ..v1.0.0)
fromstringnoInizio di un intervallo, escluso: tag, data o commit
tostringnoFine di un intervallo, inclusa: tag, data o commit. Predefinito: il branch
max_releasesintegernoRelease da includere quando non è indicato un intervallo, da 0 a 100. Predefinito 5
unreleased_onlybooleannoSolo le modifiche dopo il tag di versione più recente
include_internalbooleannoElenca nel Markdown anche documentazione, test, CI e attività varie. Predefinito false (restano comunque nei dati)
headerbooleannoInizia con il titolo # Changelog e il preambolo di Keep a Changelog
languagestringnoCodice ISO 639-1. Predefinito en. Le intestazioni sono tradotte per en, it, de, fr, es; per le altre lingue restano in inglese e i dati riportano headingsTranslated: false

Indica range oppure from/to, non entrambi. Lo strumento non traduce mai le descrizioni delle modifiche.

changesets

Ciò che è entrato in un branch, dal più recente, raggruppato per integrazione: pull request integrate e merge con i commit che hanno portato, e commit diretti. Restituisce anche gli avvisi della cronologia (clone shallow, nessun merge, squash merge).

ParametroTipoObbligatorioDescrizione
repositorystringnoPercorso del repository
branchstringnoBranch da descrivere. Predefinito: il branch predefinito
basestringnoSolo ciò che è entrato dopo questo tag, branch o commit
sincestringnoData di integrazione iniziale, YYYY-MM-DD
untilstringnoData di integrazione finale, YYYY-MM-DD
searchstringnoTesto nell’oggetto, nello SHA, nel nome del branch o nel titolo della pull request (anche all’interno dei gruppi)
authorstringnoNome o e-mail dell’autore o di chi ha eseguito l’integrazione
limitintegernoNumero massimo di voci, da 1 a 500. Predefinito 50

where_entered

Per un commit: l’integrazione (pull request, merge o commit diretto) che l’ha portato nel branch, quando, chi l’ha integrato e il primo tag che lo contiene.

ParametroTipoObbligatorioDescrizione
repositorystringnoPercorso del repository
shastringsìSHA del commit, almeno 7 caratteri esadecimali
branchstringnoBranch. Predefinito: il branch predefinito

Dati delle pull request

Con un token del servizio di hosting del repository nell’ambiente, gli strumenti aggiungono titoli, numeri, etichette e issue collegate delle pull request (merge request): GITHUB_TOKEN (o GH_TOKEN) per GitHub, GITLAB_TOKEN (o GL_TOKEN) per GitLab, AZURE_DEVOPS_EXT_PAT (un token di accesso personale) o AZURE_DEVOPS_TOKEN (un token di Microsoft Entra) per Azure DevOps. Senza token usano solo i dati Git locali e indicano quale variabile impostare.

Usare il server senza il plugin

Il server è anche un normale server MCP: niente skill, strumenti chiamati mcp__mergecat__<tool>. Le sue istruzioni dicono al client di porre la domanda di conformità e di consegnare i documenti all’utente nella conversazione, non come file nel progetto.

Procurati il server

Scarica il file singolo mergecat-mcp.cjs dalla sezione download, oppure compilalo da un clone con npm run mcp:build (viene scritto in plugins/mergecat/server/mergecat-mcp.cjs). Richiede Node.js 20 o successivo.

Aggiungilo a Claude Code

claude mcp add --transport stdio --scope user mergecat -- node /path/to/mergecat-mcp.cjs

Per passare variabili d’ambiente, aggiungi -e NAME=value prima di --, per esempio -e MERGECAT_COMPLIANCE_DIR=/path/to/records.

Verificalo

Avvia Claude Code in un repository Git ed esegui /mcp: il server mergecat dovrebbe risultare connesso. Il server scrive i log su stderr e all’avvio stampa mergecat MCP server 0.3.0 ready.

Gli altri client MCP che avviano server stdio lo eseguono allo stesso modo, node /path/to/mergecat-mcp.cjs: per GitHub Copilot, OpenAI Codex e GitLab Duo vedi Altri assistenti AI. Fuori da Claude Code CLAUDE_PROJECT_DIR non è impostata: il server usa le cartelle aperte nel client quando il client le comunica, altrimenti imposta MERGECAT_REPOSITORY o passa repository agli strumenti.

Variabili d’ambiente

VariabileEffetto
GITHUB_TOKENToken GitHub per i dati delle pull request; quando GITHUB_TOKEN non è impostata viene usata GH_TOKEN
GITLAB_TOKENToken GitLab (read_api) per i dati delle merge request; quando GITLAB_TOKEN non è impostata viene usata GL_TOKEN
AZURE_DEVOPS_EXT_PATToken di accesso personale di Azure DevOps per i dati delle pull request; AZURE_DEVOPS_TOKEN accetta invece un token di Microsoft Entra
MERGECAT_AI_SERVICEIl servizio AI a cui si riferisce la domanda di conformità, quando il client non viene riconosciuto: claude, copilot, openai, gitlab-duo o un altro nome
MERGECAT_GIT_PATHEseguibile di Git, quando git non è nel PATH
MERGECAT_COMPLIANCE_DIRCartella dei registri di utilizzo dell’AI al posto della cartella predefinita
MERGECAT_REPOSITORYRepository usato quando uno strumento non riceve il parametro repository; è anche la cartella del progetto che render_pdf protegge
CLAUDE_PROJECT_DIRImpostata da Claude Code: il progetto, usato quando non sono indicati né il parametro né MERGECAT_REPOSITORY

In Claude Code, il plugin passa le variabili dei token elencate sopra, MERGECAT_GIT_PATH e MERGECAT_COMPLIANCE_DIR dall’ambiente in cui avvii Claude Code.
