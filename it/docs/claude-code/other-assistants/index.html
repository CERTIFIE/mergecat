Altri assistenti AI

Usa il plugin e il server MCP di mergecat con GitHub Copilot, OpenAI Codex e GitLab Duo, con la domanda di conformità di ciascun servizio, il repository e i dati delle pull request.

Modifica su GitHub

Tradotta dall'inglese con l'aiuto dell'IA. In caso di dubbio fa fede la versione inglese.

Il plugin mergecat non è solo per Claude Code. La stessa cartella è anche un pacchetto Agent Plugins portabile, con le due skill (changelog e tag, nel formato SKILL.md) e il server MCP di mergecat. GitHub Copilot, OpenAI Codex e GitLab Duo caricano queste skill e avviano server MCP locali, quindi gli stessi strumenti e gli stessi passaggi funzionano anche lì.

Perché non ChatGPT

ChatGPT si connette solo a server MCP remoti, raggiungibili tramite internet. mergecat legge il repository sul tuo computer e non lo invia mai a un proprio server. Usa Codex, che esegue il server mergecat in locale e funziona con lo stesso account ChatGPT.

La domanda di conformità di ciascun assistente

Il server MCP riconosce l’assistente dal nome che la sua applicazione client comunica al momento della connessione, e chiede dei piani business di quel servizio. Ogni risposta viene salvata come registro di utilizzo dell’AI che indica il servizio e l’applicazione client.

AssistenteLa prima domanda chiede se usi
Claudeun account Claude Team o Enterprise
GitHub Copilotuna licenza GitHub Copilot Business o Enterprise
OpenAI (ChatGPT, Codex)un workspace ChatGPT Business, Enterprise o Edu, oppure una chiave API OpenAI di un’organizzazione
GitLab DuoGitLab Duo con un abbonamento GitLab a pagamento (Premium o Ultimate)
Qualsiasi altro clientun piano business o enterprise di quel client

Se l’assistente non viene riconosciuto, o se vuoi esserne sicuro, imposta MERGECAT_AI_SERVICE nella configurazione del server: claude, copilot, openai, gitlab-duo oppure il nome di un altro servizio. Le configurazioni per GitLab Duo riportate sotto la impostano.

GitHub Copilot

In VS Code, con l’estensione mergecat

Con l’estensione mergecat per VS Code installata, VS Code 1.101 e successivi offrono a Copilot il server MCP di mergecat senza alcuna configurazione. Il server è incluso nell’estensione e gira con il runtime di VS Code, quindi Node.js non serve. Legge la cartella aperta in VS Code e pone la domanda di GitHub Copilot.

L’estensione aggiunge gli strumenti, non le skill. Per avere anche le skill, installa il plugin (sezione successiva) e disattiva l’impostazione mergecat.copilot.mcpServer, così Copilot non riceve due copie del server.

Il plugin, in VS Code e in Copilot CLI

Copilot legge i marketplace di plugin nel formato di Claude Code, come quello del repository mergecat. In VS Code, aggiungi il repository all’impostazione chat.plugins.marketplaces (sperimentale), come owner/repo per un repository GitHub o come URL Git, poi installa mergecat da lì. Il plugin avvia il server con node: Node.js 20 o successivo deve essere nel PATH.

Configurazione senza il plugin

Copilot in VS Code e Copilot CLI condividono la configurazione nativa: ~/.copilot/mcp-config.json per il tuo utente, oppure .mcp.json nella radice di un workspace. Usa il file singolo mergecat-mcp.cjs dalla sezione download:

{
  "mcpServers": {
    "mergecat": {
      "type": "stdio",
      "command": "node",
      "args": ["/path/to/mergecat-mcp.cjs"],
      "env": { "GITHUB_TOKEN": "${GITHUB_TOKEN}" },
      "tools": ["*"]
    }
  }
}

Copilot Business e Enterprise

Sono le organizzazioni a decidere se Copilot può usare server MCP: per le licenze Copilot Business ed Enterprise la policy è disattivata per impostazione predefinita. Chiedi a un owner dell’organizzazione di consentirlo.

OpenAI Codex

Il plugin

Anche Codex legge i marketplace di plugin nel formato di Claude Code. Aggiungi il repository mergecat (o un suo clone locale) come marketplace:

codex plugin marketplace add CERTIFIE/mergecat

Poi installa mergecat dai plugin dell’app desktop di ChatGPT e abilitalo per un progetto in .codex/config.toml:

[plugins."mergecat@mergecat"]
enabled = true

Configurazione senza il plugin

Aggiungi il server a ~/.codex/config.toml. env_vars passa i token dall’ambiente in cui è stato avviato Codex, senza scriverli nel file:

[mcp_servers.mergecat]
command = "node"
args = ["/path/to/mergecat-mcp.cjs"]
env_vars = ["GITHUB_TOKEN", "GITLAB_TOKEN", "AZURE_DEVOPS_EXT_PAT"]

Per le skill, copia le cartelle plugins/mergecat/skills/changelog e plugins/mergecat/skills/tags del repository mergecat in ~/.agents/skills/ (per il tuo utente) o in .agents/skills/ in un repository.

GitLab Duo

GitLab Duo Agentic Chat usa i server MCP in VS Code, negli IDE JetBrains e nella GitLab Duo CLI.

Consenti gli strumenti MCP esterni

Un Owner del gruppo di primo livello attiva Allow external MCP tools nelle impostazioni GitLab Duo del gruppo (su GitLab Self-Managed anche il feature flag mcp_client, per i flow e gli agenti personalizzati).

Aggiungi il server

Scrivi ~/.gitlab/duo/mcp.json (su Windows: %APPDATA%\GitLab\duo\mcp.json), oppure .gitlab/duo/mcp.json in un progetto:

{
  "mcpServers": {
    "mergecat": {
      "type": "stdio",
      "command": "node",
      "args": ["/path/to/mergecat-mcp.cjs"],
      "env": { "MERGECAT_AI_SERVICE": "gitlab-duo" },
      "approvedTools": ["compliance_status", "repository_info", "tags", "changelog", "changesets", "where_entered"]
    }
  }
}

approvedTools approva una volta per tutte gli strumenti in sola lettura; record_compliance_answer e render_pdf, che scrivono file sul tuo computer, chiedono comunque conferma. Riavvia l’IDE o la Duo CLI.

Aggiungi le skill

Copia le cartelle plugins/mergecat/skills/changelog e plugins/mergecat/skills/tags in .agents/skills/ nel progetto (o nella cartella delle skill utente della GitLab Duo CLI). GitLab Duo le carica nelle nuove conversazioni.

Per titoli, etichette e issue collegate delle merge request, avvia l’IDE o la CLI con GITLAB_TOKEN impostato (un token con lo scope read_api).

Quale repository

Fuori da Claude Code, il server trova il repository in questo ordine: il parametro repository dello strumento, MERGECAT_REPOSITORY, le cartelle aperte nel client (VS Code le comunica ai server MCP; con più cartelle, il primo repository Git), poi la directory di lavoro del server.

Dati delle pull request

Gli strumenti aggiungono i dati delle pull request (merge request) quando nell’ambiente del server c’è un token del servizio di hosting del repository:

HostingVariabili
GitHubGITHUB_TOKEN, oppure GH_TOKEN
GitLabGITLAB_TOKEN, oppure GL_TOKEN
Azure DevOpsAZURE_DEVOPS_EXT_PAT (token di accesso personale), oppure AZURE_DEVOPS_TOKEN (token di Microsoft Entra)

Senza token, gli strumenti usano solo i dati Git locali e indicano quale variabile impostare. Non scrivere mai un token in un file di configurazione condiviso o di cui fai il commit: richiamalo invece dall’ambiente.
