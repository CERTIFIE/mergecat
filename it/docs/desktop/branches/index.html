Branch

Lo stato di ogni branch a colpo d'occhio, rispetto a origin e al branch di base, con conflitti di merge, filtri per età e un fetch sicuro.

Modifica su GitHub

Tradotta dall'inglese con l'aiuto dell'IA. In caso di dubbio fa fede la versione inglese.

Funziona offline

La pagina Branch elenca tutti i branch locali e i branch remoti che non hanno una copia locale, e per ognuno ti dice se è stato inviato con push, se è indietro, se è stato integrato o se è in conflitto con il branch di base. Legge il clone locale e non esegue mai checkout, merge o eliminazioni di branch. Aprila da Branch nella navigazione.

La pagina Branch: una riga per branch.

L’intestazione indica quanti branch ci sono, con quale branch di base e quale remote vengono confrontati e quando è stato eseguito l’ultimo fetch del repository.

Colonne

ColonnaCosa mostra
BranchIl nome; corrente per il branch su cui è fatto il checkout nel working tree, base per il branch di base. Sotto: l’upstream che traccia (tracks origin/x), “branch locale” oppure “branch remoto, nessuna copia locale”.
Ultimo commitOggetto, autore, età e SHA breve del commit più recente.
vs origin↓ commit da ricevere con pull e ↑ commit da inviare con push, oppure sincronizzato, non su origin (push mai eseguito), upstream eliminato (di solito dopo il merge della pull request) o solo su origin. Sotto: quando il branch remoto è stato aggiornato l’ultima volta qui, con un fetch o un push.
vs base↓ commit indietro e ↑ commit avanti rispetto al branch di base, integrato quando tutto il contenuto del branch è già nella base, e conflitti quando il merge nella base genererebbe conflitti. Sotto: il numero di file in conflitto, oppure “merge senza conflitti”.
EtàGiorni dall’ultimo commit. Arancione da 60 giorni, rosso da 90 giorni.

Passa il mouse su conflitti per vedere i file che andrebbero in conflitto.

Branch di base

Il selettore nell’intestazione imposta il branch rispetto al quale vengono calcolati vs base, integrato e conflitti. Parte dal branch predefinito del repository (di solito origin/main). Scegli per esempio un branch di release per vedere quali feature branch andrebbero in conflitto con esso.

Verifica dei conflitti

mergecat verifica ogni branch che si è discostato dalla base con git merge-tree, che calcola il merge senza toccare il tuo working tree o i tuoi branch. La verifica richiede Git 2.38 o successivo; con un Git più vecchio la pagina lo segnala e la colonna mostra invece “la verifica dei conflitti richiede Git 2.38”.

Filtri e ricerca

I chip sopra l’elenco filtrano le righe e mostrano quanti branch corrispondono:

FiltroBranch mostrati
TuttiBranch locali e branch remoti senza copia locale.
Solo localiBranch che esistono solo su questo computer.
Non su originPush mai eseguito, o eliminati sul remote.
IntegratiTutto il contenuto del branch è già nel branch di base.
ConflittiIl merge del branch nel branch di base genererebbe conflitti.
Più vecchi di 60 giorniUltimo commit più di 60 giorni fa.
Più vecchi di 90 giorniUltimo commit più di 90 giorni fa.

La casella di ricerca (Filtra per nome, autore…) trova il nome del branch e l’autore e l’oggetto dell’ultimo commit.

Integrati e i filtri per età sono un modo rapido per trovare i branch da ripulire; mergecat lascia a te l’eliminazione.

Fetch

Fetch esegue git fetch --all --tags --prune: aggiorna i branch remoti e i tag da tutti i remote e rimuove i branch remoti che sono stati eliminati sul server. I tuoi branch locali e il tuo working tree non vengono modificati. Il fetch usa le tue credenziali Git (il tuo credential helper); mergecat non chiede una password. Dopo un fetch i selettori dei branch e i chip dei tag di tutta l’app sono aggiornati.

Azioni sulle righe

Il pulsante ⋯ alla fine di ogni riga apre:

AzioneCosa fa
Copia nomeCopia il nome del branch.
Mostra cronologiaApre la pagina Cronologia su questo branch.
Crea tag sull’ultimo commit…Apre Nuovo tag sul commit più recente del branch.
Crea pull request…Apre Nuova pull request con questo branch come origine. Richiede una connessione; non disponibile per il branch di base.

Prossimi passi

Tag e release → Crea, annota ed esegui il push dei tag. Pull request → Apri una pull request da un branch.
