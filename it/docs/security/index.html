Compliance e audit

Sicurezza e privacy

Cosa modifica mergecat nel tuo repository, quali dati lasciano il tuo computer e verso dove, come vengono memorizzate le credenziali e cosa conserva mergecat in locale.

Modifica su GitHub

Tradotta dall'inglese con l'aiuto dell'IA. In caso di dubbio fa fede la versione inglese.

mergecat è uno strumento locale: legge i tuoi repository con il tuo Git, comunica solo con i servizi di hosting che connetti e non ha un proprio server. Questa pagina elenca cosa può modificare, quali dati lasciano il tuo computer, come memorizza le credenziali e cosa conserva su disco.

In sintesi

ArgomentoCome lo gestisce mergecat
RepositoryIn sola lettura per impostazione predefinita; scrive solo su comandi espliciti
ReteSolo i servizi di hosting che connetti (GitHub, GitLab, Azure DevOps) e le loro pagine di accesso; Claude solo tramite il plugin per Claude Code, dopo la risposta alla domanda di conformità
CredenzialiCifrate con il portachiavi del sistema operativo; solo in memoria quando non è disponibile alcun portachiavi
TelemetriaNessuna: niente statistiche di utilizzo, niente segnalazioni di crash, niente controlli degli aggiornamenti, nessun server mergecat
Dati localiImpostazioni, credenziali cifrate e una cache delle pull request nella cartella dati dell’app; mai nel repository

In sola lettura per impostazione predefinita

mergecat legge la cronologia con git log, git blame e comandi simili. Non esegue mai commit, checkout, merge o rebase né riscrive nulla, e non tocca mai il tuo working tree o i tuoi branch locali. Solo queste azioni modificano qualcosa, e solo quando sei tu ad avviarle:

AzioneCosa modificaDove
FetchEsegue git fetch --all --tags --prune: aggiorna i branch di tracciamento remoto e i tag, rimuove quelli eliminati sul remote. I branch e i file locali non vengono toccati.App desktop (pagina Branch), VS Code (pagina Branches, Fetch All Remotes)
Crea tagCrea un tag locale sul commit che scegli; annotato quando inserisci un messaggioApp desktop, VS Code (pagina Tags, Create Tag…, Create Tag Here…)
Push del tagEsegue il push di quel singolo tag sul remoteApp desktop, VS Code (pagina Tags)
Crea pull requestCrea una pull request (su GitLab: merge request) sul servizio di hostingApp desktop, VS Code (pagina Pull requests, Create Pull Request…)

Le esportazioni e i report di audit vengono scritti solo dove li salvi. Il server MCP del plugin per Claude Code non modifica mai il repository: scrive solo i registri di utilizzo dell’AI e, su richiesta, file PDF fuori dal progetto. Claude aggiorna CHANGELOG.md solo quando lo chiedi esplicitamente.

Come mergecat esegue Git:

  • con il tuo eseguibile git, avviato direttamente, mai tramite una shell;
  • con GIT_TERMINAL_PROMPT=0: il fetch e il push dei tag usano il tuo credential helper o la tua chiave SSH e non chiedono mai una password;
  • con GIT_OPTIONAL_LOCKS=0, così la lettura non acquisisce i lock facoltativi di Git.

Dati che lasciano il tuo computer

DestinazioneQuandoCosa
I tuoi remote GitFetch e push dei tagTutto ciò che Git scambia, con le tue credenziali Git
API dei servizi di hosting: GitHub, GitLab, Azure DevOpsSolo quando il servizio è connessoRichieste di pull request, approvazioni, issue collegate, pipeline e deployment del repository; le pull request che crei
Pagine di accesso: github.com, login.microsoftonline.com, la tua istanza GitLabQuando accedi con il browserL’accesso con device flow; lì si applicano l’SSO e l’MFA della tua organizzazione
Claude (Anthropic), oppure l’assistente AI in cui esegui il server MCP di mergecat (GitHub Copilot, OpenAI Codex, GitLab Duo)Solo tramite il server MCP di mergecat, dopo che la domanda di conformità lo ha consentitoMetadati della cronologia: messaggi di commit, nomi e indirizzi e-mail di autori e committer, date, nomi di branch e tag, SHA dei commit; con un token del servizio di hosting, titoli, numeri, etichette e issue collegate delle pull request

Nient’altro. mergecat non ha nessuna telemetria: non raccoglie statistiche di utilizzo e non invia segnalazioni di crash. Non controlla la presenza di aggiornamenti e non ha nessun server mergecat né account. L’app desktop include i propri font e non carica nulla da una CDN.

Gli strumenti MCP di mergecat forniscono a Claude i metadati della cronologia, non il contenuto dei tuoi file o dei diff. Claude Code stesso può leggere i file del tuo progetto secondo i propri permessi; per esempio, la skill del changelog legge CHANGELOG.md.

L'uso dell'AI viene registrato

Prima che vengano inviati i primi dati del repository in una sessione di Claude Code, mergecat chiede se usi un account Claude Team o Enterprise e registra la risposta. Vedi AI Act UE e NIS2.

Credenziali

App desktop

I token sono cifrati con il portachiavi del sistema operativo (safeStorage di Electron) e memorizzati in credentials.bin nella cartella dati dell’app.

La chiave di cifratura è conservata nel Keychain di macOS.

I dati sono cifrati con DPAPI di Windows per il tuo account utente.

La chiave di cifratura è conservata da un servizio di segreti (secret service): GNOME Keyring (libsecret) o KWallet. Senza, mergecat conserva le credenziali solo in memoria e mostra un avviso: dovrai connetterti di nuovo dopo aver riavviato l’app. Vedi Risoluzione dei problemi.

  • Quando non è disponibile alcun portachiavi, le credenziali sono conservate solo in memoria, mai scritte in chiaro.
  • L’accesso con la GitHub CLI non memorizza alcun token: mergecat esegue gh auth token quando ne ha bisogno.
  • I token di accesso dei flussi tramite browser vengono rinnovati prima della scadenza.
  • Disconnetti nella finestra Connessioni elimina la credenziale memorizzata di quel servizio.

Estensione per VS Code

  • GitHub e Azure DevOps (Sign in with Microsoft) usano gli account che VS Code gestisce già. Il token resta in VS Code; mergecat lo chiede a VS Code quando serve.
  • I token di accesso personale e i token di accesso a GitLab sono memorizzati nel SecretStorage di VS Code (basato sul portachiavi del sistema operativo), uno per servizio e host. Non vengono mai scritti nelle impostazioni o nei log.

Plugin per Claude Code e riga di comando

  • Il server MCP legge GITHUB_TOKEN (o GH_TOKEN) dal proprio ambiente, per i dati delle pull request dei repository su github.com. Non lo memorizza.
  • La riga di comando non usa alcun servizio di hosting e nessuna credenziale oltre alla tua configurazione di Git.

Privilegio minimo

Assegna ai token solo gli scope di cui mergecat ha bisogno. Per leggere servono scope di lettura; solo la creazione di pull request richiede l’accesso in scrittura (per esempio su GitLab read_api basta per leggere, api serve per creare merge request). Gli scope per ciascun servizio sono elencati in Connessioni.

mergecat non scrive mai cache o impostazioni nel tuo repository.

La cartella dati dell’app desktop:

~/Library/Application Support/mergecat/
%APPDATA%\mergecat\
~/.config/mergecat/

Oppure $XDG_CONFIG_HOME/mergecat/ quando XDG_CONFIG_HOME è impostata.

Per rimuovere tutto, disconnetti i servizi, chiudi l’app ed elimina questa cartella. Su macOS e Windows i registri di conformità si trovano nella sua sottocartella compliance: conservali se ti servono per gli audit.

Protezione dell’app desktop

  • Il contenuto della finestra viene eseguito in un renderer in sandbox, con isolamento del contesto e senza accesso a Node.js; comunica con il processo principale tramite un’interfaccia ristretta.
  • La finestra non esce mai dall’app. I link si aprono nel browser predefinito, e vengono aperti solo i link https://.
  • Viene eseguita una sola istanza dell’app alla volta.

Build non firmate

La firma del codice e la notarizzazione non sono ancora configurate, quindi macOS e Windows mostrano un avviso quando apri mergecat per la prima volta (come aprirlo). Prima di confermare:

  • scarica mergecat solo dalla pagina delle release del progetto o dalla sezione download;
  • confronta il checksum SHA-256 del file con quello pubblicato nella release (SHA256SUMS.txt, riportato anche nelle note di rilascio):
shasum -a 256 ~/Downloads/mergecat-mac-arm64.dmg
Get-FileHash "$HOME\Downloads\mergecat-windows-x64-setup.exe" -Algorithm SHA256
sha256sum ~/Downloads/mergecat-linux-x86_64.AppImage
  • se la tua policy non consente software non firmato, compila mergecat dai sorgenti (vedi Installazione) o attendi le release firmate.
