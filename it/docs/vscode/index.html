Integrazioni

Estensione per VS Code

Installa l'estensione mergecat per VS Code e usa le sue viste, le pagine del repository, i comandi e le impostazioni.

Modifica su GitHub

Tradotta dall'inglese con l'aiuto dell'IA. In caso di dubbio fa fede la versione inglese.

L’estensione mergecat porta in VS Code la vista dei changeset: la cronologia di un branch raggruppata per integrazione, le pagine del repository (branch, tag, pull request, pipeline, deployment) come schede dell’editor, il changeset blame, le metriche e il report di audit delle modifiche. Accede con gli account GitHub e Microsoft che VS Code conosce già.

Requisiti: VS Code 1.90 o successivo e Git. La verifica dei conflitti della pagina Branches richiede Git 2.38 o successivo.

Installazione

Non ancora sul Marketplace

L’estensione non è ancora pubblicata sul Visual Studio Marketplace. Installala dal file .vsix di una release, oppure compilala dai sorgenti.

Scarica mergecat-vscode.vsix dalla sezione download, poi installalo in uno di questi due modi.

Riga di comando:

code --install-extension mergecat-vscode.vsix

VS Code: apri la vista Estensioni, fai clic sul menu … in cima alla vista, scegli Install from VSIX… e seleziona il file.

Dalla radice di un clone del repository mergecat (Node.js 20 o successivo):

npm install
npm run vscode:install

Lo script compila l’estensione, ne crea il pacchetto e la installa in VS Code; trova il comando code anche quando non è nel PATH. Rieseguilo dopo ogni modifica. Per rimuovere l’estensione:

npm run vscode:install -- --uninstall

Poi esegui Developer: Reload Window, apri una cartella che contiene un repository Git e fai clic sull’icona mergecat nella barra delle attività.

Un'altra estensione con un nome simile

“MergeCat for VS Code” (mergecat.mergecat-vscode) sul Marketplace è un’estensione non correlata che registra gli stessi nomi di comandi e impostazioni. Non installarle entrambe. Se è installata, rimuovila:

code --uninstall-extension mergecat.mergecat-vscode

Viste

L’icona di mergecat nella barra delle attività apre tre viste.

Quale repository? Se la cartella aperta si trova all’interno di un repository Git, viene mostrato quel repository. Altrimenti mergecat cerca nelle sue sottocartelle (due livelli per impostazione predefinita, mergecat.repositoryScanDepth). Con un solo repository lo apre; con più repository mostra l’ultimo usato o quello del file aperto nell’editor, oppure ti chiede di scegliere (anche dal pulsante del repository nella barra del titolo).

Changeset

La cronologia raggruppata del branch selezionato, in due layout. Passa dall’uno all’altro con List | Graph nell’intestazione, oppure con Show Commit Graph / Show Changesets List.

  • List: i commit diretti come righe singole, le integrazioni (merge e, se connesso, pull request integrate con rebase merge) come gruppi da espandere. La seconda riga di ogni voce mostra SHA breve, autore, data, rischio e gli ambienti che contengono già la modifica. Fai clic su un commit per aprirne le modifiche; usa il pulsante diff della riga o il menu contestuale per aprire le modifiche combinate di un gruppo.
  • Graph: ogni commit con le sue linee; il chip sulla seconda riga indica quale changeset ha portato il commit nel branch.

L’intestazione mostra repository e branch (fai clic per cambiarli), la casella di ricerca, i filtri attivi come chip rimovibili, gli avvisi, il numero di voci e lo stato della connessione. Fai clic destro su una riga per le sue azioni: aprire le modifiche, vedere dove è entrata, aprire la pull request, copiare lo SHA. Tastiera: ↑ ↓ per spostarti, ← → per comprimere ed espandere, Enter per aprire.

Ambienti

Cosa è distribuito e dove, e quali integrazioni del branch non vi sono ancora distribuite. Fai clic su una voce per mostrarla; l’azione inline passa la vista Changesets a “cosa non è ancora in questo ambiente”.

Un ambiente è un branch che punta al codice distribuito (per esempio origin/production) oppure un pattern di tag il cui tag più recente è la versione distribuita (per esempio prod-*). Senza configurazione, vengono rilevati i branch chiamati production, staging, test o develop e i tag di release; con una connessione, si aggiungono gli ultimi deployment riusciti del servizio di hosting. Configurali con mergecat.environments.definitions:

"mergecat.environments.definitions": [
  { "name": "Production", "tagPattern": "prod-*" },
  { "name": "Staging", "ref": "origin/staging" }
]

Connessioni

I connettori di hosting (GitHub, GitLab, Azure DevOps; Bitbucket in arrivo), il modo in cui è stato eseguito l’accesso a ciascuno e cosa aggiunge la connessione. Il remote del repository determina quale connettore viene usato.

Pagine del repository

Cinque pagine si aprono come schede dell’editor: dai pulsanti sotto l’intestazione di Changesets (Branches · Tags · PRs · Pipelines · Deploys), dal menu … della vista o con i comandi mergecat: Open ….

PaginaCosa mostraConnessione
BranchesOgni branch locale e i branch remoti senza copia locale: commit in entrata e in uscita, not on origin, upstream deleted, avanti/indietro rispetto alla base, merged, conflitti con la base (con l’elenco dei file), età. Fetch esegue git fetch --all --prune --tags.Locale
TagsNome, commit, data, autore del tag, messaggio, annotato o leggero, versione, su origin oppure local only con un pulsante Push. New tag verifica il nome mentre scrivi e può eseguire il push del tag.Locale
Pull RequestsAperte, chiuse o tutte, con stato, revisori e voti, check; dettagli con commit e issue collegate. New pull request precompila titolo e descrizione a partire dai commit.Connesso
PipelinesGitHub Actions, GitLab CI/CD e Azure Pipelines: Activity (stage, job, step, dipendenze), Text (lo YAML) e Runs (stato e durata di ogni job).Connesso
DeploymentsIl deployment attivo di ogni ambiente e quelli precedenti con i loro tag; Compare environments con note di rilascio e report di audit; cosa ha portato ogni deployment.Connesso

Senza connessione, la pagina Deployments mostra gli ambienti trovati in locale (impostazioni, nomi di branch e tag) e li confronta allo stesso modo.

Analisi

  • Changeset blame: mergecat: Toggle Changeset Blame (anche nella barra del titolo dell’editor) annota la riga sotto il cursore con l’integrazione che l’ha portata nel branch analizzato: pull request o branch integrato, titolo, data e gli ambienti raggiunti. Il tooltip aggiunge il commit, chi l’ha integrata, approvazioni e issue collegate (se connesso), il primo tag di release e il rischio.
  • Changesets That Shaped This File elenca le integrazioni che hanno scritto il file corrente, a partire da quella con la quota maggiore.
  • Rischio per integrazione: un punteggio basato su dimensione, numero elevato di file, aree sensibili, codice modificato senza test, commit diretti e merge locali senza pull request, merge senza approvazione (se connesso) e revert. Filtra con Filter… › Risk…. I fattori sono elencati in Report di audit delle modifiche.
  • Metriche: mergecat: Show Metrics mostra le modifiche entrate, la quota passata da una pull request, il lead time, la dimensione delle modifiche, i revert, gli autori, l’attività per settimana o per mese, la distribuzione del rischio e i principali contributori. Con la connessione a GitHub aggiunge il tempo fino al merge.

Report di audit

Esegui mergecat: Export Audit Report… (dalla Command Palette o dal menu … della vista Changesets) e scegli l’ambito: la vista corrente, Between two releases…, Between two environments… oppure Not yet in un ambiente. Scegli HTML, Markdown, CSV o JSON e dove salvarlo. La pagina Deployments offre lo stesso report per le modifiche di Compare environments.

Le approvazioni provengono dal servizio di hosting: senza connessione il comando avvisa che verranno riportate come “unknown” e propone di connetterti. Dettagli: Report di audit delle modifiche.

Accesso per servizio

Connettiti dalla vista Connections, dalla pillola Local only · Connect nell’intestazione di Changesets oppure con mergecat: Connect….

ServizioAccessoNote
GitHub (github.com)L’account GitHub di VS CodeSSO dell’organizzazione incluso; scope repo; il token resta in VS Code
Azure DevOps (dev.azure.com)Sign in with Microsoft con l’account Microsoft di VS CodeFunziona quando l’organizzazione Azure DevOps è connessa a Microsoft Entra ID (account aziendale o dell’istituto di istruzione)
Azure DevOps (alternativa, anche per Azure DevOps Server)Token di accesso personaleScope Code (Read & write), Build (Read), Environment (Read & manage), Work Items (Read)
GitLab (gitlab.com)Token di accesso personaleScope api (read_api basta per leggere; api serve per creare merge request)
GitLab (facoltativo)Sign in with GitLab nel browser (GitLab 17.2 o successivo)Richiede l’ID applicazione di un’applicazione OAuth non confidenziale in mergecat.gitlab.clientId

I token di accesso personali e i token dell’accesso a GitLab sono memorizzati nel SecretStorage di VS Code, uno per servizio e host, e mai nelle impostazioni o nei log. Disconnettiti dalla vista Connections. Vedi anche Sicurezza e privacy.

Impostazioni

ImpostazionePredefinitoDescrizione
mergecat.gitPathvuotoEseguibile di Git. Vuoto: il git.path dell’estensione Git integrata, poi i percorsi di installazione abituali
mergecat.pageSize200Voci di primo livello caricate alla volta (da 20 a 5000)
mergecat.hideForwardIntegrationMergestrueNasconde all’interno dei gruppi i merge del branch principale in un feature branch
mergecat.defaultBranchvuotoBranch analizzato all’apertura di un repository, es. origin/main. Vuoto: il branch predefinito del remote, poi main/master, poi il branch corrente
mergecat.repositoryScanDepth2Livelli di sottocartelle in cui cercare repository quando la cartella aperta non è un repository (da 0 a 5; 0 = solo la cartella aperta)
mergecat.environments.definitions[]Ambienti: { "name", "ref" } oppure { "name", "tagPattern" }
mergecat.environments.autoDetecttrueDeduce gli ambienti dai nomi dei branch e dai tag di release quando non ne è configurato nessuno
mergecat.risk.sensitiveAreas[]Sostituisce le aree sensibili predefinite del punteggio di rischio; ogni elemento è { "id", "label", "points", "patterns" }. Vuoto: valori predefiniti
mergecat.risk.testPatterns[]Glob dei file di test per il fattore “nessun test modificato”. Vuoto: valori predefiniti
mergecat.gitlab.clientIdvuotoID applicazione di un’applicazione OAuth di GitLab per Sign in with GitLab. Vuoto: token di accesso personale

Esempio di aree sensibili personalizzate:

"mergecat.risk.sensitiveAreas": [
  { "id": "billing", "label": "Billing", "points": 3, "patterns": ["src/billing/**"] }
]
