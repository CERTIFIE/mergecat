集成

MCP 服务器与工具

mergecat MCP 服务器参考：每个工具及其参数、合规锁、环境变量，以及如何不通过插件使用该服务器。

在 GitHub 上编辑

本页借助 AI 从英文翻译。如有疑问，以英文版本为准。

mergecat MCP 服务器为 AI 助手提供分支的变更集、标签和发布，以及 Keep a Changelog 草稿。它通过 stdio 在本地运行，使用你的 Git 读取仓库，并且从不更改仓库。Claude Code 插件会将它与技能一起安装；你也可以单独添加它，并将其与 GitHub Copilot、OpenAI Codex 和 GitLab Duo 一起使用。

工具名称

安装方式Claude Code 中的工具名称
插件mcp__plugin_mergecat_mergecat__<tool>
名为 mergecat 的独立服务器mcp__mergecat__<tool>

合规锁

在本会话的合规问题得到回答且结果为 proceed 之前，仓库工具（repository_info、tags、changelog、changesets、where_entered）处于锁定状态。锁定期间，它们会返回一个错误，其中包含需要提出的问题以及调用 record_compliance_answer 的指示；它们不会读取任何内容。

compliance_status、record_compliance_answer 和 render_pdf 不会被锁定：它们不读取仓库的历史记录。

每个会话一个回答

回答保存在服务器进程的内存中。Claude Code 与其他客户端一样，为每个会话启动一个进程，因此每个新会话都会再次询问，并且每个回答都会写成一条审计记录。问题中会指明客户端所用的 AI 服务：在 Claude Code 中是 Claude Team 或 Enterprise 账户，在 Copilot 中是 GitHub Copilot Business 或 Enterprise 许可证，依此类推（参见各助手的合规问题）。参见 AI 使用记录。

使用哪个仓库

每个仓库工具都接受一个可选的 repository 参数：Git 仓库的路径（或仓库内的任意文件夹）。未提供该参数时，服务器按以下顺序确定仓库：

  1. MERGECAT_REPOSITORY；
  2. CLAUDE_PROJECT_DIR（Claude Code 项目）；
  3. 客户端中打开的文件夹（前提是客户端会将它们报告给 MCP 服务器，VS Code 就会这样做）：其中第一个是 Git 仓库的文件夹；
  4. 服务器的当前目录。

工具

compliance_status

本会话中是否已回答合规问题，以及需要提出的确切问题。没有参数。不读取仓库。

返回 aiService（问题所涉及的 AI 服务）、confirmed、askedThisSession、lastOutcome、lastRecordedAt、lastRecordFile、questions.account、questions.proceedIfNotTeamOrEnterprise 和 recordsFolder。字段说明：AI 使用记录。

record_compliance_answer

将用户在对话中给出的回答作为审计记录保存在这台计算机上（Markdown 文档和 JSON Lines 日志），并在结果为 proceed 时为本会话解锁仓库工具。

参数类型必需描述
team_or_enterprise_accountboolean是如果用户使用第一个问题中提到的商业版或企业版方案（在 Claude Code 中：Claude Team 或 Enterprise 账户），则为 true
aware_and_proceedboolean当第一个回答为 false 时如果用户了解欧盟《人工智能法案》和 NIS2 并且仍要继续，则为 true
requested_actionstring是用户请求的内容，例如 changelog v1.2.0..v1.3.0 或 tags
answers_verbatimstring否用户写下的原始回答，或所选的选项
languagestring否提问所用的语言（ISO 639-1）
ai_modelstring否助手的模型 ID
repositorystring否仓库路径

返回结果、记录 ID、记录和日志的路径，以及 Markdown 格式的记录。当结果为 stopped 时，该 Markdown 会省略用户、计算机和仓库的详细信息。

render_pdf

将 Markdown 文档（变更日志、发布说明、合规记录）转换为 PDF 文件。不读取仓库。

参数类型必需描述
markdownstring是Markdown 文档（最多 2,000,000 个字符）
file_namestring否文件名，例如 changelog-web-v1.3.0.pdf。默认：根据标题生成
folderstring否存放文件的文件夹（绝对路径）。默认：系统临时文件夹中的 mergecat
titlestring否用于 PDF 元数据和页脚的文档标题。默认：第一个 # 标题
allow_in_projectboolean否允许在项目文件夹内写入；仅在用户要求将 PDF 保存到那里时使用

除非设置了 allow_in_project，否则服务器拒绝在项目内（即使用哪个仓库中确定的文件夹）写入。文件名只保留字母、数字、.、_ 和 -。返回 file、pages 和 bytes。字体限制请参阅变更日志。

repository_info

默认分支、当前分支、托管服务，以及默认分支上的版本标签及其日期（最新的在前，最多 30 个）。还会说明拉取请求数据是否可用（GitHub (GITHUB_TOKEN set) 或 none (local Git data only)）、上次获取的时间，以及该克隆是否为浅克隆。

参数类型必需描述
repositorystring否仓库路径

tags

所有标签，最新的在前：日期、提交、附注或轻量、消息、标签创建者、是否看起来像版本号，以及是否在分支上。对于分支上的版本标签：上一个版本标签，以及自它以来的变更集数量。另外还有尚未发布的变更集数量和最新的版本标签。

参数类型必需描述
repositorystring否仓库路径
branchstring否用于制作发布的分支。默认：默认分支
patternstring否名称中包含的文本，或带 * 和 ? 的 glob 模式（例如 v2.*）；不区分大小写
versions_onlyboolean否仅返回看起来像版本号的标签（v1.2.3、1.2）
limitinteger否标签数量上限，1 到 500。默认 50

changelog

进入分支的内容的 Keep a Changelog 草稿，每个变更集一行，按发布（版本标签）和分节（Added、Changed、Deprecated、Removed、Fixed、Security）分组。返回 Markdown 草稿和结构化数据：每个变更集的分节及理由、拉取请求编号和链接、分支、提交，以及破坏性变更标志和内部标志；对于范围，还包括每一端的解析方式；以及两端颠倒或缺少拉取请求数据等说明。

参数类型必需描述
repositorystring否仓库路径
branchstring否要描述其历史记录的分支。默认：默认分支（例如 origin/main）
rangestring否一个范围 from..to（也可以写成 [from..to]）；每一端可以是标签、日期（YYYY-MM-DD，可附带时间）或提交；允许开放的端点（v1.3.0..、..v1.0.0）
fromstring否范围的起点，不包含：标签、日期或提交
tostring否范围的终点，包含：标签、日期或提交。默认：该分支
max_releasesinteger否未指定范围时包含的发布数量，0 到 100。默认 5
unreleased_onlyboolean否仅包含最新版本标签之后的变更
include_internalboolean否在 Markdown 中也列出文档、测试、CI 和杂项。默认 false（它们仍保留在数据中）
headerboolean否以 # Changelog 标题和 Keep a Changelog 前言开头
languagestring否ISO 639-1 代码。默认 en。标题会针对 en、it、de、fr、es 进行翻译；对于其他语言，标题保持英文，数据中会注明 headingsTranslated: false

请提供 range 或 from/to 其中之一，不要同时提供。该工具从不翻译变更描述。

changesets

进入某个分支的内容，最新的在前，按集成分组：已合并的拉取请求和合并及其带入的提交，以及直接提交。还会返回历史记录的警告（浅克隆、没有合并、压缩合并）。

参数类型必需描述
repositorystring否仓库路径
branchstring否要描述的分支。默认：默认分支
basestring否仅包含此标签、分支或提交之后进入的内容
sincestring否集成日期的起始，YYYY-MM-DD
untilstring否集成日期的截止，YYYY-MM-DD
searchstring否主题、SHA、分支名称或拉取请求标题中的文本（也会搜索分组内部）
authorstring否作者或集成者的姓名或电子邮件
limitinteger否条目数量上限，1 到 500。默认 50

where_entered

针对某个提交：将它带入分支的集成（拉取请求、合并或直接提交）、时间、集成者，以及包含它的首个标签。

参数类型必需描述
repositorystring否仓库路径
shastring是提交 SHA，至少 7 个十六进制字符
branchstring否分支。默认：默认分支

拉取请求数据

当环境中有仓库托管服务的令牌时，工具会补充拉取请求（合并请求）的标题、编号、标记和关联的议题：GitHub 使用 GITHUB_TOKEN（或 GH_TOKEN），GitLab 使用 GITLAB_TOKEN（或 GL_TOKEN），Azure DevOps 使用 AZURE_DEVOPS_EXT_PAT（个人访问令牌）或 AZURE_DEVOPS_TOKEN（Microsoft Entra 令牌）。没有令牌时，工具只使用本地 Git 数据，并说明应设置哪个变量。

不通过插件使用服务器

该服务器也是一个普通的 MCP 服务器：没有技能，工具名称为 mcp__mergecat__<tool>。它的说明会告诉客户端提出合规问题，并在对话中向用户提供文档，而不是作为项目中的文件。

获取服务器

从下载区下载单个文件 mergecat-mcp.cjs，或者在克隆中使用 npm run mcp:build 构建它（输出到 plugins/mergecat/server/mergecat-mcp.cjs）。它需要 Node.js 20 或更高版本。

将其添加到 Claude Code

claude mcp add --transport stdio --scope user mergecat -- node /path/to/mergecat-mcp.cjs

要传递环境变量，请在 -- 之前添加 -e NAME=value，例如 -e MERGECAT_COMPLIANCE_DIR=/path/to/records。

检查

在某个 Git 仓库中启动 Claude Code 并运行 /mcp：mergecat 服务器应显示为已连接。服务器将日志输出到 stderr，启动时会打印 mergecat MCP server 0.3.0 ready。

其他能够启动 stdio 服务器的 MCP 客户端也以同样的方式运行它：node /path/to/mergecat-mcp.cjs；GitHub Copilot、OpenAI Codex 和 GitLab Duo 的用法请参阅其他 AI 助手。在 Claude Code 之外不会设置 CLAUDE_PROJECT_DIR：如果客户端报告了其中打开的文件夹，服务器就会使用这些文件夹；否则，请设置 MERGECAT_REPOSITORY 或向工具传递 repository。

环境变量

变量作用
GITHUB_TOKEN用于获取拉取请求数据的 GitHub 令牌；未设置 GITHUB_TOKEN 时使用 GH_TOKEN
GITLAB_TOKEN用于获取合并请求数据的 GitLab 令牌（read_api）；未设置 GITLAB_TOKEN 时使用 GL_TOKEN
AZURE_DEVOPS_EXT_PAT用于获取拉取请求数据的 Azure DevOps 个人访问令牌；AZURE_DEVOPS_TOKEN 则改为接受 Microsoft Entra 令牌
MERGECAT_AI_SERVICE当无法识别客户端时，合规问题所涉及的 AI 服务：claude、copilot、openai、gitlab-duo 或其他名称
MERGECAT_GIT_PATH当 git 不在 PATH 中时使用的 Git 可执行文件
MERGECAT_COMPLIANCE_DIR存放 AI 使用记录的文件夹，用来代替默认文件夹
MERGECAT_REPOSITORY当工具未收到 repository 参数时使用的仓库；也是 render_pdf 所保护的项目文件夹
CLAUDE_PROJECT_DIR由 Claude Code 设置：项目文件夹，在既没有参数也没有 MERGECAT_REPOSITORY 时使用

在 Claude Code 中，插件会从你启动 Claude Code 的环境中传递上述令牌变量、MERGECAT_GIT_PATH 和 MERGECAT_COMPLIANCE_DIR。
