其他 AI 助手

在 GitHub Copilot、OpenAI Codex 和 GitLab Duo 中使用 mergecat 插件和 MCP 服务器，包括各服务的合规问题、仓库和拉取请求数据。

在 GitHub 上编辑

本页借助 AI 从英文翻译。如有疑问，以英文版本为准。

mergecat 插件不仅适用于 Claude Code。同一个文件夹也是一个可移植的 Agent Plugins 包，包含两个技能（changelog 和 tags，采用 SKILL.md 格式）以及 mergecat MCP 服务器。GitHub Copilot、OpenAI Codex 和 GitLab Duo 能够加载这些技能并启动本地 MCP 服务器，因此同样的工具和步骤在它们中也适用。

助手如何添加 mergecat工具技能
VS Code 中的 GitHub Copilotmergecat VS Code 扩展会自动添加服务器；或者使用插件是使用插件时提供
GitHub Copilot CLI插件，或 Copilot 的 MCP 配置是使用插件时提供
OpenAI Codex（CLI、IDE 扩展、应用）插件，或 config.toml是使用插件时提供，或手动复制
GitLab Duo（VS Code、JetBrains、Duo CLI）GitLab Duo 的 mcp.json是手动复制
网页版和应用中的 ChatGPT不支持——

为什么不支持 ChatGPT

ChatGPT 只连接可通过互联网访问的远程 MCP 服务器。mergecat 读取你计算机上的仓库，从不将其发送到自己的服务器。请使用 Codex：它在本地运行 mergecat 服务器，并且可以使用同一个 ChatGPT 账户。

各助手的合规问题

MCP 服务器根据客户端应用在连接时报告的名称识别助手，并询问该服务的商业版方案。每个回答都会保存为一条 AI 使用记录，其中注明服务和客户端应用。

助手第一个问题询问你是否使用
ClaudeClaude Team 或 Enterprise 账户
GitHub CopilotGitHub Copilot Business 或 Enterprise 许可证
OpenAI（ChatGPT、Codex）ChatGPT Business、Enterprise 或 Edu 工作区，或者组织的 OpenAI API 密钥
GitLab Duo带有付费 GitLab 订阅（Premium 或 Ultimate）的 GitLab Duo
任何其他客户端该客户端的商业版或企业版方案

如果助手未被识别，或者你想确保无误，请在服务器配置中设置 MERGECAT_AI_SERVICE：claude、copilot、openai、gitlab-duo，或其他服务的名称。下文中 GitLab Duo 的配置就设置了它。

GitHub Copilot

在 VS Code 中使用 mergecat 扩展

安装 mergecat VS Code 扩展后，VS Code 1.101 及更高版本无需任何配置即可向 Copilot 提供 mergecat MCP 服务器。该服务器随扩展一起打包，并使用 VS Code 的运行时运行，因此不需要 Node.js。它读取 VS Code 中打开的文件夹，并提出 GitHub Copilot 的问题。

扩展只添加工具，不添加技能。如果也需要技能，请安装插件（见下一节），并关闭设置 mergecat.copilot.mcpServer，以免 Copilot 获得两份服务器副本。

在 VS Code 和 Copilot CLI 中使用插件

Copilot 可以读取 Claude Code 格式的插件市场，例如 mergecat 仓库中的插件市场。在 VS Code 中，将该仓库添加到设置 chat.plugins.marketplaces（实验性）中，GitHub 仓库写作 owner/repo，也可以写作 Git URL，然后从中安装 mergecat。插件使用 node 启动服务器：PATH 中必须有 Node.js 20 或更高版本。

不使用插件的配置

VS Code 中的 Copilot 和 Copilot CLI 共用原生配置：个人配置为 ~/.copilot/mcp-config.json，或者使用工作区根目录下的 .mcp.json。请使用下载区中的单个文件 mergecat-mcp.cjs：

{
  "mcpServers": {
    "mergecat": {
      "type": "stdio",
      "command": "node",
      "args": ["/path/to/mergecat-mcp.cjs"],
      "env": { "GITHUB_TOKEN": "${GITHUB_TOKEN}" },
      "tools": ["*"]
    }
  }
}

Copilot Business 和 Enterprise

由组织决定 Copilot 能否使用 MCP 服务器：对于 Copilot Business 和 Enterprise 许可证，该策略默认关闭。请让组织的所有者允许它。

OpenAI Codex

插件

Codex 同样可以读取 Claude Code 格式的插件市场。将 mergecat 仓库（或本地克隆）添加为插件市场：

codex plugin marketplace add CERTIFIE/mergecat

然后从 ChatGPT 桌面应用的插件中安装 mergecat，并在 .codex/config.toml 中为某个项目启用它：

[plugins."mergecat@mergecat"]
enabled = true

不使用插件的配置

将服务器添加到 ~/.codex/config.toml。env_vars 会从启动 Codex 的环境中传递令牌，而不会把令牌写入文件：

[mcp_servers.mergecat]
command = "node"
args = ["/path/to/mergecat-mcp.cjs"]
env_vars = ["GITHUB_TOKEN", "GITLAB_TOKEN", "AZURE_DEVOPS_EXT_PAT"]

如需技能，请将 mergecat 仓库中的文件夹 plugins/mergecat/skills/changelog 和 plugins/mergecat/skills/tags 复制到 ~/.agents/skills/（个人使用）或某个仓库中的 .agents/skills/。

GitLab Duo

GitLab Duo Agentic Chat 可以在 VS Code、JetBrains IDE 和 GitLab Duo CLI 中使用 MCP 服务器。

允许外部 MCP 工具

由顶级群组的 Owner（所有者）在该群组的 GitLab Duo 设置中打开 Allow external MCP tools（允许外部 MCP 工具）。在 GitLab Self-Managed 上，还需要为流程和自定义智能体打开 mcp_client 功能标志。

添加服务器

编写 ~/.gitlab/duo/mcp.json（Windows：%APPDATA%\GitLab\duo\mcp.json），或项目中的 .gitlab/duo/mcp.json：

{
  "mcpServers": {
    "mergecat": {
      "type": "stdio",
      "command": "node",
      "args": ["/path/to/mergecat-mcp.cjs"],
      "env": { "MERGECAT_AI_SERVICE": "gitlab-duo" },
      "approvedTools": ["compliance_status", "repository_info", "tags", "changelog", "changesets", "where_entered"]
    }
  }
}

approvedTools 会一次性批准只读工具；record_compliance_answer 和 render_pdf 会在你的计算机上写入文件，因此仍会请求确认。然后重新启动 IDE 或 Duo CLI。

添加技能

将文件夹 plugins/mergecat/skills/changelog 和 plugins/mergecat/skills/tags 复制到项目中的 .agents/skills/（或 GitLab Duo CLI 的用户技能文件夹）。GitLab Duo 会在新对话中加载它们。

如需合并请求的标题、标记和关联的议题，请在设置了 GITLAB_TOKEN（具有 read_api 权限范围的令牌）的情况下启动 IDE 或 CLI。

使用哪个仓库

在 Claude Code 之外，服务器按以下顺序查找仓库：工具的 repository 参数、MERGECAT_REPOSITORY、客户端中打开的文件夹（VS Code 会将它们报告给 MCP 服务器；有多个文件夹时，使用第一个 Git 仓库），最后是服务器的工作目录。

拉取请求数据

当服务器的环境中有仓库托管服务的令牌时，工具会补充拉取请求（合并请求）数据：

托管服务变量
GitHubGITHUB_TOKEN 或 GH_TOKEN
GitLabGITLAB_TOKEN 或 GL_TOKEN
Azure DevOpsAZURE_DEVOPS_EXT_PAT（个人访问令牌）或 AZURE_DEVOPS_TOKEN（Microsoft Entra 令牌）

没有令牌时，工具只使用本地 Git 数据，并说明应设置哪个变量。切勿将令牌写入共享的或提交到仓库的配置文件：请改为从环境中引用它。
