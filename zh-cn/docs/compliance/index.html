合规与审计

欧盟《人工智能法案》与 NIS2

mergecat 如何记录 AI 使用、为从分支到环境的每项变更形成文档，并限制离开你计算机的数据，从而为你的欧盟《人工智能法案》和 NIS2 合规计划提供证据。

在 GitHub 上编辑

本页借助 AI 从英文翻译。如有疑问，以英文版本为准。

mergecat 涉及监管机构和审计员关注的两个主题。Claude Code 插件会将你仓库的数据发送给 AI 服务，而每个 mergecat 应用都会为哪些变更进入了分支、哪个环境在运行它们形成文档。本页说明 mergecat 记录了什么、强制执行了哪些控制措施，以及这些证据与欧盟《人工智能法案》（EU AI Act）和 NIS2 指令下的典型义务有何关联。

不构成法律建议

本页介绍 mergecat 的功能。它不构成法律建议，也不评估你的组织是否属于欧盟《人工智能法案》（Regulation (EU) 2024/1689）或 NIS2 指令（Directive (EU) 2022/2555，以其转化为你所在国家国内法后的形式为准）的适用范围。mergecat 提供证据和技术控制手段；合规仍是你所在组织的责任。请向你的合规官或法律顾问咨询如何使用这些证据。

为什么 Git 工具与合规相关

  • 它可能会将公司数据发送给 AI 服务。 通过 Claude Code 插件，mergecat 会向 Claude 提供仓库的历史元数据：提交消息、作者和提交者的姓名及电子邮件地址、日期、分支和标签名称、提交 SHA，以及（使用 GitHub 令牌时）拉取请求数据。许多组织只允许在经批准的 AI 账户上这样做，并希望每次使用都留有记录。根据《通用数据保护条例》（GDPR），姓名和电子邮件地址也属于个人数据。
  • 它记录软件如何变更。 谁编写了变更、谁集成了它、是否有经过审阅的拉取请求批准了它，以及它何时到达生产环境：这正是变更管理、发布评审和事件调查所需要的证据。
  • 它本身就是你供应链的一部分。 一个读取仓库并持有 GitHub、GitLab 或 Azure DevOps 令牌的工具，应当默认只读、安全地存储凭据，并且不将数据发送到任何你未选择的地方。

1. AI 使用：先询问、再记录、后发送

桌面应用、VS Code 扩展和命令行从不将数据发送给 AI 服务。只有 Claude Code 插件会这样做，而且只在有人回答了合规问题之后。

在每个 Claude Code 会话中，在读取第一份仓库数据之前，Claude 会询问一次你是否使用 Claude Team 或 Enterprise 账户。回答决定接下来会发生什么：

第一个回答：是否为 Team 或 Enterprise 账户？第二个回答：是否了解欧盟《人工智能法案》和 NIS2，仍要继续？结果审计记录
是不询问mergecat 继续保存在你的计算机上，并显示在对话中
否是mergecat 继续保存在你的计算机上，并显示在对话中
否否mergecat 停止；仓库工具保持锁定，不会向 Claude 发送任何仓库数据保存在你的计算机上；对话中的副本不含用户、计算机和仓库的详细信息

该决定由 MCP 服务器强制执行，而不仅仅依赖于给 Claude 的指令：在会话中记录的回答允许之前，每个仓库工具（repository_info、tags、changelog、changesets、where_entered）都会拒绝运行，并改为返回这些问题。

每个回答都会在你的计算机上成为一条审计记录：一份 Markdown 文档，加上 JSON Lines 日志中的一行，包含日期和时间、结果、请求的操作、操作系统用户和 Git 用户、计算机、仓库、AI 服务和模型、发送的数据，以及问题和回答。有关每个字段、存储文件夹以及如何为审计收集记录，请参见 AI 使用记录。

是声明，而非核实

mergecat 记录的是用户在使用时所作的声明。它不会向 Anthropic 核实账户类型，并且在每个新的 Claude Code 会话中都会再次提出该问题。记录本身也注明了这一点：它记录的是声明，而不是法律评估。

2. 变更管理和可追溯性

变更审计报告记录某个范围内的每项变更：一个发布相对于上一个发布增加了什么，或者下一次部署会给生产环境带来什么。对于每项变更，它会列出：

  • 由谁编写（其提交的作者），以及由谁将其集成到分支中；
  • 是否经过拉取请求，附有编号和链接；
  • 由谁批准，以托管服务报告的为准（未连接时报告为“unknown”）；
  • 关联的议题、变更的规模以及它包含的提交；
  • 它的风险级别和风险因素：数据库迁移、流水线、配置、安全相关文件、没有测试的变更、直接提交、未经批准的合并等；
  • 已经在运行它的环境。

摘要会统计没有拉取请求、未获批准和高风险的变更数量，HTML 报告中的“需要关注”（needs attention）部分会列出这些变更。报告附有所报告事实的 SHA-256 指纹：基于相同的历史记录和相同的数据重新生成报告，会得到相同的指纹，因此以后可以核验已存储的报告。格式：HTML（可打印为 PDF）、Markdown、CSV 和 JSON。

围绕这份报告，mergecat 还能回答审计员或事件响应人员最先提出的问题：

  • 每个环境中进入了什么，又是何时进入的？ 连接托管服务后，“部署”页面会显示每个环境当前上线的部署，包括其标签、提交、日期和流水线运行，以及之前部署的历史和每次部署带来的内容。
  • 下一次部署会带来什么？ 对比环境以变更集的形式列出将预发布环境（或主分支）部署到生产环境会带来的内容，包括仅存在于生产环境中的热修复。
  • 这个提交从何而来？ 这个提交是从哪里进入的？ 会指出将该提交带入分支的集成，以及包含它的首个标签。在 VS Code 中，变更集追溯（changeset blame）会对文件的每一行执行同样的操作。

有关报告的内容、风险因素以及如何在各个应用中生成报告，请参见变更审计报告。

3. 设计即安全

  • 默认只读。 mergecat 只在你运行明确的命令时才会写入：获取、创建或推送标签、创建拉取请求。它从不提交、检出、合并或改写任何内容。
  • 凭据保存在操作系统钥匙串中。 令牌通过 macOS、Windows 或 Linux 的钥匙串加密；没有钥匙串时，令牌只保存在内存中，绝不会以明文写入。VS Code 扩展使用 VS Code 自己的账户和机密存储。
  • 本地优先。 所有不需要托管服务的功能都无需连接即可在本地仓库上运行。
  • 没有 mergecat 服务器，没有遥测。 数据只会流向你连接的托管服务，以及在回答合规问题之后通过 Claude Code 插件流向 Claude，除此之外不会离开你的计算机。

详细信息：安全与隐私。

与典型义务的关系

下表将 mergecat 的证据和控制措施对应到欧盟《人工智能法案》和 NIS2 合规计划通常涵盖的主题。某个主题是否适用于你，以及它还有哪些其他要求，取决于你的组织、所在行业和你的角色。

欧盟《人工智能法案》

《人工智能法案》的大部分具体义务（例如日志记录和人类监督）是针对高风险人工智能系统的提供者和部署者制定的；根据 Git 历史记录生成变更日志通常不属于此类系统。尽管如此，许多组织仍在其 AI 治理和 AI 素养措施中，将同样的原则应用于每一次 AI 使用。

主题mergecat 提供的内容仍由你的组织负责的内容
AI 素养和意识对于非 Team 或 Enterprise 的账户，第二个问题会在用户继续之前提醒他们注意《人工智能法案》和 NIS2培训、内部 AI 政策、经批准的 AI 账户
AI 使用的透明度每条记录都会写明 AI 服务、模型、请求的操作以及所发送数据的类别告知相关人员，例如姓名出现在历史记录中的作者；你的 GDPR 评估
人类监督MCP 服务器会在回答被记录之前一直锁定仓库工具，技能会指示 Claude 等待你的回答，绝不代你回答；变更日志是对话中的草稿，只有在你要求时才会更改 CHANGELOG.md在发布 AI 输出之前对其进行审查
记录保存和日志记录每个决定对应一条 Markdown 记录和一条 JSON Lines 条目，保存在用户的计算机上收集、保护和保留这些记录

NIS2 指令

NIS2 要求基本实体和重要实体采取网络安全风险管理措施（第 21 条），规定其管理机构须对这些措施负责（第 20 条），并为重大事件规定了报告义务（第 23 条）。适用范围内的实体通常会将类似的要求传递给其软件供应商。

主题mergecat 提供的内容仍由你的组织负责的内容
开发和维护中的安全、变更管理按发布或部署生成的变更审计报告：拉取请求、批准、风险因素、未经审阅的变更你的变更和发布政策，以及审阅本身
供应链安全AI 使用记录写明 AI 服务和发送的数据；mergecat 在本地运行，只与你连接的服务通信评估你的供应商，包括 AI 服务和 mergecat 本身
事件处理和报告每个环境运行的内容以及每次部署带来的内容；提交从哪里进入、在哪个发布中你的事件处理流程以及向主管机关发出的通知
访问控制和身份验证默认只读；令牌保存在操作系统钥匙串中；通过托管服务登录，你的 SSO 和 MFA 在其中生效令牌范围、账户管理、MFA 策略
有效性评估、问责审计摘要（经拉取请求的变更比例、未获批准、高风险）以及可供管理层审查的带指纹报告设定目标、审查证据、保存证据

将证据保存在审计员会查看的地方

mergecat 将 AI 使用记录存储在每个用户的计算机上，并将审计报告保存到你选择的位置。它不会集中收集这些内容。请决定你的组织将它们保存在哪里（例如与发布文档放在一起）以及保存多长时间。
