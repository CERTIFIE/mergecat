桌面应用

分支

一目了然地查看每个分支相对于 origin 和基准分支的状态，包括合并冲突、按时长筛选，以及安全的获取操作。

在 GitHub 上编辑

本页借助 AI 从英文翻译。如有疑问，以英文版本为准。

可离线使用

“分支”页面列出每个本地分支以及没有本地副本的远程分支，并告诉你每个分支是否已推送、是否落后、是否已合并，或是否与基准分支存在冲突。它读取本地克隆，从不检出、合并或删除分支。在导航栏中点击分支即可打开它。

“分支”页面：每个分支一行。

标题栏会显示分支的数量、对比所用的基准分支和远程仓库，以及仓库上次获取的时间。

列

列显示的内容
分支名称；工作树中检出的分支标为当前，基准分支标为基准。下方：它跟踪的上游分支（tracks origin/x）、“本地分支”或“远程分支，无本地副本”。
最后提交最新提交的主题、作者、时长和短 SHA。
对比 origin↓ 待拉取的提交和 ↑ 待推送的提交，或者已同步、不在 origin 上（从未推送）、上游已删除（通常在拉取请求合并之后）或仅在 origin 上。下方：远程分支上次在本机更新（通过获取或推送）的时间。
对比基准↓ 落后于基准分支的提交和 ↑ 领先于基准分支的提交；分支的所有内容都已在基准分支中时显示已合并；将其合并到基准分支会产生冲突时显示冲突。下方：存在冲突的文件数，或“可无冲突合并”。
距今距最后一次提交的天数。60 天起显示为橙色，90 天起显示为红色。

将鼠标悬停在冲突上，可查看会产生冲突的文件。

基准分支

标题栏中的选择器用于设置计算对比基准、已合并和冲突时所依据的分支。它初始为仓库的默认分支（通常是 origin/main）。例如，选择一个发布分支，即可查看哪些功能分支会与它冲突。

冲突检查

mergecat 使用 git merge-tree 检查每个与基准分支产生分叉的分支，该命令会计算合并结果，而不会触及你的工作树或分支。此检查需要 Git 2.38 或更高版本；如果 Git 版本较旧，页面会给出提示，并且该列会显示“冲突检查需要 Git 2.38”。

筛选和搜索

列表上方的徽标用于筛选各行，并显示匹配的分支数量：

筛选条件显示的分支
全部本地分支，以及没有本地副本的远程分支。
仅本地仅存在于此计算机上的分支。
不在 origin 上从未推送，或已在远程仓库上删除。
已合并该分支的所有内容都已在基准分支中。
冲突将该分支合并到基准分支会产生冲突。
超过 60 天最后一次提交在 60 天以前。
超过 90 天最后一次提交在 90 天以前。

搜索框（按名称、作者筛选…）匹配分支名称，以及最后一次提交的作者和主题。

已合并和按时长筛选可以帮你快速找到需要清理的分支；mergecat 将删除操作留给你自己完成。

获取

获取会运行 git fetch --all --tags --prune：它会从每个远程仓库更新远程分支和标签，并移除在服务器上已删除的远程分支。你的本地分支和工作树不会被更改。获取使用你的 Git 凭据（你的凭据助手）；mergecat 不会索要密码。获取完成后，整个应用中的分支选择器和标签徽标都会更新到最新状态。

行操作

每行末尾的 ⋯ 按钮会打开：

操作作用
复制名称复制分支名称。
显示历史记录在此分支上打开“历史记录”页面。
在最新提交处创建标签…在该分支的最新提交上打开新建标签。
创建拉取请求…打开新建拉取请求，并以此分支作为源分支。需要连接；不适用于基准分支。

后续步骤

标签与发布 → 创建、附注并推送标签。 拉取请求 → 从某个分支创建拉取请求。
