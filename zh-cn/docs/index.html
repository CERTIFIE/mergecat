入门

简介

mergecat 显示哪些内容在何时进入了 Git 分支，像 TFS 变更集一样按集成分组，并追踪每项变更从分支到部署的全过程。

在 GitHub 上编辑

本页借助 AI 从英文翻译。如有疑问，以英文版本为准。

mergecat 按集成对分支的 Git 历史记录进行分组，就像 TFS 和 TFVC 显示变更集那样。你可以看到哪些内容进入了 main（或任意分支）、何时进入、通过哪个拉取请求进入，以及之后由哪个环境运行它。它适用于任何本地仓库，可离线使用，默认只读。

桌面应用的“历史记录”页面，已连接到 GitHub。

问题所在

在 main 上执行 git log，所有功能分支的提交会交错在一起。经过几次合并后，你就再也分不清哪些提交属于同一组、是哪个分支带入了它们，以及它们实际是何时到达 main 的。从 Team Foundation Server 转过来的团队怀念变更集视图：每次签入一行，包含其中的全部内容。

mergecat 恢复了这一视图。它遍历分支的第一父提交历史，并显示：

  • 直接在分支上进行的直接提交，每个一行；
  • 以可折叠分组显示的集成（合并提交），包含它们带入的提交以及被合并分支的名称，即使该分支已被删除。

连接 GitHub、GitLab 或 Azure DevOps 后，mergecat 会补充 Git 不存储的内容：拉取请求、压缩合并和变基合并、关联的议题、流水线和部署。mergecat 的工作原理详细说明了分组方式。

三种使用方式

桌面应用 → 支持 macOS、Windows 和 Linux。在一个窗口中查看历史记录、分支、标签、拉取请求、流水线和部署。 VS Code 扩展 → 在编辑器中提供 Changesets 视图、在编辑器标签页中打开的仓库页面以及原生差异视图。 Claude Code 插件 → 通过只读的 MCP 服务器，根据变更集列出标签并起草 Keep a Changelog 格式的变更日志。

命令行工具为脚本提供相同的历史记录、指标和审计报告：参见命令行。

原则

本地优先。 mergecat 使用你自己的 Git 从你的克隆中读取历史记录。分组、差异、筛选、导出、分支和标签无需任何账户或网络连接即可使用。连接托管服务是可选的，只会补充数据。

默认只读。 mergecat 从不提交、检出、合并或改写任何内容。只有当你亲自启动操作时它才会写入：获取、创建或推送标签、创建拉取请求。获取和标签推送使用你的 Git 凭据。

你的凭据保留在你的计算机上。 令牌通过系统钥匙串加密；拉取请求数据缓存在应用自己的数据文件夹中，绝不会存放在仓库中。mergecat 与 Git 通信，并在你连接托管服务后与该托管服务通信。参见仅本地与已连接。

专为变更审计而设计

了解什么进入了分支、谁批准了它以及它在哪里运行，是变更审计的核心。mergecat 把这些信息整理成一份报告。

欧盟《人工智能法案》与 NIS2

审计报告列出某个范围内的每项变更：由谁编写、由谁集成、是否经过拉取请求以及由谁批准、它的风险因素以及运行它的环境，并附有内容的 SHA-256 指纹。Claude Code 插件在读取仓库之前，会在每个会话中记录一次你是否使用 Claude Team 或 Enterprise 账户。阅读欧盟《人工智能法案》与 NIS2，了解这些记录如何支持你履行文档义务。

浏览文档

安装 → 在 macOS、Windows 或 Linux 上安装桌面应用。 快速开始 → 五分钟内打开一个仓库并读懂它的变更集。 mergecat 的工作原理 → 第一父提交遍历、分支名称、压缩合并和变基合并。 历史：变更集与提交图 → 桌面应用“历史记录”页面的每个部分。 仅本地与已连接 → 连接 GitHub、GitLab 或 Azure DevOps 会增加什么。 变更审计报告 → 谁编写、审阅并批准了某个发布中的每项变更。
