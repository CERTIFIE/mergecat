配置

桌面应用的设置、每个 mergecat 组件的环境变量，以及 mergecat 在 macOS、Windows 和 Linux 上存储数据的位置。

在 GitHub 上编辑

本页借助 AI 从英文翻译。如有疑问，以英文版本为准。

mergecat 无需任何配置即可在任何本地仓库上工作。本页列出你可以更改的内容：桌面应用的设置，桌面应用、命令行和 MCP 服务器的环境变量，以及每个组件保存数据的位置。VS Code 设置列在 VS Code 页面上。

桌面应用设置

打开文件 › 设置…（在 macOS 上按 ⌘,，在 Windows 和 Linux 上按 Ctrl,），或点击顶部栏中的齿轮图标。设置是这台计算机的偏好设置；凭据在连接中管理。

设置：外观、Git 可执行文件，以及浏览器登录所用的客户端 ID。

设置默认值说明
外观系统浅色、深色或系统；立即生效
Git 可执行文件空git 可执行文件的路径。留空时：先在 PATH 中查找 git，然后查找常用安装文件夹。对话框会显示找到的 Git 版本或错误
GitHub OAuth App 客户端 ID空启用使用 GitHub 登录：由管理员一次性创建、勾选了 Enable Device Flow 的 OAuth App 的客户端 ID。它不是机密信息
Microsoft Entra ID 客户端 ID（Azure DevOps）空为 Azure DevOps 启用使用 Microsoft 登录：一个开启了 Allow public client flows 并具有 Azure DevOps 权限 user_impersonation 的 Entra ID 应用的应用程序（客户端）ID
Microsoft 租户organizationsorganizations（任意工作账户）、你的租户 ID 或你的域名
GitLab OAuth 应用程序 ID空启用使用 GitLab 登录（GitLab 17.2 或更高版本）：一个具有 api 范围的非机密 OAuth 应用程序。用于当前打开的仓库所在的 GitLab 实例
每页条目数200每次加载的顶层历史记录条目数，50 到 5000

没有客户端 ID 时，请使用个人访问令牌进行连接。如何注册这些应用：GitHub、GitLab、Azure DevOps。

设置与你最近打开的 10 个仓库一起存储在应用数据文件夹中的 settings.json 里。外观设置由应用窗口存储。

环境变量

变量使用者用途
MERGECAT_GITHUB_CLIENT_ID桌面应用用于使用 GitHub 登录的 OAuth App 客户端 ID
MERGECAT_MICROSOFT_CLIENT_ID桌面应用用于使用 Microsoft 登录（Azure DevOps）的 Entra ID 应用客户端 ID
MERGECAT_MICROSOFT_TENANT桌面应用Entra ID 租户（默认为 organizations）
MERGECAT_GITLAB_CLIENT_ID桌面应用用于使用 GitLab 登录的 GitLab OAuth 应用程序 ID
MERGECAT_GITLAB_URL桌面应用GitLab 实例 URL（自托管 GitLab、测试）
MERGECAT_GITHUB_API_URL、MERGECAT_GITHUB_GRAPHQL_URL桌面应用GitHub REST 和 GraphQL 端点（测试）
MERGECAT_USER_DATA_DIR桌面应用用于设置、凭据和缓存的单独文件夹（测试、并行运行）
MERGECAT_MEMORY_CREDENTIALS=1桌面应用不使用系统钥匙串：凭据仅保存在内存中（测试）
MERGECAT_GIT_PATH命令行、MCP 服务器Git 可执行文件
GITHUB_TOKENMCP 服务器GitHub 仓库的拉取请求数据；未设置时使用 GH_TOKEN
GITLAB_TOKENMCP 服务器GitLab 仓库的合并请求数据；未设置时使用 GL_TOKEN
AZURE_DEVOPS_EXT_PAT、AZURE_DEVOPS_TOKENMCP 服务器Azure DevOps 仓库的拉取请求数据：个人访问令牌或 Microsoft Entra 令牌
MERGECAT_AI_SERVICEMCP 服务器无法识别客户端时，合规问题所涉及的 AI 服务：claude、copilot、openai、gitlab-duo 或其他名称（其他 AI 助手）
MERGECAT_COMPLIANCE_DIRMCP 服务器AI 使用记录的文件夹
MERGECAT_REPOSITORYMCP 服务器工具未获得 repository 参数时使用的仓库
CLAUDE_PROJECT_DIRMCP 服务器由 Claude Code 设置：项目目录，在 MERGECAT_REPOSITORY 之后使用（其他客户端：它们打开的文件夹）

客户端 ID 变量会在桌面应用启动时读取，并填充你留空的设置；在“设置”中输入的值优先。管理员可以借此提供组织的登录应用，例如通过受管理的环境。

VS Code 设置

扩展的设置（mergecat.gitPath、mergecat.pageSize、mergecat.environments.definitions、mergecat.risk.sensitiveAreas、mergecat.gitlab.clientId 等）及其默认值列在 VS Code 页面上。

数据位置

桌面应用

应用数据文件夹中保存着 settings.json、加密的 credentials.bin 以及 pull-request-cache/ 文件夹。

~/Library/Application Support/mergecat/
%APPDATA%\mergecat\
~/.config/mergecat/

如果设置了 XDG_CONFIG_HOME，则为 $XDG_CONFIG_HOME/mergecat/。

MERGECAT_USER_DATA_DIR 会替换此文件夹。导出文件和审计报告保存在你选择的位置；保存对话框会建议你的“文档”文件夹。

Claude Code 插件和 MCP 服务器

AI 使用记录（Markdown 文件和 compliance-log.jsonl）：

~/Library/Application Support/mergecat/compliance/
%APPDATA%\mergecat\compliance\
$XDG_DATA_HOME/mergecat/compliance/

未设置 XDG_DATA_HOME 时：~/.local/share/mergecat/compliance/。

MERGECAT_COMPLIANCE_DIR 会替换此文件夹。PDF 会写入 Claude 的草稿目录（scratchpad）或系统临时文件夹中的 mergecat 文件夹；变更日志是对话中的文档。

VS Code 扩展

拉取请求数据缓存在 VS Code 用户数据中该扩展的全局存储文件夹里；令牌保存在 VS Code 的 SecretStorage 中。审计报告保存在你选择的位置；保存对话框会建议仓库文件夹。

命令行

命令行不存储任何内容：它将结果输出到终端。

mergecat 的任何组件都不会将设置或缓存写入你的仓库。
