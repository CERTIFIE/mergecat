限制与集成方式

针对完成拉取请求的每种方式 mergecat 会显示什么、此版本的已知不足，以及浅克隆、PDF 和各工具的限制。

在 GitHub 上编辑

本页借助 AI 从英文翻译。如有疑问，以英文版本为准。

mergecat 按 Git 记录的合并提交对历史记录进行分组。你的团队如何完成拉取请求，决定了这种结构保留了多少；连接托管服务可以填补其中的一些空白。本页列出 mergecat 在每种情况下显示的内容，以及此版本的已知限制。

集成方式

拉取请求的完成方式mergecat 显示的内容
合并（非快进），包括 Azure DevOps 的半线性合并分组：每个合并一个变更集，包含它带入的提交
压缩一个提交；当消息看起来像拉取请求时标记为“压缩”；连接后显示原始提交
变基和快进直接提交；连接后按拉取请求分组；当分支完全没有合并时显示警告
对使用过正向集成的功能分支进行快进，或在分支本身上执行 git pull 合并标记为“反向”：从那里开始，第一父提交路径可能会沿着错误的一侧
浅克隆显示警告；分组可能不完整

推荐的约定

使用合并提交（非快进）完成拉取请求，并将分支名称或工作项 ID 写进拉取请求标题。标题最终会出现在合并消息中，并且在分支删除后依然保留，因此即使没有连接，mergecat 也能为变更集命名。

仅本地与已连接

功能仅本地已连接
非快进合并的变更集是是
被合并分支的名称当合并消息中包含它，或分支仍然存在时始终
拉取请求编号、标题、作者、链接只有编号和标题，且仅当它们出现在合并消息中时是
变基合并拉取请求的变更集否（提交看起来是直接提交）已分组
压缩合并拉取请求的原始提交否是
关联的议题、标记、批准否是

完整的对比请参阅仅本地与已连接。

已知不足

  • 尚无法根据远程 URL 识别 GitHub Enterprise 和自托管 GitLab 主机。
  • 连接器仅针对模拟的 API 响应进行了测试，尚未针对真实的 GitHub、GitLab 或 Azure DevOps 进行测试。
  • 不支持 Azure DevOps 的经典发布（Release）流水线（仅支持 YAML 流水线和环境）。
  • Azure DevOps：不显示拉取请求的检查和工作项的标题。
  • Bitbucket 已列出，但尚不可用（“即将推出”）。
  • 获取和标签推送使用你的 Git 凭据（凭据助手或 SSH）；不会提示输入密码。
  • 在 VS Code 中，GitHub 登录使用 VS Code 的 github.com 账户，因此无法通过这种方式连接自托管的 GitHub Enterprise。
  • 桌面应用只从已连接托管服务的部署中获取环境，其审计报告中的“环境”列为空。
  • 命令行只读取 Git：没有拉取请求数据，因此其审计报告中的批准情况为未知。
  • mergecat MCP 服务器（Claude Code 插件和其他助手）只有在其环境中有令牌（GITHUB_TOKEN、GITLAB_TOKEN 或 AZURE_DEVOPS_EXT_PAT）时才能获取拉取请求数据，并且仅限 github.com、gitlab.com 和 Azure DevOps 上的仓库（无法识别自托管的 GitHub 和 GitLab 主机）。
  • 不支持网页版和应用中的 ChatGPT：它只使用远程 MCP 服务器。请改用 Codex（其他 AI 助手）。
  • 桌面应用和本网站提供英语、意大利语、德语、简体中文、弗留利语和印地语版本（在应用中：设置、语言）。VS Code 扩展、命令行、MCP 工具、导出的文件和审计报告，以及 Git 和托管服务的消息仅提供英文。

浅克隆

浅克隆（例如 CI 中常见的 git clone --depth 1）会截断历史记录：较早的提交会缺失，边界处的分组可能不完整。mergecat 会显示警告，将历史记录被截断处的提交标记为“浅克隆”，并且 MCP 工具 repository_info 会报告 shallowClone: true。要获得完整的结果，请获取完整的历史记录：

git fetch --unshallow

Git 版本

读取历史记录时，任何较新的 Git 版本都可以。“分支”页面的冲突检查使用 git merge-tree，需要 Git 2.38 或更高版本。

PDF 输出

Claude Code 插件生成的 PDF 使用 A4 页面和标准 PDF 字体（Helvetica 和 Courier）：

  • Latin-1 文本（涵盖西欧语言）按原样打印；
  • 一些排版字符会被替换为 ASCII（→ 替换为 ->，弯引号替换为直引号，… 替换为 ...，€ 替换为 EUR，破折号替换为 -）；
  • 其他所有字符，包括希腊文、西里尔文、亚洲文字和表情符号，都会打印为 ?。

对于使用其他文字系统书写的语言，请要求输出 Markdown。PDF 支持标题、段落、列表、引用、水平线、代码、简单表格、粗体、斜体和链接。

数值限制

位置限制
桌面应用：每页条目数50 到 5000，默认 200
VS Code：mergecat.pageSize20 到 5000，默认 200
VS Code：mergecat.repositoryScanDepth0 到 5，默认 2
桌面应用：最近的仓库10
命令行：--limit默认 50；使用 --all 则不限制
MCP tags、changesets：limit1 到 500，默认 50
MCP changelog：max_releases0 到 100，默认 5
MCP repository_info：列出的版本标签30
MCP render_pdf：markdown最多 2,000,000 个字符
