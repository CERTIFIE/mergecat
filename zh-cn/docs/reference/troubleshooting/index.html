故障排除与常见问题

解决与 Git、仓库所有权、未签名的安装包、凭据、连接和 Claude Code 插件有关的常见问题，并查找常见问题的解答。

在 GitHub 上编辑

本页借助 AI 从英文翻译。如有疑问，以英文版本为准。

大多数问题都源于 mergecat 的运行环境：Git 安装在哪里、仓库归谁所有、系统提供哪种钥匙串，或者团队如何集成拉取请求。请在下文中查找你看到的消息。

未找到 Git

消息为 Git was not found. Install Git (https://git-scm.com/downloads) or set the path to the git executable in the settings.（未找到 Git。请安装 Git，或在设置中设置 git 可执行文件的路径。）

mergecat 首先使用配置的路径，然后是 PATH 中的 git，最后是常见的安装文件夹：

/opt/homebrew/bin/git、/usr/local/bin/git、/usr/bin/git。

从程序坞或访达启动的应用不会获得你 shell 中的 PATH，因此 mergecat 也会在 Homebrew 文件夹中查找。/usr/bin/git 需要 Xcode Command Line Tools；可以用以下命令安装：

xcode-select --install

%ProgramFiles%\Git\cmd\git.exe、%ProgramFiles(x86)%\Git\cmd\git.exe 和 %LOCALAPPDATA%\Programs\Git\cmd\git.exe。

安装 Git for Windows，或者在 PowerShell 中查找已有的 Git：

Get-Command git

/usr/bin/git、/usr/local/bin/git。

使用包管理器安装 Git，例如 sudo apt install git，或者用 which git 查找已有的 Git。

如果 Git 安装在其他位置，请设置它的路径：

组件位置
桌面应用设置 › Git 可执行文件；对话框会显示找到的版本
VS Codemergecat.gitPath（为空时：先使用 VS Code 的 git.path，再查找常见的文件夹）
命令行、MCP 服务器环境变量 MERGECAT_GIT_PATH

Git 拒绝读取仓库

消息为 Git refuses to read this repository because it is owned by another user（Git 拒绝读取此仓库，因为它归另一个用户所有），后面跟着一条命令。Git 会保护你免受归其他账户所有的仓库的影响（“dubious ownership”，即可疑的所有权），例如位于外部驱动器、网络共享、由其他用户创建的文件夹，或者 WSL 或容器卷上的仓库。

如果你信任该仓库，请使用消息中的文件夹将其标记为安全：

git config --global --add safe.directory "/path/to/repository"

不是 Git 仓库

Not a Git repository: …（不是 Git 仓库）表示该文件夹不在 Git 工作副本内。请打开仓库的根文件夹或其中的任意文件夹。在 VS Code 中，mergecat 还会搜索所打开文件夹的子文件夹（mergecat.repositoryScanDepth，默认两层）。

系统警告应用未签名

mergecat 的安装包尚未进行代码签名或公证。请先验证下载的文件（参见未签名的安装包），然后：

如果 macOS 提示无法打开 mergecat，因为 Apple 无法检查其是否包含恶意软件：

  1. 先从“应用程序”文件夹尝试打开一次 mergecat。
  2. 打开系统设置 › 隐私与安全性。
  3. 滚动到关于 mergecat 的提示，点击仍要打开，然后确认。

如果 macOS 提示该应用已损坏，说明下载的文件被隔离了；验证校验和之后，可以移除隔离属性：

xattr -dr com.apple.quarantine /Applications/mergecat.app

如果 Microsoft Defender SmartScreen 显示 Windows 已保护你的电脑，请点击更多信息，检查文件名，然后点击仍要运行。

Linux 不会检查 AppImage 的签名。运行之前，请为 AppImage 添加可执行权限：

chmod +x mergecat-linux-x86_64.AppImage

Linux 上无法记住凭据

消息为 未找到密钥服务（GNOME Keyring 或 KWallet）：凭据仅保存在内存中，重启应用后需要重新连接。

mergecat 使用系统钥匙串加密凭据，绝不会以明文写入。没有密钥服务时，它只将凭据保存在内存中。请安装并解锁 GNOME Keyring 或 KWallet（大多数桌面环境都自带其中之一），然后重新启动 mergecat 并重新连接。在没有密钥服务的系统上，每次启动后都需要重新连接。

在任何系统上，没有可用的系统钥匙串 的含义都相同；而 凭据仅保存在内存中（已设置 MERGECAT_MEMORY_CREDENTIALS） 表示设置了环境变量 MERGECAT_MEMORY_CREDENTIALS=1。

连接错误

消息原因处理方法
The hosting service rejected the credentials. Sign in again.令牌已过期、已被撤销或缺少访问权限断开连接后重新连接；在仅本地与已连接中查看令牌所需的权限范围
GitLab rejected the token (expired, revoked or for another instance).GitLab 令牌无效，或者属于另一个 GitLab 实例重新登录，或在正确的实例上创建新的访问令牌
The organisation that owns … requires SSO authorisation for this token.启用了 SAML SSO 的 GitHub 组织通过消息中的链接为该组织授权令牌
API rate limit reached; it resets at …对托管服务的请求过多等到显示的时间之后再试。桌面应用会按提交缓存拉取请求数据，因此之后的加载所需的请求更少
Azure DevOps API error: HTTP …Azure DevOps 的其他错误检查组织 URL、你对项目的访问权限以及令牌的权限范围

获取或标签推送失败

mergecat 使用你自己的凭据运行 Git，从不提示输入密码。如果获取或标签推送失败，请在终端中于同一仓库内运行 git fetch 或 git push：如果它要求输入密码，请设置凭据助手（例如 Git Credential Manager）或 SSH 密钥，然后在 mergecat 中重试。

关于合并和压缩的警告

警告含义
此分支没有合并提交：每个提交都显示为直接提交。拉取请求是以变基或快进方式完成的。连接托管服务即可按拉取请求对它们分组
此分支没有通过非快进合并进行集成：拉取请求似乎是以压缩方式合并的…每个拉取请求都是单个提交。连接后可查看原始提交
集成方式混合：… 个拉取请求似乎是以压缩方式合并的…一些拉取请求是压缩合并的；它们显示为单个提交
… 个合并把“main”合并到了别处…在该分支上执行的 git pull 合并，或快进到某个功能分支上：从那里开始的分组可能有误
这是一个浅克隆…较早的历史记录缺失。请运行 git fetch --unshallow

mergecat 在每种情况下显示的内容，请参阅限制与集成方式。

审计报告中的批准情况为“未知”

批准情况存储在托管服务中。请在导出报告之前连接 GitHub、GitLab 或 Azure DevOps；导出时，桌面应用和 VS Code 会提示你进行连接。命令行从不连接，因此它的报告中批准情况始终为未知。参见变更审计报告。

某个环境运行的提交不在你的克隆中

当某个环境运行的提交在你的克隆中尚不存在时（例如部署来自较新的构建），“部署”页面会给出提示。点击获取（或运行 git fetch），然后重新对比。

VS Code 命令的行为出乎意料

“MergeCat for VS Code”（mergecat.mergecat-vscode）是 Marketplace 上一个无关的扩展，它注册了相同的命令和设置名称。请将其移除：

code --uninstall-extension mergecat.mergecat-vscode

Claude Code 插件

再次询问合规问题

这是预期行为。回答属于 Claude Code 会话：每个会话都会启动一个新的 mergecat MCP 服务器进程，它会在发送第一批仓库数据之前再次询问。每个回答都是一条新的 AI 使用记录。

Claude 提示需要合规确认

在问题得到回答且结果允许使用之前，仓库工具处于锁定状态。请在 Claude 提问时回答该问题。如果你在本会话中早些时候对两个问题都回答了“否”，请再次请求 mergecat 数据，Claude 会再次提出该问题。

缺少 mergecat 工具

  1. 在 Claude Code 中运行 /mcp，检查 mergecat 服务器是否已连接。
  2. 检查是否已安装 Node.js 20 或更高版本，并且可作为 node 调用：node --version。
  3. 检查插件是否已安装：claude plugin list。
  4. 安装或更新后，运行 /reload-plugins 或开始一个新会话。

变更日志中没有拉取请求标题

请在设置了仓库托管服务令牌的情况下启动 Claude Code：GitHub 使用 GITHUB_TOKEN（或 GH_TOKEN），GitLab 使用 GITLAB_TOKEN（或 GL_TOKEN），Azure DevOps 使用 AZURE_DEVOPS_EXT_PAT 或 AZURE_DEVOPS_TOKEN。只能识别 github.com、gitlab.com 和 Azure DevOps 上的仓库。参见拉取请求数据。

PDF 中显示问号

PDF 使用标准 PDF 字体，只涵盖 Latin-1。对于使用其他文字系统书写的语言，请要求输出 Markdown。参见 PDF 输出。

常见问题

mergecat 会更改我的仓库吗？

只有在你执行获取、创建或推送标签，或者创建拉取请求时才会。它从不提交、检出、合并或改写任何内容。参见安全与隐私。

mergecat 会把我的代码发送到别处吗？

桌面应用和 VS Code 只与你连接的托管服务通信。Claude Code 插件会在合规问题之后，将历史元数据（提交消息、姓名、电子邮件地址、日期、分支和标签名称、提交 SHA，以及使用令牌时的拉取请求数据）发送给 Claude；它的工具不会发送文件内容或差异。Claude Code 本身可以在其自身的权限范围内读取你项目中的文件。

有 mergecat 账户、服务器或遥测吗？

没有。mergecat 没有账户、没有服务器、没有遥测，也不会检查更新。

mergecat 可以离线使用吗？

可以，凡是不需要托管服务的功能都能离线使用：变更集、差异、筛选、导出、分支、标签，以及不含批准情况的审计报告。

插件为什么要询问是否使用 Team 或 Enterprise 账户？

许多组织只允许在受商业协议约束的 AI 账户上使用公司数据。该问题和记录为每个会话记录下这一决定。参见欧盟《人工智能法案》与 NIS2。

我的设置和数据在哪里？

参见数据位置。
