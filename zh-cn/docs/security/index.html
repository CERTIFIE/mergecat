合规与审计

安全与隐私

mergecat 会更改仓库中的哪些内容，哪些数据会离开你的计算机以及发送到哪里，凭据如何存储，以及 mergecat 在本地保存了什么。

在 GitHub 上编辑

本页借助 AI 从英文翻译。如有疑问，以英文版本为准。

mergecat 是一个本地工具：它使用你自己的 Git 读取仓库，只与你连接的托管服务通信，并且没有自己的服务器。本页列出它可能更改的内容、哪些数据会离开你的计算机、它如何存储凭据，以及它在磁盘上保存了什么。

概览

主题mergecat 的处理方式
仓库默认只读；仅在明确的命令下写入
网络仅限你连接的托管服务（GitHub、GitLab、Azure DevOps）及其登录页面；仅通过 Claude Code 插件、在回答合规问题之后才与 Claude 通信
凭据使用操作系统钥匙串加密；没有可用的钥匙串时仅保存在内存中
遥测无：没有使用统计、没有崩溃报告、没有更新检查、没有 mergecat 服务器
本地数据设置、加密的凭据和拉取请求缓存，保存在应用数据文件夹中；绝不存放在仓库中

默认只读

mergecat 使用 git log、git blame 及类似命令读取历史记录。它从不提交、检出、合并、变基或改写任何内容，也从不触及你的工作树或本地分支。只有以下操作会更改内容，而且只在你亲自启动时才会执行：

操作更改的内容位置
获取运行 git fetch --all --tags --prune：更新远程跟踪分支和标签，并移除已在远程仓库上删除的分支和标签。不会触及本地分支和文件。桌面应用（“分支”页面）、VS Code（Branches 页面，Fetch All Remotes）
创建标签在你选择的提交上创建本地标签；输入消息时创建附注标签桌面应用、VS Code（Tags 页面，Create Tag…、Create Tag Here…）
推送标签将该标签推送到远程仓库桌面应用、VS Code（Tags 页面）
创建拉取请求在托管服务上创建拉取请求（GitLab 中为合并请求）桌面应用、VS Code（Pull requests 页面，Create Pull Request…）

导出文件和审计报告只会写入你保存的位置。Claude Code 插件的 MCP 服务器从不更改仓库：它只会写入 AI 使用记录，以及在你请求时在项目之外写入 PDF 文件。只有在你明确要求时，Claude 才会更新 CHANGELOG.md。

mergecat 运行 Git 的方式：

  • 使用你自己的 git 可执行文件，直接启动，绝不通过 shell；
  • 设置 GIT_TERMINAL_PROMPT=0：获取和标签推送使用你的凭据助手或 SSH 密钥，绝不会提示输入密码；
  • 设置 GIT_OPTIONAL_LOCKS=0，使读取操作不会获取 Git 的可选锁。

离开你计算机的数据

目的地时机内容
你的 Git 远程仓库获取和标签推送时Git 交换的任何内容，使用你的 Git 凭据
托管服务 API：GitHub、GitLab、Azure DevOps仅当该服务已连接时对仓库的拉取请求、批准、关联的议题、流水线和部署的请求；你创建的拉取请求
登录页面：github.com、login.microsoftonline.com、你的 GitLab 实例通过浏览器登录时设备流登录；你所在组织的 SSO 和 MFA 在该页面上生效
Claude（Anthropic），或你在其中运行 mergecat MCP 服务器的 AI 助手（GitHub Copilot、OpenAI Codex、GitLab Duo）仅通过 mergecat MCP 服务器，并且在合规问题允许之后历史元数据：提交消息、作者和提交者的姓名及电子邮件地址、日期、分支和标签名称、提交 SHA；使用托管服务的令牌时，还包括拉取请求的标题、编号、标记和关联的议题

除此之外没有其他数据。mergecat 没有遥测：它不收集使用统计，也不发送崩溃报告。它不检查更新，也没有 mergecat 服务器或账户。桌面应用内置了所需字体，不从 CDN 加载任何内容。

mergecat MCP 工具向 Claude 提供的是历史元数据，而不是你的文件内容或差异。Claude Code 本身可以在其自身的权限范围内读取你项目中的文件；例如，变更日志技能会读取 CHANGELOG.md。

AI 使用会被记录

在发送 Claude Code 会话的第一份仓库数据之前，mergecat 会询问你是否使用 Claude Team 或 Enterprise 账户，并记录回答。参见欧盟《人工智能法案》与 NIS2。

凭据

桌面应用

令牌通过操作系统的钥匙串（Electron safeStorage）加密，并存储在应用数据文件夹的 credentials.bin 中。

加密密钥保存在 macOS 钥匙串（Keychain）中。

数据使用 Windows DPAPI 针对你的用户账户进行加密。

加密密钥由密钥服务（secret service）保管：GNOME Keyring（libsecret）或 KWallet。如果没有密钥服务，mergecat 只会将凭据保存在内存中，并显示一条警告：重启应用后你需要重新连接。参见故障排除。

  • 当没有可用的钥匙串时，凭据仅保存在内存中，绝不会以明文写入。
  • GitHub CLI 登录不存储任何令牌：mergecat 会在需要时运行 gh auth token。
  • 浏览器登录流程获得的登录令牌会在过期之前刷新。
  • “连接”对话框中的断开连接会删除该服务已存储的凭据。

VS Code 扩展

  • GitHub 和 Azure DevOps (Sign in with Microsoft) 使用 VS Code 已在管理的账户。令牌保留在 VS Code 中；mergecat 会在需要时向 VS Code 请求令牌。
  • 个人访问令牌和 GitLab 登录令牌存储在 VS Code 的 SecretStorage 中（由操作系统钥匙串支持），每个服务和主机各一个。它们绝不会写入设置或日志。

Claude Code 插件和命令行

  • MCP 服务器从其环境中读取 GITHUB_TOKEN（或 GH_TOKEN），用于获取 github.com 仓库的拉取请求数据。它不会存储该令牌。
  • 命令行不使用任何托管服务，除了你的 Git 设置之外也不使用任何凭据。

最小权限

只为令牌授予 mergecat 所需的范围。读取只需要读取范围；只有创建拉取请求才需要写入权限（例如，GitLab 的 read_api 足以读取，创建合并请求则需要 api）。各服务所需的范围列在连接中。

本地数据和缓存

内容位置说明
设置（桌面应用）应用数据文件夹中的 settings.jsonGit 路径、登录所用的客户端 ID、Microsoft 租户、每页大小、最近打开的 10 个仓库
凭据（桌面应用）应用数据文件夹中的 credentials.bin加密的令牌
拉取请求缓存（桌面应用）应用数据文件夹中的 pull-request-cache/，每个仓库一个文件按提交 SHA 保存的拉取请求数据。已合并的拉取请求会一直保留；“无拉取请求”的结果会在 6 小时后重新检查，打开的拉取请求则在 1 小时后重新检查
拉取请求缓存（VS Code）VS Code 中该扩展的全局存储文件夹相同的数据，按提交 SHA 保存
AI 使用记录mergecat 合规文件夹参见 AI 使用记录
来自 Claude Code 的 PDFClaude 的草稿目录（scratchpad），或系统临时文件夹中的 mergecat 文件夹仅当你请求 PDF 时

mergecat 从不将缓存或设置写入你的仓库。

桌面应用的应用数据文件夹：

~/Library/Application Support/mergecat/
%APPDATA%\mergecat\
~/.config/mergecat/

如果设置了 XDG_CONFIG_HOME，则为 $XDG_CONFIG_HOME/mergecat/。

要删除所有内容，请断开各服务的连接，退出应用，然后删除此文件夹。在 macOS 和 Windows 上，合规记录位于其 compliance 子文件夹中：如果审计需要这些记录，请予以保留。

桌面应用加固

  • 窗口内容在沙盒化的渲染进程中运行，启用了上下文隔离且无法访问 Node.js；它通过一个范围很窄的接口与主进程通信。
  • 窗口绝不会离开应用、导航到其他页面。链接会在你的默认浏览器中打开，并且只会打开 https:// 链接。
  • 应用同时只运行一个实例。

未签名的构建

代码签名和公证尚未配置，因此首次打开 mergecat 时，macOS 和 Windows 会发出警告（如何打开）。在确认之前：

  • 只从项目的发布页面或下载部分下载 mergecat；
  • 将文件的 SHA-256 校验和与发布中公布的校验和（SHA256SUMS.txt，也列在发布说明中）进行比较：
shasum -a 256 ~/Downloads/mergecat-mac-arm64.dmg
Get-FileHash "$HOME\Downloads\mergecat-windows-x64-setup.exe" -Algorithm SHA256
sha256sum ~/Downloads/mergecat-linux-x86_64.AppImage
  • 如果你的政策不允许使用未签名的软件，请从源代码构建 mergecat（参见安装），或等待已签名的发布。
