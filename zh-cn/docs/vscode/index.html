集成

VS Code 扩展

为 VS Code 安装 mergecat 扩展，并使用它的视图、仓库页面、命令和设置。

在 GitHub 上编辑

本页借助 AI 从英文翻译。如有疑问，以英文版本为准。

mergecat 扩展把变更集视图带入 VS Code：按集成分组的分支历史记录、以编辑器标签页打开的仓库页面（分支、标签、拉取请求、流水线、部署）、变更集追溯（changeset blame）、指标以及变更审计报告。它使用 VS Code 已经登录的 GitHub 和 Microsoft 账户。

系统要求：VS Code 1.90 或更高版本，以及 Git。Branches 页面的冲突检查需要 Git 2.38 或更高版本。

安装

尚未上架 Marketplace

该扩展尚未发布到 Visual Studio Marketplace。请从某个发布的 .vsix 文件安装，或者从源代码构建。

从下载区下载 mergecat-vscode.vsix，然后通过以下两种方式之一安装。

命令行：

code --install-extension mergecat-vscode.vsix

VS Code： 打开扩展视图，点击视图顶部的 … 菜单，选择 Install from VSIX…（从 VSIX 安装），然后选择该文件。

在 mergecat 仓库的克隆根目录中（Node.js 20 或更高版本）运行：

npm install
npm run vscode:install

该脚本会构建并打包扩展，然后将其安装到 VS Code 中；即使 code 命令不在 PATH 中，它也能找到。修改代码后请再次运行。要移除扩展：

npm run vscode:install -- --uninstall

然后运行 Developer: Reload Window，打开一个包含 Git 仓库的文件夹，并点击活动栏中的 mergecat 图标。

名称相似的另一个扩展

Marketplace 上的“MergeCat for VS Code”（mergecat.mergecat-vscode）是一个无关的扩展，它注册了相同的命令和设置名称。请不要同时安装两者。如果已经安装了它，请将其移除：

code --uninstall-extension mergecat.mergecat-vscode

视图

活动栏中的 mergecat 图标会打开三个视图。

使用哪个仓库？ 如果打开的文件夹位于某个 Git 仓库内，则显示该仓库。否则，mergecat 会搜索它的子文件夹（默认两层，mergecat.repositoryScanDepth）。只有一个仓库时直接打开它；有多个仓库时，显示上次使用的仓库或编辑器中文件所在的仓库，或者请你选择（也可以通过标题栏中的仓库按钮选择）。

Changesets 视图

所选分支的分组历史记录，有两种布局。可以通过页眉中的 List | Graph 切换，或者使用 Show Commit Graph / Show Changesets List。

  • List：直接提交显示为单行，集成（合并，以及连接后的变基合并拉取请求）显示为可展开的分组。每行的第二行显示短 SHA、作者、日期、风险，以及已包含该变更的环境。点击某个提交可打开它的更改；使用该行的差异按钮或上下文菜单可打开某个分组的组合更改。
  • Graph：每个提交及其泳道；第二行的徽标表示是哪个变更集把该提交带入了分支。

页眉显示仓库和分支（点击可切换）、搜索框、以可移除徽标形式显示的当前筛选条件、警告、条目数量以及连接状态。右键点击某一行可执行它的操作：打开更改、查看它从哪里进入、打开拉取请求、复制 SHA。键盘操作：↑ ↓ 移动，← → 折叠和展开，Enter 打开。

Environments 视图

显示什么部署在哪里，以及分支中的哪些集成尚未部署到那里。点击某个条目即可定位到它；行内操作会将 Changesets 视图切换为“尚未进入此环境的内容”。

环境可以是指向已部署代码的分支（例如 origin/production），也可以是一个标签模式，其最新的标签即为已部署的版本（例如 prod-*）。未进行配置时，会检测名为 production、staging、test 或 develop 的分支以及发布标签；有连接时，还会加入托管服务最近的成功部署。可以用 mergecat.environments.definitions 配置环境：

"mergecat.environments.definitions": [
  { "name": "Production", "tagPattern": "prod-*" },
  { "name": "Staging", "ref": "origin/staging" }
]

Connections 视图

托管连接器（GitHub、GitLab、Azure DevOps；Bitbucket 即将推出）、每个连接器的登录方式，以及连接会补充什么。仓库的远程仓库决定使用哪个连接器。

仓库页面

有五个页面以编辑器标签页的形式打开：可以通过 Changesets 页眉下方的按钮（Branches · Tags · PRs · Pipelines · Deploys）、视图的 … 菜单，或者 mergecat: Open … 命令打开。

页面显示内容连接
Branches每个本地分支，以及没有本地副本的远程分支：传入和传出的提交、not on origin、upstream deleted、相对于基准分支的领先/落后、merged、与基准分支的冲突（列出文件）、距今时间。Fetch 会运行 git fetch --all --prune --tags。本地
Tags名称、提交、日期、标签创建者、消息、附注或轻量、版本、在 origin 上，或带有 Push 按钮的 local only。New tag 会在你输入时检查名称，并可以推送标签。本地
Pull Requests打开、已关闭或全部，显示状态、审阅者和投票、检查；详细信息包含提交和关联的议题。New pull request 会根据提交预填标题和描述。已连接
PipelinesGitHub Actions、GitLab CI/CD 和 Azure Pipelines：Activity（阶段、作业、步骤、依赖关系）、Text（YAML）和 Runs（每个作业的状态和持续时间）。已连接
Deployments每个环境的线上部署，以及之前带有标签的部署；带有发布说明和审计报告的 Compare environments；每次部署带来了什么。已连接

没有连接时，Deployments 页面会显示在本地找到的环境（来自设置、分支名称和标签名称），并以同样的方式对比它们。

洞察

  • Changeset blame（变更集追溯）：mergecat: Toggle Changeset Blame（也位于编辑器标题栏中）会为光标所在行标注把它带入所分析分支的集成：拉取请求或被合并的分支、标题、日期以及它已到达的环境。悬停提示还会显示提交、集成者、批准情况和关联的议题（需连接）、首个发布标签以及风险。
  • Changesets That Shaped This File 列出编写了当前文件的集成，按所占份额从大到小排列。
  • Risk per integration（每个集成的风险）：根据以下因素计算的分数：规模、涉及文件多、敏感区域、修改了代码却没有修改测试、直接提交和没有拉取请求的本地合并、未经批准的合并（需连接）以及还原（revert）。使用 Filter… › Risk… 进行筛选。各项因素列在变更审计报告中。
  • Metrics（指标）：mergecat: Show Metrics 显示进入的变更、经拉取请求的比例、前置时间、变更规模、还原、作者、每周或每月的活动、风险分布以及主要贡献者。连接 GitHub 后还会显示合并所需时间。

审计报告

运行 mergecat: Export Audit Report…（通过命令面板或 Changesets 视图的 … 菜单），然后选择范围：当前视图、Between two releases…、Between two environments… 或某个环境的 Not yet in。选择 HTML、Markdown、CSV 或 JSON 格式以及保存位置。Deployments 页面为 Compare environments 中的变更提供同样的报告。

批准情况来自托管服务：没有连接时，该命令会警告批准情况将报告为“unknown”（未知），并提供连接选项。详细信息：变更审计报告。

各服务的登录方式

可以从 Connections 视图、Changesets 页眉中的 Local only · Connect 胶囊按钮，或者 mergecat: Connect… 进行连接。

服务登录方式说明
GitHub（github.com）VS Code 的 GitHub 账户包括组织 SSO；权限范围 repo；令牌保留在 VS Code 中
Azure DevOps（dev.azure.com）使用 VS Code 的 Microsoft 账户进行 Sign in with Microsoft当 Azure DevOps 组织已连接到 Microsoft Entra ID（工作或学校账户）时可用
Azure DevOps（备选方式，也适用于 Azure DevOps Server）个人访问令牌权限范围 Code (Read & write)、Build (Read)、Environment (Read & manage)、Work Items (Read)
GitLab（gitlab.com）个人访问令牌权限范围 api（只读取时 read_api 就足够；创建合并请求需要 api）
GitLab（可选）在浏览器中 Sign in with GitLab（GitLab 17.2 或更高版本）需要在 mergecat.gitlab.clientId 中填入非机密 OAuth 应用程序的应用程序 ID

个人访问令牌和 GitLab 登录令牌保存在 VS Code 的 SecretStorage 中，每个服务和主机各一个，绝不会出现在设置或日志中。可在 Connections 视图中断开连接。另请参阅安全与隐私。

所有命令都位于命令面板中的 mergecat: 下。

命令作用

Show/Hide Forward-Integration Merges切换分组内“main 合并到功能分支”的合并
Show Commit Graph / Show Changesets List在图形和列表之间切换
Compare Two Refs…两个发布、标签或提交之间进入了什么，以同样的方式分组
Export…当前视图的 Markdown、CSV 或 HTML 变更日志
Where Did This Commit Enter?把某个提交带入分支的集成，以及包含该提交的首个标签
Open Commit Changes / Open Combined Changes在 VS Code 的差异编辑器中查看某个提交或整个分组的差异
Open Pull Request / Copy Commit SHA行操作
Connect… / Disconnect…登录 GitHub、GitLab 或 Azure DevOps，或忘记凭据（另有 Connect GitHub 和 Disconnect GitHub）
Open Branches / Open Tags / Open Pull Requests / Open Pipelines / Open Deployments打开某个仓库页面
Fetch All Remotes运行 git fetch --all --prune --tags，然后刷新
Create Tag… / Create Tag Here…在所分析分支的最新提交或所选行上打开“New tag”表单
Create Pull Request…打开“New pull request”表单
Toggle Changeset Blame为当前行标注把它带入的集成
Changesets That Shaped This File编写了当前文件的集成
Show Metrics某段时间的流程指标
Export Audit Report…当前视图、某个发布范围、两个环境或下一次部署的审计报告
Configure Environments… / Refresh Environments编辑或重新加载环境
Show What Is Not Yet Deployed Here将 Changesets 视图切换为某个环境尚未运行的内容
Refresh / Load More重新读取历史记录；加载下一页条目

设置

设置默认值描述
mergecat.gitPath空Git 可执行文件。为空时：先使用内置 Git 扩展的 git.path，再查找常见的安装位置
mergecat.pageSize200每次加载的顶层条目数（20 到 5000）
mergecat.hideForwardIntegrationMergestrue在分组中隐藏主分支合并到功能分支的合并
mergecat.defaultBranch空打开仓库时分析的分支，例如 origin/main。为空时：先使用远程默认分支，然后是 main/master，最后是当前分支
mergecat.repositoryScanDepth2当打开的文件夹不是仓库时，搜索仓库的子文件夹层数（0 到 5；0 = 仅打开的文件夹）
mergecat.environments.definitions[]环境：{ "name", "ref" } 或 { "name", "tagPattern" }
mergecat.environments.autoDetecttrue未配置环境时，根据分支名称和发布标签推测环境
mergecat.risk.sensitiveAreas[]替换风险评分的默认敏感区域；每一项为 { "id", "label", "points", "patterns" }。为空时：使用默认值
mergecat.risk.testPatterns[]用于“未修改测试”因素的测试文件 glob 模式。为空时：使用默认值
mergecat.gitlab.clientId空用于 Sign in with GitLab 的 GitLab OAuth 应用程序的应用程序 ID。为空时：使用个人访问令牌

自定义敏感区域的示例：

"mergecat.risk.sensitiveAreas": [
  { "id": "billing", "label": "Billing", "points": 3, "patterns": ["src/billing/**"] }
]

与桌面应用的区别

两个应用使用同一引擎读取相同的历史记录，并且拥有相同的仓库页面。区别如下：

VS Code 扩展桌面应用
Changesets 视图侧边栏视图，在 VS Code 的差异编辑器中显示差异带详细信息面板的完整窗口
变更集追溯（changeset blame）、Changesets That Shaped This File是否
指标面板是否
每行显示风险和环境是否
环境定义mergecat.environments.definitions来自托管服务的部署
审计报告中的“环境”列已填充空
GitHub 登录VS Code 的 GitHub 账户使用 GitHub 登录（OAuth App）、GitHub CLI 或令牌
Azure DevOps 登录VS Code 的 Microsoft 账户或令牌使用 Microsoft 登录（Entra ID 应用）或令牌
凭据存储VS Code 账户和 SecretStorage操作系统钥匙串

关于桌面应用，请参阅安装和历史记录。两者的已知限制列在限制与集成方式中。
